# 快速开始

完整运行需要同时启动 Backend、Canvas Agent 与 `web/` 前端三个进程。

## 本地启动

```bash
git clone git@github.com:helishou/infinite-canvas-mcp.git
cd infinite-canvas-mcp
npm install
npm run dev:local
```

启动后访问：

```text
http://localhost:3000
```

`npm run dev:local`（Windows 下为 `scripts\dev-local.bat`）会先清理 17370、17371、3001 三个端口上的旧服务，再拉起 backend(17370)、agent(17371) 与 web(3001)。`npm run dev:services` 不做清理，直接三进程并发启动。`dev` 不是 watch，也不是探活命令。

如果要在自己的机器上完整跑短片生产栈，用上面的本地三进程模式；Docker 镜像只包含前端。

## Docker 启动

如果你只需要界面预览，可以基于当前源码构建前端镜像：

```bash
docker build -t infinite-canvas .
docker run --rm -p 3000:3000 infinite-canvas
```

仓库 Dockerfile 只构建静态前端并由 nginx 提供，AI 请求由浏览器前台直连你自己的接口。Backend、Canvas Agent、MCP 与 H3 短片生产栈位于源码层面，Docker 前端镜像不包含它们。详见[Docker 部署](/zh-CN/docs/overview/docker)。

## Vercel 部署

根目录 `vercel.json` 只构建 `web/`。该方式适合预览前端；画布、素材和结构化配置的完整持久化仍需连接可访问的 Backend。

## 首次使用建议

- 先打开右上角配置弹窗，填入自己的 `Base URL`、`API Key` 和模型名。
- 如果需要提示词仓库内容，打开 `/prompts` 会由浏览器前端直连拉取并使用内存缓存。
- 如果需要跨设备同步画布、素材和生成记录，可在配置弹窗中填写 WebDAV。

## 说明

- 画布项目、“我的素材”、生成记录和结构化配置统一写入本地 Backend SQLite；媒体文件写入 Backend 媒体目录，WebDAV 同步需要用户自行配置。
- AI API Key 随渠道配置保存在 Backend SQLite，由前端读取后直接请求对应的 OpenAI 兼容接口。
