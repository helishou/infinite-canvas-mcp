# 制作数据流

画布和制作台看起来是两个地方，实际只维护一份制作源稿。理清这条链路只需要记住三件事：

- 一份源稿：场次、镜头、Clip、主体和连续性只在一个地方编辑；
- 一个画布的两个挂载点：画布页和制作台里的画布是同一个项目；
- 四层生效：保存、编译、发布、生成是四件不同的事，其中编译又分「产出提示词」和「应用到画布」两步。

## 三层数据

| 层 | 内容 | 存在哪里 | 谁写 |
| --- | --- | --- | --- |
| 制作源稿 | 场次、剧本正文、镜头、Clip 分组、主体、连续性、素材定义 | Backend SQLite 的 `episode_productions`（分集）或 `canvas_productions`（独立与共享资产画布） | 制作台编辑与制作类 MCP 工具 |
| 画布 | 剧本文字节点、角色/场景/道具节点、每场一个 H3 节点、图片/视频/音频节点 | Backend SQLite 的画布项目，按 `drama_episodes.canvas_id` 与分集固定绑定 | 画布操作（网页、MCP、Agent） |
| 编译产物 | 每个制作目标的 Prompt、参考清单、审核与回执 | 源稿的 `director.artifacts` 与编译作业记录 | 编译器产出，应用时写入画布 Clip |

画布不是源稿的副本，而是源稿的投影加媒体容器。场次、镜头、Clip 归属、主体引用由源稿决定；节点位置、画布分组、额外图片由画布自己决定。

## 画布上有什么

- 剧本节点：每场一个文本节点，正文与场次投影同步；在画布上改正文会写回同一份源稿。
- 素材节点：角色、场景、道具各自一个稳定节点，名称和说明双向保存。
- H3 视频节点：每个正式场次一个，未归属场次的 Clip 归到该制作对象默认的 H3 节点；Clip 列表保存在节点的 `metadata.segments`。正式 Clip 带 `productionClipProjection`，指向源稿中的 Clip（`targetId`）与编译基线（`sourceHash`、`artifactId`、`promptHash`）。
- 媒体节点：图片、视频、音频的真实来源。编译、参考和生成都从这里已归档的媒体读取。

同一个画布在画布页是全屏页面，在制作台里是可收起的浮层，两者打开的是同一个画布项目。

## 四层生效

| 层级 | 做什么 | 不会做什么 |
| --- | --- | --- |
| 保存 | 写入源稿，并把场次、镜头、Clip 分组、主体引用投影到画布节点 | 不生成 Prompt，不提交媒体任务 |
| 编译 | 校验目标输入，编译出每个目标的 Prompt 与参考清单 | 不改媒体文件，不改镜头设计 |
| 应用 | 把编译结果写进 H3 节点的 Clip，并同步参考 | 不覆盖人工编辑；冲突时保留人工稿 |
| 发布 | 冻结一个可追溯的版本快照 | 不是生成的默认前置条件 |
| 生成 | 按当前已保存稿提交媒体任务 | 不等待发布稿 |

界面上的一次「校验并编译」实际包含编译与应用两步。应用失败或目标未就绪时，编译本身可能已经成功，界面会停在「编译成功、画布未就绪」，此时应先处理该目标再重新编译，而不是当作编译失败。

保存本身不直接改 Prompt：镜头、分镜轨和续接边界保存后，同一次提交会追加一个 Clip 刷新，Backend 只对输入真正变化的 Clip 跑「连续性检查 → 编译 → 应用」，Prompt 在编译成功后由应用步骤写入。进度显示在该 Clip 的编译状态上，不需要再次手动编译。拆分、合并、重新分组等结构性调整仍要点「校验并编译」；还没投影到画布的 Clip 不参与自动刷新。

## 哪些编辑会写回源稿

- 剧本正文、素材名称与说明：双向同步，画布和制作台改的是同一份源稿。
- 场次归属：由制作台维护，画布上的剧本节点只展示所属场次。
- Clip 的分镜轨与续接边界：在画布 H3 面板里的修改会写回源稿，等同制作台操作。
- 人工改写的 Clip Prompt：作为人工稿保留，不冒充已反向同步；再次编译时以旧基线做三方合并，冲突保留人工编辑。
- 参考绑定、引用顺序：在画布事务内保存，不直接改写导演参考卡。

时长、Clip 归属、参考顺序等由源稿派生的字段不能单独在画布上编辑，需要回到镜头或 Clip 的源稿修改。

## 一次典型链路

1. 在制作台改一个镜头，保存。
2. Backend 写入源稿，并把该镜头、Clip 的标题与分组投影到画布节点。
3. 保存会为受影响的 Clip 追加一次后台校验与编译；结构性调整则在分镜台点「校验并编译」。
4. 编译作业产出 Prompt，应用后写入对应 H3 Clip；参考同步失败时停在上文所述的未就绪状态。
5. 在画布上确认 Clip 提示词与参考，再单独发起生成。

## 常见误判

- 保存后画布 Prompt 没变是正常的：Prompt 只在编译并应用后更新。
- 画布不是第二份数据：画布页与制作台浮层看到的是同一个项目，切换不会产生两套内容。
- 编译成功不等于生成就绪：编译只证明 Prompt 与参考成立，媒体仍需单独生成。
- 画布上手动改的 Prompt 不会被下一次编译悄悄覆盖，也不会被当成源稿已更新。
