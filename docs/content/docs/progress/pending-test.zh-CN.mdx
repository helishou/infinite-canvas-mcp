# 待测试

## H3 参考兼容与迁移恢复

- Web 开发服务运行时执行 `node scripts/test-h3-reference-compatibility.mjs`，在独立内存测试页验证真实参考弹窗和参考卡。非默认地址可设置 `CANVAS_TEST_WEB`；不请求模型或写入项目。
- 打开角色图位于场景图之前或之间的旧 Clip，参考卡和已保存的 Picture 标签仍应对应原图片；分镜优先提交时也保持对应关系，生成不得改写已保存提示词。
- 在单件服装仍选中的情况下关闭角色服装总开关，实际提交中不应出现服装图，已开启的声线仍可使用；重新打开服装开关应恢复原选择。
- 在隔离的旧数据库中模拟备份完成后 H3 迁移失败，排除故障后重试应完成启动并保留原项目；旧版固定名称备份及失败尝试留下的备份均不得被覆盖。

## 画布历史维护与性能

- 执行 `npm run prune-canvas-batches --workspace backend -- 30` 只预览；显式追加 `--apply` 才创建并校验唯一备份，在同一事务内推进检查点并清理连续的过期前缀。历史缺口或备份失败时保持原数据。维护保持手动触发，默认保留期仍为 30 天。
- 清理后，保留期内请求仍能恢复原回执；更早的已提交请求不得重复执行。浏览器读取最新画布、持久确认原命令，并保留后续编辑或冲突草稿；读取失败保留待确认命令。已有数据库迁移独立回执表前生成并校验备份。
- 在大画布检查内容编辑、参考顺序、分组、节点移动、快速平移和 5% 缩放。纯内容变化应复用空间结构，同时显示最新内容；视口阈值不变。
- PR 检查新增 Web 类型与构建、Backend 构建、H3 类型与测试，以及隔离浏览器协作场景。构建 `canvas-agent` 和 Backend 并安装锁定的 Playwright Chromium 后，可运行 `node scripts/run-canvas-browser-tests.mjs collaboration` 或 `node scripts/run-canvas-browser-tests.mjs performance label`。测试隔离 Backend 数据、媒体、Agent 配置、端口与 Vite 缓存，测量及失败证据保存到 `artifacts/browser-tests`，不提交收费生成。

## Agent 侧边栏自动连接

- 打开 Agent 侧边栏时应自动读取当前后台的连接信息并建立连接，无需再点「连接」。关闭再打开已连接的侧栏，应保留原连接；手动断开后本次打开期间保持断开，重新打开时再自动连接。
- 首次连接失败后不要持续重复提交连接；服务恢复后重新打开侧栏应能再次连接。带连接信息的启动链接继续自动连接；自动连接与手动连接同时触发时不应重复创建连接，较晚返回的连接信息不应重置已经建立的连接。

## 单集剧本、镜头、分镜与 H3 Clip

- 进入分集「制作」页，编辑场次动作/对白与镜头并调整顺序；预览影响后先发布剧本、再发布镜头表。仅保存草稿不提交生成。另一个窗口使用过期修订提交时应返回当前版本，保留双方未提交内容。回执缺失时保留原 operationId、修订和 payload，刷新后取回原回执，不执行第二次编辑或发布。
- 选择 `fullPlot`、`script.md` 或 `storyboard.md` 导入待审核草稿，原文保持不变。发布后以 Backend 结构化版本为正式来源，可把已发布剧本/镜头版本导出为 Markdown；历史版本可恢复到草稿而不删除已发布历史。
- 用稳定镜头 ID 绑定分镜关键帧；只有说明动作承接时才合并相邻镜头。同步 H3 草稿后，定向更新应保留已有 Clip 的 segmentId 和历史结果。
- 自动模式在发布镜头表后局部重做，沿用并冻结画布节点或既有配置中的模型，不设任务额度。用临时执行器核对模型继承与冻结、旧额度不再限制提交、缺参考、任务失败暂停，以及 taskId、storageKey、画布节点与 H3 Clip 回写。尚未做付费实测。

## 画布生图工作流宽高比

- 把画布生图节点设为 16:9 并选择 `qwen_image_2_1` 工作流，核对最终提交给 ComfyUI 的执行图确实在画幅输入上收到 16:9。已保存的工作流字段若仍是 1:1，应在运行 ComfyUI 前阻断并说明冲突。归档后从文件读取真实像素：方图保留在任务历史中，但不得成为活动关键帧；比例正确的结果记录实际尺寸。自动检查无需付费生图。

## 画布导入 SVG 图片

- 通过文件选择、拖入画布和素材侧栏导入 `.svg`：应显示为图片节点或图片素材，缩放时保持矢量清晰度，刷新后仍能读取原始 SVG；替换图片节点时也可选择 SVG。
- 用 `canvas_import_local_images` 导入带 `viewBox` 的本地 SVG：应保留原文件、MIME 与宽高；把非 SVG 内容改名为 `.svg` 应被拒绝。直接打开媒体 URL 时不应执行 SVG 内脚本。
- SVG 保留为可编辑的画布图片；作为模型参考时，Backend 应提交确定性 PNG 派生图，并在任务中记录原件与实际提交的 storageKey，不再需要手工浏览器转换。

## H3 计划、引用与任务等待

- 实际注册的 `h3_apply_video_plan` schema 应要求每段 `id` 与每镜 `start/end`。普通 `config` 节点应在画布 revision 改变前被拒绝，并提示正确的 H3 节点类型。
- 角色节点缺少 `characterAssetId` 或完整服装媒体目录时，应在绑定角色组前失败。`h3_write_storyboard_prompt(dryRun: true)` 只返回预览不写入；错误的分镜绑定 ID、职责、启用状态、媒体类型和句柄应指向具体镜头与字段。
- `canvas_wait_tasks` 超时应返回原任务 ID 和下一次等待动作；继续等待不得创建第二个生成任务。

## MCP 契约与 H3 原子准备（1.5.11）

- 核对实际工具目录保留字段说明、整数/范围约束、数组限制、未知字段策略及声明的跨字段条件；更新插件时，已有工具的 schema 和 handler 一并更新，不仅重新启用旧注册。
- `h3_prepare_clip` 将正文/配置、现有角色服装选择及参考绑定组成同一个最终候选；`dryRun: true` 只预检不写入，版本冲突或最终引用非法时整笔拒绝。运行归属、结果和任务历史受保护；此工具不生成视频。
- 引用错误返回 `REFERENCE_INVALID`、具体 issue code 和 `retryPolicy: after_input_change`。H3 诊断读取明确声明 `readOnlyHint: true`，写入或混合预览/写入工具仍按可写处理；不能原样重提被拒请求。
- `h3_get_clip` 的 `include: ["result"]` 核对精确项目/节点/Clip/任务/storageKey；可用 taskId 与 storageKey 选择历史结果，二者不能在不包含 result 的总览查询中被忽略。其他 Clip 的任务或媒体直接拒绝；共享父任务须有本段完成/复用事件，不能凭父任务平铺媒体数组或目录最新文件验收。缺少证据时返回不可核验或错误，不猜结果。
- 核对同一生成幂等键只恢复原任务，不再次排队；将原键用于另一目标或请求必须拒绝，历史回执不覆盖新稿或新任务。隔离任务存储可验证此契约，不需要提交真实生成。
- 源码/构建、独立真实 HTTP 检查和当前 Backend/Hermes 生效分别验收。授权安全处理服务后加载 Backend/共享包并刷新 MCP 目录；配套 Hermes 客户端 Python 修复也须由运行进程实际加载，仅刷新画布工具声明不能代替。不得为部署验收改生产稿、历史输出或在途任务。

## 画布主页创意对话

- 在画布主页选择「资产创作」或「剧目创作」，输入创意并提交：应开启新的 Agent 对话，保留原始创意作为用户消息。未连接、Agent 忙碌、已有未发草稿或生产 SOP 不可用时应保留主页输入；断线和重复点击不得发送两次。
- 资产路线在对话明确方向后创建新画布并登记资产计划；剧目路线创建剧目、首集及绑定画布，首集梗概和完整剧情分别回读。只有明确要求出图或视频时才提交画布生成任务，核对 taskId、媒体归档与节点回写。
- 核对 Agent 开发及构建运行路径都能加载画布生产 SOP，升级时保留站点工作空间的本地修改并显示冲突提示；继续对话应沿用创作规则。检查中英文、深浅主题和小屏布局。
- Agent 连接后模型列表应来自当前 Codex 服务；若保存了该服务不支持的旧模型，自动改选服务默认模型及其支持的思考程度，创意对话不应因过期模型返回 400。

## H3 随源角色换图刷新参考

- 在角色节点原位替换一张已被 H3 Clip 选中的形象图：所有引用该角色的 Clip 参考卡和生成输入应改用新图，保留服装勾选、声线、其他 Clip 内容和历史输出；刷新画布及其他窗口也应看到新图。
- 调整服装顺序应按原图片保留选择；增加新服装不自动启用；删除唯一已选服装时回退到角色当前主图。重复提交同一编辑不产生第二次变更，失败的批量操作不留下部分更新。

## H3 角色服装选择

- 双击当前 Clip 的角色参考，弹窗应列出角色节点中的每套服装，显示缩略图、名称与预览入口；勾选后应用，仅所选服装进入当前 Clip 的参考槽和生成输入。
- 关闭服装总开关后重新打开，应恢复之前勾选的服装；更换服装不删除角色节点的完整目录，也不改变其他 Clip 的选择或声线开关。角色节点新增服装后，已有 Clip 不应自动启用新服装。

## H3 个人设置作用范围与预览路径

- 设置作用范围仅留在当前窗口，不进入共享画布 metadata；用两个窗口核对同一 H3 节点的独立选择。
- 原生 H3 将实时预览和彩色 TAEH3 开关直接提交生成节点；TE 加速展开图将目标节点和彩色 TAEH3 开关提交预览桥。授权安全重载后核对预览；执行图自动测试不代表已经运行真实 ComfyUI 生成。

## 画布视频裁剪

- 视频节点工具栏的「裁剪」按钮打开裁剪预览，普通视频和有视频结果的智能节点均显示入口。用范围滑块、秒数输入或当前播放位置选择开始与结束时间，播放选段或裁剪到画布。
- 裁剪生成独立视频节点，保留原视频和选段音轨，也支持无声视频。Backend 使用本地 FFmpeg、FFprobe，归档结果并通过现有任务与画布 ops 同步。
- 核对无效或清空范围、处理中取消、关闭或切换预览，以及刷新后任务恢复；检查中英文、深浅主题。播放预览或调整范围不应提交裁剪任务。

## H3 每个视觉来源独立描述

- 分镜编辑的实体定义中，选中的每张视觉来源均有缩略图、名称和独立的视觉特征描述；原描述保留为主体补充说明。分别描述脸部、服装或形态时，完成后提示词应将各段描述对应到各自图片。
- 描述随当前 Clip 的参考绑定保存，重排来源后跟随原图；取消选择后不编入提示词，重新添加同一来源可继续使用已保存描述。留空只使用该来源自己的规则分析，其他 Clip 不受影响。


## H3 修改稿文件与冻结短句柄（1.5.10）

- `h3_prepare_clip_updates` 读取 Backend 用户的 Hermes `cache/scratch` 内 JSON 文件（一个 `INFINITE_CANVAS_PREPARED_UPDATES_ROOT` 可覆盖源目录），传精确目标与原始文件字节 SHA-256。文件包含 `formatVersion: 1`、`projectId`、`nodeId`、`expectedRevision`、`items: [{segmentId,before,update:{segmentId,patch或edits}}]`；修改已有根字段必须提供实际 before，基线过期、次数/引用/版本错误均在冻结前整批拒绝。
- 文件必须为允许目录内的绝对 `.json` 路径且摘要一致，沿用现有本地文件导入大小上限。方案冻结在 Backend 管理的文件中，与源稿和画布分开，MCP 重连后仍可恢复；载入后改源文件不会改变旧句柄。画布操作不由脚本或私有 RPC 代提交。
- 审核返回的有界 `changePreviews`、字段清单、选择策略及摘要后，`h3_update_clips` 仅传 `preparedId`，不重新输出内联 updates。载入已经完成预检且不写画布，可选 dryRun 再核对版本；按字段选择更小且精确等价的 edits/patch。默认保护 `<d>...</d>` 对白、duration、timeline 时间边界和正文时间范围，仅用户明确授权后才能在文件 allowChanges 中列出 dialogue/timing。编译通过和字节等价不代表创意质量通过。
- 提交与恢复沿用冻结的 operationId、revision 和 operations，复用现有原子事务；重复句柄只取原回执，不再次写入。`replayed: true` 表示历史提交值，不代表当前项目状态；版本冲突不自动 rebase。完成核验或明确放弃后，`h3_discard_clip_updates` 仅删除精确冻结文件，保留原稿、画布、媒体及数据库事务回执。
- 独立真实 MCP HTTP 测试覆盖十段191条修改、载入/预览零写入、一次提交、原始 Yjs 同步、取历史回执不覆盖新稿、跨连接恢复、中途回滚和清理。真实十段清理稿的本地隔离回放也逐项一致，未写生产画布。实际常驻 Backend/Hermes 注册与用户请求到完成的耗时仍需在授权安全重载后分别验证；协议/本地回放时间不是模型端到端提速结果。

## H3 待确认任务与按钮恢复

- 同一个 H3 节点的不同 Clip 同时等待一采确认时，分别选中各段均应显示确认继续、保留一采与放弃任务；处理一段不影响另一段的任务和预览。
- 旧状态中任务仍待确认、Clip 却显示已完成时，Backend 启动恢复或拒绝重叠的重新生成请求后，应恢复该段的确认入口，不提交额外生成。放弃仍保留历史媒体并恢复之前的输出。


## H3 视觉风格与场景保持

- 夜景、池塘或其他有明确背景的 Clip 选择「柔光」「现代韩系」：风格保持场景、光照方向、机位及动作，不再额外要求过曝冷白窗光、白天或长焦；「柔光」不再附带漫画画风。真实成片是否消除突兀白背景仍需人工观察。
- 旧提示词中已保存的这两种模板前缀在本次提交时替换为新版，保持原风格选择、场景、分镜、对白与声音；关闭模板只移除已识别的模板前缀。不会自动改写保存的提示词或重新生成历史视频。
- 新运行的缓存比较包含模板正文，避免同一风格 ID 命中旧版生成输入；无模板 Clip 的缓存身份保持不变。已提交任务继续使用提交时输入，服务有活动任务时不为本修复中断运行。

## H3 增强提示词的 Clip 隔离

- 切换 Clip 后立即增强：输入原文、文本身份、模式、时长及参考素材必须都来自当前 Clip；当前文本尚未加载、同步受阻或为空时，不能读取其他 Clip 的原文兜底。
- 增强过程中切到其他 Clip：结果仍绑定发起时的 Clip，只能替换该 Clip 未变化的原文。当前 Clip 显式绑定的其他 Clip 视频仍正常进入参考清单。
- 独立浏览器页面已用内存模型复现旧问题（目标 B 搭配 A 原文），并验证修复后的输入和候选回写位置；相关测试、插件类型检查及构建通过，真实模型输出仍待用户验证。

## H3 逐段随机种子

- 选择「随机」后，复制已有 Clip 或从当前段连续运行，每次新运行应为各段分配独立种子；面板、生成记录和实际输入中的值一致，再次运行应换新值。
- 选择「固定」时保留输入值（包括 0），单独调整 LoRA 等参数不改变种子。二采确认、二采失败重试和原任务恢复沿用本次已确定的种子；重复提交同一请求不创建新任务、不重新随机。

## H3 独立取消按钮

- 单段或连续任务排队/运行时，设置面板显示「取消生成」，与重置并重新运行分开。取消只针对当前 Clip 绑定的父任务，连续任务停止其后续 Clip，不提交新生成任务，也不取消其他并发父任务。
- 取消请求期间按钮显示「正在取消…」，取消和重置按钮不可重复点击；任务已结束的竞态安全收口。缺少父任务身份时取消按钮禁用；待确认状态继续使用确认、保留一采和放弃任务。

## H3 预览尺寸与预加载

- 当前播放一采、后台预加载不同分辨率的下一段时，左下角尺寸只显示当前可见视频；切换至已预加载片段及切回一采后，尺寸标注随当前片段更新。
- 已加载媒体的虚线画幅框按实际宽高比绘制，空预览仍按配置画幅提示；网格对齐后的画面边缘应与虚线框一致。核对视频和图片切换、无自动播放，以及预览容器拖拽后仍等比显示。

## H3 分镜文本框的自定义 Subject 引用

- 定义场景、道具或其他自定义实体后，在剧情摘要、开头总体描述、逐镜描述、声景和配乐中引用对应 `<Subject N>`，应显示实体名称及可用的视觉预览；插入和修复菜单应包含全部已定义 Subject。

## H3 叙事增量与字段投影（1.5.9）

- 同节点其他 Clip 的提示词应保持可编辑；若删除前有未确认的文本草稿，旧草稿应保留而非静默写入恢复后的新文本身份。
- Clip 恢复后立即打开分镜编辑并保存：等待新提示词会话完成读取后应能保存；旧身份草稿仍留在草稿箱，新文档不含旧草稿的未确认修改。若 Backend 尚未恢复该 Clip，编辑器应显示具体读取错误并保留表单修改。
- 同一画布保留一个因 Clip 文本身份变化而受阻的旧草稿，再在其他智能图片节点编辑提示词并点击生成：当前图片提示词应正常同步与提交，旧 Clip 草稿继续保留。当前图片提示词自身同步失败时仍须阻止生成。

## 智能生图二次生成的参考范围

- 智能生图节点首次生成后，在没有实时图片参考、也没有显式恢复历史参考时打开参数设置，应继续显示文生图工作流字段，不得把自身结果或 `@` 候选算成已用参考。接入一张、两张图片以及选中两套角色服装时，设置面板应分别按实际输入切换；提示词中的 `@` 选择与实际生成器保持一致。
- 显式恢复旧结果时仍按快照参考数展示；清除历史参考后回到实时输入。循环当前输入与普通图片节点自身编辑参考保持原有行为。

- 将一个文本节点连到智能生图节点，并让该生图节点再连到另一个同时接有图片参考的生成节点。首次生成后再次点击前一个节点的生成：它应继续按纯文本输入选择文生图工作流；后一个节点仍应保留自己的图片参考。

## 循环图片输出预览对比

- 将多张图片组成有序输入组，连接到图片循环节点，同时提供一张固定参考图。生成后分别打开各轮输出预览：对比滑块左侧应是该轮对应的输入组图片；切换到同槽的历史结果后仍应对应当前输入槽。原输入已删除的旧循环槽不应误用固定参考图显示对比。普通图片结果仍按生成快照选择对比图。

## H3 潜空间二采兼容性预检

- ComfyUI 缺少 `H3LatentUpscalerNodeMegapixels` 时，开启潜空间放大二采并提交 Clip：Backend 应在一采任务开始前明确提示缺失节点，不再跑完一采才失败。安装兼容节点后，确认所选放大模型出现在 `NanFengH3LowPeakLatentUpscalerV15` 列表中，提交可继续。另行实测一采速度；预检仅解决已确认的迟发报错。
- 同时开启 H3 潜空间续写与潜空间放大二采时，应在采样前拒绝这组不兼容设置。

## H3 潜空间续写从中段接续

- 一组潜空间续写完成后，修改 Clip3 并运行当前及后续 Clip：Backend 应读取当前绑定的 Clip2 成片对应的画面与音频潜变量，只从 Clip3 开始生成，保留旧任务潜变量文件和 Clip1–2 成片；核对新任务的续写段号与归档结果。
- 改变 Clip3 的模型或尺寸、替换 Clip2 活动成片，或移走对应潜变量文件：应在 ComfyUI 采样任务开始前明确失败。本机 ComfyUI 根目录未配置时应提示不支持该续跑方式。

## H3 增强提示词传入原文

- 在 Clip 中填写含对白的完整六段式 Ref2VA 提示词并点击「增强提示词」：文本生成请求应包含编辑框当前的完整原文及参考素材清单；只有结构化提示词时不应再以“没有自由文本”为由拒绝。采用候选前检查主体引用与对白。
- 旧结构化稿前另有用户自由文本时，请求应同时包含两者，并把自由文本标为更高优先级。协作文本尚未同步完成时按钮应禁用，不应点击后毫无反应。

## 角色声线上传自动压缩

- 重启 Backend 后，在画布角色编辑器或角色资产编辑器上传大于 0.5 MB 的声线：活动声线应变为 24 kHz 单声道、64 kbps MP3，界面显示压缩前后大小，原媒体仍保留。小于等于 0.5 MB 的声线和普通音频资产上传应保持原格式。菲比角色与有对白的 H3 Clip 应引用已试听确认的压缩 MP3。
- Backend 尚未重启时，角色声线上传应明确提示压缩功能未加载，不应悄悄把大文件设为活动声线。

## 智能文字结果编辑

- 重启 Backend 后，双击已生成成功的智能文字节点结果：修改应保存到当前结果，同时保留原输入提示词。普通智能图片节点不应把媒体内容开放为文字编辑。

## H3 分镜编辑按提示词镜头数打开

- 在一个 Clip 的提示词中写两段行首 `[Shot N]`，同时加入四张分镜图。点击「分镜编辑」应只显示两镜；没有在提示词中明确指定图片的镜头应保持未绑定，可分别手动选择分镜图。完成后重新打开，镜头数与手动绑定保持不变。
- 图数与镜头数相等时，空镜头仍可按参考顺序初始化；已在提示词中明确绑定的镜头保持原顺序。重复或失效的绑定应清空，不增加镜头。

## H3 V15 LoRA 强度范围

- ComfyUI 重载修改后的 V15 自定义节点后，检查 `/object_info/NanFengH3MultiReferenceGeneratorV15`：八个 LoRA 强度输入均应允许 -4 到 10。把某个 Clip 的 LoRA 强度设为 7，确认画布保留该值，并核对新任务的 V15 实际输入和生成日志均为 7；高于 10 或低于 -4 的值应在提交前夹紧。旧日志不能证明新节点声明已加载。

## 智能图片节点工具

- 在含多张结果的图片模式智能节点上切换主图，依次检查反推提示词、裁剪、切图、局部编辑、放大、自动色阶、多角度、查看、下载与加入素材库。各工具应使用当前主图；仅有媒体存储键时也应可用。反推提示词应创建正确连线的文本与配置节点。替换图片后，原智能节点的模型与提示词配置应保留。

## H3 分镜图优先占用 Picture 序号

- 在人物图排在分镜图之前的旧 Clip 中重排分镜卡并完成分镜编辑：分镜图应按镜头顺序占用最前面的 Picture 槽位，其后才是其他图片；提示词中原有 `<Picture N>` 仍应指向各自原图。再核对新生成日志的输入 refs 和实际提交的图片槽位顺序；旧日志保持生成当时的历史快照。

## 本地总后台启动

- 在 VS Code 终端运行 `npm run dev:local`，总后台应打印启动成功且 `/health` 可响应，画布打开后可连接；Web 与 Agent 仍可用。默认 `dev:backend` 不再启动 watch 子进程；只有需要监听源码变化时才显式运行 `npm run dev:watch --workspace backend`。
- 在已有较多 H3 历史任务的画布环境运行 `npm run dev:backend`：总后台健康检查应较快可用，打开画布不再等待全部历史 H3 任务重放。启动最多处理最近 10 条待恢复候选（包括未结束任务，以及仍绑定节点或 Clip 的终态 H3 任务）；未入选的旧候选保持原状。入选的终态 H3 任务应继续完成回写，即使其较早的生成日志已按保留策略清理。

## 画布视频同屏对比

- 在有至少两个视频节点的画布中，从一个视频的顶部菜单点击「对比」：画布先进入选节点状态，高亮其他可用视频；按 Esc 或点击顶部提示应能取消且不打开弹窗。点击另一个视频节点后，对比弹窗才打开，并已选中该视频；点击当前视频或非视频节点不应打开。弹窗内可继续增删视频，画布节点本身不变。
- 播放、暂停并拖动共用进度条，确认所有视频指向同一已播放时间。时长不同时，较短视频停在末帧，较长视频继续播放；只有当前视频有声音。关闭并重新打开对比后应从初始状态开始。
- 鼠标停在进度条上，以及展开视频候选列表时，反复播放和跳转；对比弹窗应保持可用，不出现 React 更新深度报错。

## H3 LoRA 自动发现

- 在当前 ComfyUI 模型目录的 `Minimax` 子目录之外新增 LoRA，展开 H3 Clip 的 LoRA 区域，确认下拉列表显示其相对路径；保持区域展开时再加一个文件，点击「刷新 LoRA 列表」后确认无需刷新页面即可选到。选择后刷新画布，确认 Clip 仍保存该路径。
- Backend 仍加载旧目录时，在 LoRA 槽位输入 `H3_speed_slider_1.1.safetensors` 并按回车；槽位应自动启用，重新打开 Clip 后保留该 ComfyUI 相对文件名。
- 在 LoRA 区域搜索 `speed_slider`，确认各槽位下拉框只显示匹配的文件名；清空搜索后恢复完整列表，已选 LoRA 不改变。槽位内直接输入完整相对文件名仍可用。

## 智能生成与 H3 Clip 引用显示

- 在普通智能生成节点（含图片、视频、音频、文本模式）的富文本提示词里输入或粘贴 `<Picture 1>`，确认它保持普通文字，不出现“当前 Clip 引用未找到”的红色徽标；原有 `@` 素材选择仍可用。切到 H3 Clip 提示词或分镜编辑器，失效的 `<Picture N>`、`<Subject N>` 仍显示可点击修复的引用徽标。

## H3 分镜图与 Picture 顺序

- 将含 12 个行首 `[Shot X]`、复合分镜引用句 `shared by [Shot X]`，以及其他章节中分镜编号的提示词贴入 H3 Clip 并打开分镜编辑器：应只显示 `detailed_description` 内行首的 12 个分镜。保存后重新打开，分镜数、逐镜正文和复合分镜引用句仍应正确，不把句中引用拆成新分镜。
- 在画布建包含多张分镜图的有序组，调整槽位顺序。在 H3 分镜轨点击空分镜格并选该组，确认所有可用图片按槽位顺序连续进入分镜轨，原有后续分镜仍在后面；在分镜提示词编辑器的「绑定分镜图」下拉框选同一组，确认图片依次加入当前 Clip 并绑定到连续分镜项。刷新后核对分镜轨、参考列表及 Picture 顺序。组内混入非图片或无效槽位时应跳过；Clip 时长不足以给每张图至少 0.5 秒时，轨道批量导入应提示且不写入部分结果。
- 在同一 Clip 绑定三张分镜图，把第三张移到第一张之前，或先给后面的分镜格绑图、再给前面的空格绑图：参考图列表中分镜图的相对顺序应与分镜轨一致；提示词中的 `<Picture N>` 应继续指向原来的图，其他图片参考保持原槽位。
- 对已有顺序错位的 Clip，在分镜编辑器点击「完成」，或通过 `h3_write_storyboard_prompt` 按逐镜绑定写入：分镜图与 Picture 的相对顺序应对齐。刷新后核对分镜轨、参考图列表和生成前的实际参考输入顺序。

## 记住上次生图配置

- 在画布图片节点中修改模型、质量、尺寸、张数、透明背景和 16 倍数对齐，再新建图片节点：应沿用最近选择的模型、质量、尺寸、张数和透明背景；重新打开设置面板时，对齐开关也应保留选择。
- 刷新页面后再新建图片节点，确认这些设置仍在；重新打开原节点，确认它已保存的单独设置仍优先于新的默认值。

## H3 失效 Picture 引用的编辑恢复

- 在图片参考已绑定的 Clip 中粘贴 Ref2VA 提示词，并在 `subject_definitions` 中把 `<Subject 1>` 定义为婚书：编辑器应显示中性的主体标签，不再误报“人物未找到”。删去该定义但保留正文里的 `<Subject 1>` 时，失效标签应提示“主体未找到”；已有 Picture 标签仍保持原绑定。
- 选中一个 H3 Clip，确认当前 Clip 标题同时显示 `Clip N` 和内部 ID；点击 ID 可复制完整值，悬停时间轴 Clip 卡也能看到同一 ID。重排 Clip 后序号跟随新顺序，内部 ID 仍跟随原 Clip。
- 在 Clip 的提示词中使用第 4 张图片 `<Picture 4>` 后，从参考槽或素材职责弹窗移除第 3 张角色服装图：应通过 Backend ops 保存，不再因提示词编号或旧参考副本报错阻断；旧页面夹带移除前的参考列表时也应成功。刷新后确认图片仍已移除、提示词仍可编辑，角色声线和其他 Clip 不受影响；生成前检查剩余图片编号。
- 角色服装总开关关闭、完整服装目录中仍有单件保留旧 enabled 状态时，生成预检不应再要求该服装的图片绑定，声线引用仍可用。提示词若还引用失效的 `<Picture N>`，错误应指出前端可见的 Clip 序号和具体标签，不显示内部片段 ID。
- 已提交的画布操作在丢失响应后用同一 operationId 重试时，即使旧检查点含 H3 旧参考，Backend 也应返回原回执、不新增 revision；新的参考编辑若夹带未知旧素材仍应拒绝。
- 重新打开曾被旧 Backend 将已提交操作误标为拒绝的画布草稿：页面应查到原回执，以不变的 operationId 重取并清除草稿，不新增 revision；查不到原回执的拒绝操作仍须保留供用户明确处理。
- 打开一个当前仅有 3 张图片参考、但已保存分镜摘要仍写有 `<Picture 4>` 的 Clip，确认 H3 节点与页面正常显示；打开分镜编辑器后在表单内看到缺失引用提示，并能修改摘要。
- 未修正时点击「完成」应留在编辑器并提示错误；修正摘要中的编号后再完成，主体定义与保留分析按当前引用生成。此过程不应在打开页面时静默改写提示词。
- 在同时绑定分镜图、道具图、角色服装图和画外声线的 Clip 中，不把道具图加入主体清单。点击「完成」应成功保存，并将道具图写成独立参考；服装图仍属于角色视觉来源，声线仍属于画外说话人。

## H3 当前 Clip 的参考输入线

- 在画布上选中 H3 的不同 Clip，确认只显示当前 Clip 已启用素材的虚线箭头，方向为分镜图等参考素材指向 H3；切回旧 Clip 后线随之切换。分镜图在 H3 下方时，线应从图片顶部进入 H3 底部。
- 同一媒体存在多个画布节点时，应连接绑定记录中的来源节点；图片生成与裁切形成的来源实线仍表示原有生成关系，不代表 H3 输入。切换 Clip 不应新增项目连线或 revision。

## 有序组拖放与缩放

- 在测试画布中依次拖动组内成员换槽、拖出组、拖回组，每一步立即撤销和重做；核对 `groupSlots` 顺序、成员 `groupId`、位置与宽高都恢复到操作前后各自的值，不出现再次排布造成的跳位或缩小。刷新后核对 Backend 回执与页面一致。
- 在测试画布中把组内成员拖到右侧空隙，再点击「整理」，确认保存顺序与画面顺序一致；从图片边缘抓取时按图片中心命中槽位，拖到槽位区域外仍可正常移动。
- 从组外拖入或在组内拖动成员时，移至已有成员的左侧或右侧，确认出现“插入第 N 位”的落点提示，松手后成员按提示插入且原成员依次后移；移至成员中央应提示目标格，并保持原有交换或替换行为。空格、列间空隙和画布缩放下的落点提示也应与实际结果一致。
- 缩小有序组后再放大，确认槽位与成员不越出组框、成员保持原宽高比，原本适配槽位的成员恢复到原尺寸。向三成员组加入第四个成员时，新行出现后已有成员应一起重排。
- 通过 MCP 向较小的有序组添加成员并刷新画布，确认新旧成员都位于记录的槽位内。此项需先让 Backend 进程加载新构建。

## H3 站位图提示词引用

- 在同时绑定站位 / 轴线图与人物图的 Ref2VA Clip 中打开分镜编辑并点击「完成」：确认 `subject_definitions` 为站位图生成独立的 `<Picture N>` 空间规划定义，`retention_analysis` 生成对应的站位、动线与 180° 轴线保留行；人物身份来源不应把站位图当作外貌图。再通过 `h3_write_storyboard_prompt` 检查同样的引用职责。
- 对已保存实体定义且其中包含站位图的 Clip 重新编辑，确认 Subject 行将它描述为空间指引，同时仍生成独立 Picture 定义与保留行。重新生成前先检查手工改写的提示词；「完成」会重写自动生成段落。

## 编辑角色替换参考图

- 编辑角色的一张参考图并点击卡片上的替换按钮，从画布选择另一张图片后保存；确认新图片来源和尺寸已替换，卡片原有职责、服装说明、顺序及主图选择保留。取消画布选图后再用顶部“从画布添加”，确认此次操作会追加而不会误替换。

## MCP 画布状态自动分页

- 449 节点画布默认调用 `canvas_get_state` 应一次返回全部节点 ID、类型、标题和可用的生成模式，不带布局、媒体路径、metadata 或连线数组；`view: "graph"` 返回布局尺寸和连线。
- 指定 `projectId` 与相同 `ifRevision` 时只返回 `unchanged: true` 和项目摘要；revision 变化时返回新目录。与图关系、指定节点或分页参数混用时应报错。
- 摘要超过当前 MCP 输出上限（默认 512 KiB）时，应返回一页及 `nextNodeOffset`；按该位置继续读取，合并前核对各页的项目 revision 相同，并按连线 ID 去重。
- 可传 `nodeLimit` 主动控制单次节点数量与 token 开销。若单个节点摘要即使不带连线仍超限，应明确返回 `OUTPUT_TOO_LARGE`，不能给出无法前进的分页位置。

## MCP 定向画布读取瘦身

## H3 参考素材职责与角色组统一弹窗

- 挂载一张由角色节点参与生成的分镜图，打开「参考素材职责」弹窗，确认「分镜中出现的人物」已自动勾选本次生成实际引用的角色，未参与生成的角色不应被勾选；分别通过画布选节点和拖拽挂载验证，旧图片节点沿参考连线回溯角色的场景也应生效。
- 对分镜图片点击预览左上角删除按钮，确认只移除当前 Clip 的图片引用，分镜卡片及其时长保留为空分镜，画布上的原始素材不受影响；「去除素材」仍移除整个当前引用。

- 在 H3 Clip 的 Refs 行双击普通素材、角色参考和分镜素材，确认均打开「参考素材职责」；单击职责标签不再打开弹窗。点击「从画布替换」并选择相同类型素材，确认原引用位置被替换且职责/用途保留；点击「去除素材」只移除当前引用。左侧预览的放大按钮应打开完整图片/视频/音频灯箱，点遮罩、关闭按钮或按 Esc 均可关闭。
- 双击角色组引用确认同一弹窗内仍显示服装目录和声线开关；切换服装启用状态或声线后应用，确认 Refs 与提交输入同步更新；“从本段移除整组”仍可移除角色组。服装图放大预览不改变启用状态。
- 角色参考图职责与提交用途仍由源角色节点控制，提交用途固定为普通参考；打开角色参考素材编辑时不再显示职责、提交用途说明和标签字段，在浅色和深色主题下确认预览及操作控件清晰可用。

- Agent 设置回填：连接后台后应能正常读取并回填 Agent 面板宽度、权限模式、模型和推理强度，浏览器控制台不应出现 `set is not defined`。
- H3 智能分镜：Ref2VA 应同时向分镜模型传入实际参考图片、素材清单和逐图分析；I2VA 只传图片1，FL2VA 只传图片1和图片2，T2VA 不传图片；图片、视频、音频编号应分别从1开始，并与最终输入槽位一致。
- H3 提示词增强：在 T2VA、I2VA、FL2VA 和 Ref2VA 模式下点击「增强提示词」，应按当前片段时长生成对应官方字段结构；已连接的图片、视频和音频应按各自编号传入模型；全局提示词应参与增强；用户对白和画面文字应逐字保留。
- 文档站导航与本页目录：手机宽度打开文档侧边栏时，顶部应显示当前文档分类及说明；展开后可在项目介绍、操作手册、开发文档、项目进度、商务合作和赞助支持之间切换，切换后分类标题及下方页面列表应同步更新；桌面端顶部分类栏保持不变，宽度达到 960px 时正文右侧应显示带层级折线的本页标题目录，点击可跳转，滚动时自动高亮当前标题；较窄宽度继续显示顶部折叠目录。
- Canvas Agent 生成流程引用：提示词仅包含已经通过 `referenceNodeIds` 传入的 `@[node:...]` 引用时，应直接把现有文本、图片、视频、音频或组节点连接到生成配置节点，不再创建重复的提示词文本节点；提示词包含普通文字时仍应创建独立的提示词文本节点。
- 视频画面截取：右键有内容的视频节点应显示「截取首帧」「截取尾帧」「截取当前帧」；三项操作应按视频原始比例在右侧生成并选中图片节点，同时建立视频到图片的连线；「截取当前帧」应使用播放器此刻停留的画面，截取过程不得改变原视频的播放位置。
- 文本节点：节点正文右上角不再显示「生图」按钮，文字内容应使用完整正文区域；节点上方工具条中的生图入口仍可正常创建生成配置。
- 多文本生成：生成次数大于 1 时只创建一个文本结果节点和一条来源连线；节点右上角显示实际生成成功的文本数量，点击后应像多图节点一样展开所有备选文本；点击「设为主文本」应立即替换正文，原主文本保留为备选，双击正文编辑后再次切换回来仍应保留修改。
- 组节点引用：组节点应使用透明、轻量的边框与标题样式，并显示右侧输出连接点；把组连接到生成节点后，组内有内容的图片、视频、音频、文本及可引用扩展节点都应作为输入，普通提示词面板的 `@` 列表应显示组内资源，生成配置的 `@` 列表应允许一次选择整组；组与单节点重复引用时不得重复发送同一资源。
- 节点参考栏：普通节点提示词面板、放大编辑器和生成配置输入框上方应显示当前输入节点；图片和视频显示缩略图并可悬停预览，文本、音频及扩展节点显示对应类型；组连接应展开显示组内每个有效内容节点，删除任一展开项都应断开整组连线。点击加号进入画布选择后可连续添加有效参考，已连接、目标自身、已通过组引用的组内节点及不可引用节点不可重复选择，按 ESC 或顶部提示返回输入框；新增连接后 `@` 列表应立即更新。
- 多图透明背景：展开包含透明 PNG 或 WebP 的多图节点时，主图与所有备选图的透明区域都应直接显示画布背景；切换主图前后不得出现白色或主题面板底色。
- 画布选择与平移：左下工具栏应能切换「选择」与「移动」模式并用图标显示当前模式；选择模式拖动空白区域应显示疏朗清晰的虚线框，虚线长度、间距和粗细在任意缩放比例下保持一致；移动模式应能从空白区域或节点上拖动画布。按住 Control 或空格应临时反转当前工具且不改变工具栏模式，即选择变移动、移动变范围选择；点击画布页任意按钮后按空格应只临时切换工具，不得再次触发该按钮；输入框和可编辑文本内仍可正常输入空格。中键平移以及 Shift/Cmd 追加选择节点应继续可用。
- 文档站国际化：访问文档站首页及 `/docs` 应直接显示英文，不得出现重定向循环；切换简体中文后 URL 应带 `/zh-CN` 且首页、顶部导航、侧边栏、正文、搜索框和页面操作文案均显示中文；刷新、站内跳转和再次切回 English 后语言应保持正确，搜索结果与 Markdown/LLM 文档内容不得混入另一种语言。
- 国际化基础框架：从页面右上角切换简体中文或 English 后，首页、顶部及移动端导航、版本弹窗、配置主面板、渠道编辑、模型选择、页面标题、页面描述和 Ant Design 内置文案应立即切换，刷新页面后保持所选语言；偏好设置中不应再显示语言选项，WebDAV 同步错误、提示词来源及其他尚未接入翻译的业务模块暂时仍可能显示中文。
- 全局弹层主题：全站 Dropdown、Menu、Select、Cascader、TreeSelect 等弹层在浅色主题下应使用白色背景、轻灰悬停和选中态，在深色主题下应使用深色背景与低对比度浅色交互态，不应再出现默认黑灰色块、文字对比不足或单个页面配色不一致。
- 画布节点缩放稳定性：选中任意节点并反复拖动四角缩放时，节点工具条应在缩放期间隐藏、松开后恢复，页面不应再出现 `Maximum update depth exceeded`。
- Agent MCP 初始化状态：首次进入空白对话、点击「新对话」或恢复历史对话后，无需先发送消息，对话区应立即显示 Codex 会话准备，并列出 `codex_apps`、`infinite-canvas`、`node_repl` 等完整 MCP 服务状态；全部服务进入终态前可输入并保留草稿，但发送按钮、上传和回车提交应禁用；可选 MCP 失败时应提示警告但允许发送，`infinite-canvas` 缺失或失败时应阻止发送并显示明确原因；首轮及后续任务运行期间再次收到的 MCP 状态只进入诊断日志，模型开始处理及回复完成后对话区不应残留初始化卡片。
- Agent 模型设置：连接 Canvas Agent 后，输入框左下方应显示当前 Codex 模型与推理强度；模型列表应来自当前账号实际可用模型且不显示内部审查模型或重复项，切换模型后强度选项随模型能力更新且无空白选项，刷新页面后保留选择，发送任务时实际使用所选模型和强度；本地控制台与右侧「日志」应记录本轮使用的模型和推理强度。
- Agent 新对话响应：一轮对话完成后点击「新对话」，聊天内容应在服务端确认切换后清空并进入空白对话；后台应串行创建线程并预热 MCP，多个标签页应按同一会话版本同步，旧 HTTP 响应不得覆盖较新的 SSE 状态，初始化完成前不能发送到上一条会话或重复创建线程；重启 Agent 后应重新恢复并预热已有活动线程，无法恢复的失效空线程应自动替换为可用的新线程。
- Agent 读取画布卡片：读取当前画布完成后，卡片应按非零类型显示文本、图片、配置、视频、音频、分组、其他节点及连线数量，例如「3 个文本、5 张图片、2 个配置、4 条连线」；空画布应显示「当前画布为空」，执行失败时仍应显示错误信息，刷新恢复历史后统计保持一致。
- Agent 首次发送响应：在空白新对话中输入内容并按回车后，输入框应立即清空、用户消息应立即出现在对话中，再显示「正在思考」；线程创建或发送失败时，原输入和附件应恢复；任务运行期间输入的新草稿不应在请求成功后被清空。
- Agent 动态工具信息：执行内置生图、查看图片、命令、文件修改或其他动态工具时，卡片标题应显示具体工具名称；执行失败时正文应显示真实错误原因，刷新并恢复历史对话后仍应保持一致，不再统一显示「工具操作已完成」。
- Agent 画布生图：重启 Canvas Agent 后，其自动生成的工作区 `AGENTS.md` 应同步为最新版指令（用户自行编写的其他 `AGENTS.md` 不应被覆盖）；输入“生成一张图片”时应调用 `canvas_generate_image`，通过当前画布节点创建并运行生成流程；只有明确输入“使用 Codex 内置生图/ImageGen 技能生成”时才允许调用内置能力，Codex App Server 返回的 `imageGeneration` 结果应显示在对话中并作为保持原比例的图片节点添加到当前画布；Agent 不应在没有生成结果时提前声称“已生成”。
- Agent 顶部栏：在对话、历史和日志之间新增「技能」标签并显示已加载数量；连接状态应位于左侧 Agent 标题旁，并与右侧新对话使用相同规格的文字按钮，只有内容标签显示选中线；标签图标始终显示，中英文模式下都应按标签区域的实际可用宽度隐藏文字并保留小号数量，空间足够时显示图标和文字，拖动宽度时不应裁切、换行、横向滚动或错位。
- Agent 输入框窄屏布局：底部上传、Skill、确认模式、权限模式、模型和思考程度控件在窄面板下应只显示图标，宽面板下恢复文字；所有纯图标操作悬停时应使用统一样式显示名称或当前状态，任意宽度都不出现横向溢出。
- Agent 本地 Skill 管理：连接 Canvas Agent 后进入「技能」，应能读取当前 Codex 工作空间发现的项目、个人、系统和管理员 Skill，并支持搜索、按范围筛选、刷新及启停；未能加载的 Skill 应通过可点击、可滚动的详情查看原因；画布在站点工作空间 `.agents/skills` 下创建的 Skill 应可新建、编辑和删除，其他来源只读且不得被画布改写；编辑期间文件被其他窗口修改时应拒绝覆盖，清空显示名称、短说明和默认提示词后旧值应被删除，同时保留图标、品牌色等未由当前界面管理的元数据；多个标签页同时连接时，任一页面的 Skill 变更应自动同步，断开或切换 Agent 时旧请求不得重新写回列表或弹出编辑器。
- Agent Skill 草稿生成：创建 Skill 时应提供「空白创建」「从当前对话生成草稿」「从当前画布生成草稿」三种入口；空对话不得发起生成，取消时不得写入文件，确认后才写入站点工作空间 `.agents/skills`；Agent 运行中应禁用生成，多标签页下对话和画布来源必须分别严格绑定发起请求的 `threadId` 和 `clientId`，生成期间外部 MCP 仍应操作最近聚焦页面；草稿运行时创建、启停、删除和更新 Skill 应被统一拒绝，点击停止应真实中断临时草稿 turn；草稿不得泄露本地路径、密钥、媒体数据、真实节点 ID 或任务进度等临时状态，普通中文斜杠文本与 `/imagine` 等命令必须保持完整，生成草稿使用的临时 turn 不得出现在 Agent 对话、历史或日志中。
- Agent Skill 调用：在技能页点击「使用」或在输入框输入 `/` 搜索并选择 Skill 后，Skill 应作为原子 token 插入正文，而不是显示在输入框上方；发送任务时应通过 Codex 原生结构化 Skill 输入执行，发送成功后清除选择，失败时保留；新建对话、断开连接、Skill 被停用或删除时也应清除失效选择，发送前、任务完成后和刷新历史后的用户消息文字与 token 位置应保持一致。
- Agent 输入框快捷引用：输入 `/` 后应显示已启用 Skill 列表，输入 `@` 后应显示当前画布的图片、视频、音频和文本素材，长列表使用较高的内部滚动区域；选中项应按当前光标位置插入正文，例如「这是第一张图 `@图片1` 融合第二张图 `@图片2`」，不再集中显示在输入框上方，按 `Backspace` 或 `Delete` 时应整块删除；发送时应保持原句顺序，按节点 ID 精确引用发起页面的素材，并把引用图片的实际内容交给 Codex；输入框和聊天记录都应将引用渲染为与正文基线对齐的紧凑标签，悬浮或聚焦后可预览图片、视频、音频或文本内容，不重复显示内部图片附件，切换会话或刷新后引用样式应保持；可用方向键、`Enter` 或 `Tab` 选择，`Esc` 应关闭候选菜单，候选菜单打开时回车不得误发送消息。
- Agent Markdown 样式：右侧 Agent 回复中的代码块应为横向占满消息区域、无语言标题和无双层边框的紧凑代码条，单行内容不应保留纵向大面积空白，复制操作仅在悬停时弱化显示；行内代码、链接在浅色和深色主题下应清晰；点击外部链接后应显示中文紧凑确认弹窗，长路径能够正常换行且复制、继续打开和关闭操作可用；点击 `/Users/`、`/home/` 等本地绝对文件路径时应改为提示在系统文件管理器中定位，支持复制路径，且浏览器地址不应跳转为 localhost 文件路径。
- Agent 工具确认模式：右侧面板标题栏不应再显示「工具确认」开关；对话输入框左下方应显示确认模式选择，默认选中「自动确认」，画布写入工具应直接执行；切换为「手动确认」后，画布写入工具应在对话中展示等待确认卡片，并支持批准或拒绝。
- Canvas Agent Codex 升级：启动 Canvas Agent 后应输出 Canvas Agent、内置 Codex 和本机 Codex 版本，实际运行的内置 Codex 应为 0.160.0；内置与本机版本不一致、未安装本机 Codex，或 npm 存在更新版本时应显示对应升级提醒，npm 检查失败不应阻止服务启动；Agent 模型下拉框应展示新 app-server 返回的 GPT-6 系列，能正常创建或恢复会话、发送消息并调用画布工具；运行中停止任务应只中断当前 turn，随后无需重启 Agent 即可继续发送新任务。
- Canvas Agent Debug：普通启动应通过公共 logger 输出 Info、Warn 和 Error 日志；使用 `npx -y @basketikun/canvas-agent --debug` 启动后还应输出 Debug 日志并显示日志文件路径，终端统一采用“`YYYY-MM-DD HH:mm:ss` 级别 消息 详情”的纯文本单行格式，`~/.infinite-canvas/logs/` 下应按启动日期生成相同格式的 `canvas-agent-YYYY-MM-DD.log`，同一天多次启动应追加到同一文件；日志中不应出现连接 token 或图片 Data URL 原文。
- Canvas Agent 凭据脱敏：Codex 与 Claude CLI 的 stderr 包含 Bearer token、`sk-` 密钥、显式 API key/token/authorization 赋值、ANSI 样式或跨输出分片的凭据时，调试日志和网页诊断事件均不应出现明文；普通 stderr 文本应保持不变。
- Canvas Agent 配置权限：在 Linux 和 macOS 上保存配置后，`~/.infinite-canvas` 权限应为 `0700`，`canvas-agent.json` 权限应为 `0600`，已有的宽松权限也应被纠正；配置应能继续正常读写，Windows 启动不受影响。
- Canvas Agent URL 自动连接：链接应在 `#` 后传递 `agentUrl` 和 `agentToken`，进入或选择具体画布时继续保留，读取后立即从地址栏移除，并可连接有效的本机、局域网或远程 HTTP(S) Agent 地址且不主动展开设置面板；缺少参数或地址无效时应展开设置并显示错误。
- 图片 API 模型参数：`gpt-image-*` 的生成和编辑请求不应发送 `response_format`，`dall-e-*` 请求仍应发送 `response_format: "b64_json"`。
- Canvas Agent Codex 日志：Codex app-server 输出带颜色或样式控制符及 UTC 时间的 stderr 时，本地日志和网页诊断日志应只显示一份 `YYYY-MM-DD HH:mm:ss` 本地时间和干净文本，不应出现重复 ISO 时间或 `[2m`、`[31m` 等 ANSI 转义内容。
- Agent HTTP 诊断日志：网页发送一条普通消息后，本地 Debug 日志不应重复输出 `/health`、`/canvas/state`、`/canvas/activate` 成功请求、流式增量或完整会话响应，只保留 HTTP 请求与 Codex 生命周期摘要；右侧「日志」应以单行时间线展示发送、开始、回复、工具、完成用量和错误，不再输出 userMessage started/completed、流式摘要、重复 threadId 或大段原始 JSON。
- Agent 排查日志：右侧「日志」中的排查视图应显示连接摘要，并可按错误、警告和信息筛选；向下查看日志时仅列表内部滚动，标题、连接状态、筛选数量和操作按钮保持固定；连续相同事件应折叠计数，单条日志可展开查看完整详情；原始 JSON、复制全部、复制最近错误和清空功能应继续可用，浅色与深色主题下均应清晰。
- Agent 排查日志顺序与跟随：日志应按时间从旧到新排列，进入日志或切换筛选时定位到最新事件；停留底部时自动跟随新日志，展开最后一条后应继续停留在完整详情底部，向上浏览后暂停跟随并显示与对话区视觉高度一致的居中圆形向下箭头，新日志数量只在悬浮提示中显示；列表底部不应出现额外留白，点击按钮后回到底部并恢复跟随。
- Agent 对话统计：用户消息应右对齐并使用透明无气泡的简洁排版，用户和 Codex 两侧均不显示人物头像，消息下方均不显示时间或 Token 信息；输入框上方应居中展示最新一次模型调用的输入、缓存、输出 Token 用量，不显示会话累计值，数值更新时应从旧值平滑滚动到新值而非突然跳变，新建、切换或删除当前会话后应清空旧统计。
- Agent 回复实时显示：在右侧 Agent 发送消息后，用户消息下方应立即出现“正在思考...”，任务运行期间不应闪退；工具完成后应显示 Codex 正在继续处理及已等待时长，等待超过 30 秒时提示可继续等待或停止本轮；Codex 的回复应在当前对话中持续显示，实时事件缺失时也应在任务完成后自动同步完整内容，无需切换到历史或日志再返回对话。模型繁忙等任务失败时应立即结束等待状态，在对话中显示中文错误原因和重试建议，诊断日志不应再把失败轮次记为“处理完成”，刷新历史后错误仍应保留。新建尚未发送首条消息的空会话不应反复出现历史读取失败。
- Agent 对话实时与历史一致性：运行包含思考、命令及画布工具的较长任务，在执行中刷新发起页面或打开第二个页面时，已出现的用户消息、思考过程、工具卡和回复前缀均应保留并继续更新；同一思考或工具只显示一张卡片，任务结束及再次刷新后内容、顺序和状态应一致。切换页面焦点不能改变本轮画布工具目标，发起页面断开后不得把图片或写操作转交其他画布，使用相同页面身份重连后才能继续处理。
- Agent 流式交互性能：发送长回复时文字应连续平滑出现，输入框、滚动和画布操作不应随回复变长而明显卡顿；长历史会话中只有当前流式消息持续更新，屏幕外消息不应造成明显布局压力；任务完成后应通过 SSE 自动同步完整历史，不再持续请求 `/health` 轮询状态。
- Agent 过程时间线：新建 Agent 对话后 Codex 应生成可读思考摘要，并在运行时依次显示中文的思考摘要、执行计划、命令执行、网页搜索、文件修改和画布工具活动；思考摘要的图标、标题和箭头应稳定保持在同一行，默认收起且无边框，点击箭头后才展开 Codex 实际返回的具体摘要，其中 Markdown 强调、列表和代码应正确渲染而非显示原始符号，多行代码块和文本流程图应保留原始换行并允许横向滚动，完成事件不应再用「已完成分析」覆盖已经收到的摘要；同一轮连续命令应合并为显示数量的无边框折叠行，折叠时不显示命令预览，单条展开后直接显示详情，多条展开后可逐条查看工作目录、耗时、退出状态和运行输出；其他工具调用继续使用紧凑卡片排版，状态图标、标题和状态文字保持在同一行；结构化任务进度不应混在对话时间线中，而应独立放在对话区下方、Token 统计上方，支持展开和折叠，并逐项实时更新「待处理」「进行中」「已完成」状态；新任务生成时默认展开，任务结束后保留最新结果，同一计划更新不应生成重复内容；文件详情展示文件路径与新增/修改/删除动作，工具详情不应出现请求 ID、英文工具名或原始 JSON；一轮对话结束自动同步历史以及刷新页面后从历史中 resume 对话时，思考摘要、命令和工具过程记录仍应完整保留并保持相同展示。
- Agent 权限控制：输入框可选择「请求批准」「自动审查」「完全访问」；请求批准模式下，Codex 编辑工作区外文件、执行受限命令或访问网络时应在对话中显示审批卡片，支持拒绝、允许一次和本会话允许，并能依次处理多个并发请求；提交决定后卡片应保持禁用等待，只有 Codex 确认处理后才移除；等待审批时刷新页面，未处理的审批卡应自动恢复且不能让任务永久卡住；自动审查模式应仅将需要用户决定的风险操作送入审批；完全访问必须先显示风险确认，启用后可访问网络和本机文件且不再请求审批；选择应在刷新后保留。
- Agent 历史记录：点击记录卡片应直接进入对应对话，不再显示「进入」按钮；可勾选单条或全选多条记录并批量删除，删除当前对话后聊天内容应清空。
- Agent 默认新对话：每次进入任一画布并连接 Agent 后，对话区应保持空白且不自动恢复上一次会话，并在后台创建新线程、预热 MCP；需要继续旧对话时可在「历史」中主动选择恢复。
- Agent 当前画布优先：在已打开某个画布时要求 Agent 创建、修改、整理或生成内容，Agent 应直接读取并操作当前画布，不应先调用 `canvas_list_projects` 或使用 `site_navigate` 重复进入画布；只有明确要求查看或切换其他画布时才允许查询画布列表并导航。
- Agent 图片消息：发送一张或多张图片附件后，图片应紧跟用户文字并在消息右侧显示为约 40px 的紧凑缩略图，不再撑大消息区域，单击缩略图应打开大图预览，打开或关闭预览不应改变消息间距或产生额外空行；任务运行中、完成同步历史、切换页面及重新进入历史对话后都应显示浏览器本地保存的图片缩略图，不应消失或把 attachmentId、附件使用说明等内部上下文回显到用户消息中；删除历史会话后应同步清理对应缩略图。
- 画布文本复制：在 Agent 对话或节点信息详情中用鼠标选中文字后，按 `Ctrl/Cmd + C` 应复制所选文本，不应触发画布节点复制；未选中文字且焦点位于画布时，原有节点复制快捷键应保持可用。
- Agent 工作目录指令：`canvas-agent/agent-instructions.md` 应作为独立维护源；重启 Canvas Agent 后，当前工作目录应自动生成 `AGENTS.md`；新建对话发送消息时，Codex 日志中的用户消息只包含本轮请求和必要的附件上下文，不再重复整段 Infinite Canvas 前置提示词，画布及工作台工具仍可正常调用。
- 画布文本设置：文本节点和生成配置节点切换到文本模式后应显示推理强度设置，可选择自动、低、中、高、极高；选择自动时默认 OpenAI Responses 请求不应携带 `reasoning`，选择其他档位时应携带所选强度，刷新画布后节点设置应保留；文本模型自定义调用脚本应能读取 `reasoningEffort`，OpenAI 模板应按自动或指定档位正确组装请求。
- 生图工作台参考图：将一张或多张图片拖入参考图区域后应直接上传并显示缩略图；拖入非图片文件应忽略，拖动过程中区域应显示高亮提示，放下文件不应导致浏览器打开或替换当前页面。
- 工作台历史图片清理：生图或视频工作台生成内容后，在「我的素材」删除图片、删除画布图片节点、清空画布或删除画布，再次打开对应生成记录时，历史缩略图、结果图片和参考图仍应正常显示；删除生成记录时，其专属本地文件仍应正常清理。
- 视频创作台参考资产：将图片、MP4/MOV 视频或 MP3/WAV 音频拖入任一参考资产区域后，应按文件类型自动上传到对应列表；当前拖入区域应显示高亮提示，原有数量、大小、时长和格式限制应继续生效。
- 画布组装提示词：输入或连接超长提示词后，浮层正文高度不应继续撑大，内容应可在正文区域内滚动查看和编辑，标题及关闭按钮保持可见。
- 画布节点提示词：图片等节点下方的提示词超过输入区域高度后，鼠标悬停在输入区域内滚动应查看提示词内容，不应缩放画布。
- 画布节点提示词回显：单图或多图生成完成后，切换选择生成结果的根节点及任一子节点，下方输入区域都应继续显示生成时的提示词；切换到其他节点再选回来后也不应清空。
- 画布生成配置：连接文本节点后连续点击生成（包含失败重试），组装提示词不应重复追加上游文本；在生图、文本、视频、音频之间切换时，实际请求应始终使用当前面板展示的对应类型模型。
- 画布多图生成：开始生成 N 张图片后应立即创建一个包含 N 个可展开槽位的图片节点，并且来源到结果只保留一条连线；生成期间空槽位应独立显示生成中或失败，任何已有图片内容的槽位都必须始终显示图片，任意图片率先成功后应立即成为主图并展示，不等待其他请求完成；收起状态应最多显示三层紧密错开的背板，避免占用过多画布空间，右上角应显示醒目的「N 张」数量提示；点击数量后，浮动工具条应暂时隐藏，各图片槽位应从当前节点向右上方整齐展开；已成功图片的「设为主图」应常驻显示，并在亮色、深色主题及不同图片背景上保持清晰；点击画布空白处应自动收起并恢复工具条。
- 画布多图主图切换：点击「设为主图」后，节点中心和当前最长边应保持不变，仅按新图片比例调整另一条边；自由变形节点应完全保持现有宽高，画布视口及左下角缩放值不应变化。
- 画布多图失败槽位：包括当前主槽位在内的每个失败槽位都应显示「重试」和「删除」；重试只更新当前槽位，已有成功主图时不得抢占主图；删除只移除当前失败槽位并同步更新图片数量。
- 画布多图尺寸调整：子图展开时开始拖动尺寸控制点，应先收起图片组一次，再正常调整根节点尺寸，不应触发 React 循环更新或应用错误页。
- 画布左侧元素列表：点击元素整行应平滑定位并选中对应节点，自动缩放不得超过 100%；有内容的图片元素应显示预览按钮，点击后打开大图弹窗且不触发画布定位。
- 配置与用户偏好：导出 JSON 后应包含渠道、默认模型、生成偏好、提示词来源和 WebDAV 配置；在修改当前配置后重新导入该文件，应恢复导出时的设置，错误 JSON 文件应提示格式不正确。配置文件包含 API Key 和 WebDAV 凭据，不应公开分享。
- 局部遮罩编辑：弹窗底部应为「重置」「导出到画布」「立刻生成」；两个按钮都要求已涂抹区域并填写修改要求，「导出到画布」只写入节点和连线不发起请求，结果节点的提示词面板应预填拼好的提示词并可手动生成，「立刻生成」在写入节点后立即生成。涂抹区域并填写修改要求后确认，画布应在原图下方生成一个「遮罩标注」图片节点，内容为原图叠加半透明蓝色标注区域，颜色和透明度应与弹窗里涂抹时看到的一致；结果节点在原图右侧生成，并同时接收来自原图和遮罩标注的两条连线。请求应按普通参考图发送两张图片，提示词按「图片1 / 图片2」编号说明原图和标注区域，不再携带 mask 参数，Gemini 格式渠道也应可用；生成结果只改动标注区域，且不得残留蓝色标注。
- 图片编辑弹窗：遮罩、切图和裁剪连续滚轮缩放时，图片与遮罩应保持同步且不再闪烁、短暂消失或跳动；遮罩画笔圆心应始终固定在鼠标位置，仅直径随缩放变化，缩放后仍可准确涂抹、拖动切分线和调整裁剪框。
- 提示词中心布局：页面标题及提示词总数应居中；连续输入搜索文字时应在停止输入约 300ms 后再查询；桌面端分类与标签应在左侧独立滚动，右侧搜索框下直接展示提示词卡片；标签数量较多时不能继续向下挤压提示词，窄屏下应恢复上下排列且内容不溢出；不再显示「我的提示词」Tab，收藏提示词应直接加入我的资产。
- 提示词详情弹窗：封面和参考图应固定显示在上方，复制及加入资产操作栏固定在底部，只有中间的标签、描述及提示词内容区域可以滚动；弹窗宽高应受视口限制且不超出屏幕。
- 提示词来源：7 个内置来源应从 Image Prompts 统一仓库读取，更新后数量依次为 323、494、517、53、76、126、129；提示词仍按 7 个来源分组并可独立启用，来源内可继续按 `tags` 筛选。添加标准 JSON URL 后应能查看内容，填写非数组 JSON 或不可访问地址时应显示失败，并继续保留该来源上一次成功缓存的内容。
- 提示词缓存迁移：拉取提示词源后刷新页面，确认提示词中心能从 Backend 恢复缓存；修改来源地址或超过缓存周期后，确认会重新拉取并覆盖对应缓存。
- 提示词中心加载态：清空或首次打开提示词中心时，确认远程来源加载期间显示明显的加载卡片；已有缓存后台刷新时不遮挡当前列表。
- 提示词详情图片预览：点击详情页封面或参考图，确认能打开大图预览并可关闭返回详情页。
- 提示词来源界面：来源应以卡片列表展示，启用开关位于左侧，数量、同步状态和上次成功时间作为次级信息显示，查看、拉取及自定义来源编辑/删除操作使用带文字按钮；底部定时拉取区域应保持独立边框布局。
- 画布提示词库：不应再显示「我的提示词」分组；不展开任何公共来源直接搜索其中的提示词，匹配项应自动显示；点击「插入画布」后应创建正文正确且标题保持为提示词标题的文本节点。
- 全站 Agent：新增 `generation_get_status` 工具，画布生成节点可按 `nodeIds` 查询，生图和视频工作台提交后会返回 `taskId` 并可查询排队、运行、成功或失败状态；需验证查询只由当前活动标签页返回。
- 本地 Agent 多标签页隔离：同时打开两个不同画布并连接同一个 Agent，分别聚焦标签页后通过 MCP 读取和修改画布，操作应只落在当前聚焦页面；网页面板发起的整个 Codex turn 应固定操作发起页面，即使中途聚焦另一标签页也不能切换目标；非运行状态关闭当前页面后应回退到最近聚焦且仍连接的页面，运行中关闭发起页面则不得把操作转交其他画布，只有同一页面身份重连后才能继续；其他页面回传同一请求结果应被拒绝。
- 本地 Agent 多标签页会话同步：所有标签页共享同一个站点级 Codex 活跃线程；任一页面发送消息、新建、恢复或删除会话后，其他页面应同步活跃线程和聊天记录；Agent 输出仅显示在事件所属线程，运行中不能新建、恢复、删除或再次发送任务。
- 本地 Agent 运行状态同步：在一个标签页运行较长 Codex 任务，等待某张工具卡显示「工具完成」后再打开或刷新第二个标签页；第二个标签页应立即显示 Codex 正在运行并禁用发送，整轮结束后两个标签页同时恢复；工具卡只显示「工具完成」，整轮结束由「本轮完成」表示。
- 本地 Agent 图片附件落画布：在右侧 Agent 上传参考图并要求基于商品信息创建生图流程，附件应创建为保持原比例的真实图片节点，分析提示词应创建为文本节点，二者都应连接到生成配置节点；刷新页面后参考图仍可显示并参与生成。任务中途切换到其他标签页时，附件只能写入发起任务的标签页；若发起标签页关闭，附件读取应失败且不能落入其他画布。
- Agent 对话滚动：从历史或日志切回对话、恢复其他会话时应自动定位到最新消息；手动向上浏览后应显示与日志完全相同尺寸、位置和样式的居中圆形向下箭头，新消息不强制打断阅读，对话底部不应出现额外留白，点击按钮后平滑回到底部并继续跟随新消息。
- Agent 消息区分：用户消息应在右侧使用透明无气泡排版，AI 回复应在左侧使用无头像的开放式 Markdown 排版；长文本、多张附件、错误消息及浅色/深色主题下均应清晰且不溢出。
- Agent 命令记录：命令执行中应显示运行状态；完成后，同一轮相邻命令应合并为「已执行 N 条命令」折叠行且默认不显示原始命令，单条展开后直接显示完整详情，多条展开后可分别查看命令、输出和退出状态；对话结束或刷新后分组与记录不应消失。
- 跨域提示：生图、视频或音频请求被浏览器跨域策略拦截时，应明确提示需要通过自己的服务转发请求，不再只显示笼统的网络错误。

### 画布循环节点

- 将 8 个输入节点放入左侧有序组，设置起始序号与每轮数量，确认轮数随可用槽位自动计算且面板不提供手填轮数；序号越界时不提交任务。没有可计数输入时默认一轮。
- 将 8 张图片和 2 张固定参考连到循环，右侧连接 2 个生成节点后运行；确认 Backend 将它们按顺序纳入单个右侧有序组并补足到 8 个槽。所有结果都使用循环节点的模型与提示词，每轮参考内容依次对应输入槽；已有节点 ID、旧媒体与生成历史保留。重跑仍写回对应槽。
- 将两张可用图片放入左侧有序组，循环节点旧设置为“图片关闭”、每轮数量为 1 时仍应显示并运行 2 轮；左侧第 1/2 张图分别以可见参考线连接右侧第 1/2 个结果槽。改起始序号或每轮数量后，参考线随本轮实际输入更新，不保留上一轮计划的错位连线；缩小画布查看组连线概览时仍能看到逐槽参考关系。
- 将旧连线整理成「循环 → 生成 A → 生成 B」后运行，确认 A、B 都被纳入同一个输出有序组，分别承接前两轮；旧 A→B 连线被移除，不将 A 的结果传给 B。多余既有输出节点不删除。
- 分别设置图片、视频、音频和文本输出模式，确认生成面板的模型、提示词和参数与循环节点本身一致；四种结果均写入指定输出槽，重跑保留旧媒体/文本历史。
- 输入组包含文本提示词时，确认轮数按组内节点槽位数计算，每轮文本与循环提示词正确组合；`《计数》`、`《总数》`、`《进度》`按本轮序号替换。每轮数量大于 1 时按有序组相邻槽分批，不回绕。
- 在一轮失败、并行轮次反向完成和点击停止时确认任务只回写自己的槽；失败或停止后不启动待运行轮次，已完成轮次结果保留。重复准备同一个 runId 返回原输出组和槽位，不重复创建节点。
- 图片任务日志分开展示「固定 refs」和「本轮组图」。当本轮需要 1 张组图 + 2 张固定图、选用的工作流却只有 2 个图片输入槽时，运行前提示槽位不足；Backend 也拒绝提交到模型，不能静默丢掉第三张。选择具有 3 个图片输入槽的工作流后逐轮运行。
- Flux2-Klein 工作流若使用旧 Inspire 单模型加载节点，执行时转换为当前 ComfyUI 内置 CLIP/UNET 加载节点，不覆盖用户工作流文件；ComfyUI 服务恢复后用三图输入验证真实推理与结果归档。
- 并行轮次反向完成时结果仍归各自输出节点；失败或停止会取消在途任务，不再启动其余轮次。非媒体生成链选择并行时须明确拒绝提交；视频结果不得被图片生成节点静默当作参考图。
