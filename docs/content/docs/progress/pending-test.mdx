# Pending Tests

## H3 first-pass confirmation

- Run a confirmation-mode clip on a test canvas. After the first pass, the original parent task, node, and clip should show `awaiting_confirmation`; the task center should preview the first pass and offer confirm second pass, keep first pass, and discard. Refresh and restart Backend normally, then confirm that the same task ID can continue.
- In a multi-clip run, later clips must wait for the current decision. A failed second pass should allow an explicit retry or keeping the first pass; discarding should preserve historical media and logs. MCP status and wait tools must not report a paused workflow as successful. Automated tests do not replace a real H3 generation check.

## 画布草稿瘦身 + MCP 读取工具瘦身

**画布草稿只存作用域基线**

- 打开一个节点较多的画布（例如「婚书未烬·第1集」，231 节点），改一个节点标题、拖动一个节点，然后 DevTools → Application → IndexedDB → `infinite-canvas-command-outbox`：新增命令记录里的 `base` 应只剩本次操作涉及的节点（通常 1 个），体积 **< 20 KB**（改前约 2.28 MB/条）。
- 刷新页面：**画布节点数与连线数与刷新前一致**（不能只剩 1 个节点——作用域基线绝不能被当成整图投影种子）。
- 让 MCP / 另一个窗口同时改同一节点的同一字段，再回本窗口提交：应照常弹出「冲突」提示（作用域基线与原整图快照的判定结果必须完全一致，不能漏报）。
- H3 分镜（Clip）的增删改：仍然能从本地草稿恢复、冲突提示照常（H3 细粒度 op 需要节点内 `segments` 结构，基线里原样保留）。
- 旧草稿（改版前写入的整图基线）刷新后仍能正常恢复和提交，不需要清缓存。

**MCP 返回体瘦身**

- 调 `canvas_get_state`（不带参数）：返回节点摘要（`totalNodes` 为真实节点总数，节点项不含 `metadata`），231 节点画布应在几百 KB 以内、不再报 `OUTPUT_TOO_LARGE`。
- 调 `canvas_get_state({ nodeIds: ["<某节点 id>"] })`：只回该节点的完整 metadata。
- 调 `canvas_export_snapshot`：仍返回完整画布（契约未变）；在超大画布上会返回可自助恢复的 `OUTPUT_TOO_LARGE` 错误并给出缩小范围建议。
- 调 `assets_list`：不再返回内联 base64（`coverUrl` 显示为 `[inline-media:image/png]`），`pageSize`/`page`/`keyword` 真正生效。
- **后端进程需要重启后上述 MCP 改动才生效**（backend 是 `tsx src/index.ts`，无热重载）。

**未自动执行**：`backend/src/maintenance/prune-canvas-batches.ts`（画布操作批次保留清理，实测该表 5.3 万行 / 44 MB 无 TTL）。需要时手动执行 `cd backend && npm run prune-canvas-batches -- 30`，脚本会先 `VACUUM INTO` 备份再删。

## 文本节点右键「复制内容」

- 右键**文本节点**（含文本模式的智能生成节点，例如「反推提示词配置」结果节点）：菜单应出现「复制内容」，点击后正文写入系统剪贴板并提示「已复制」，菜单自动关闭。
- 右键**非文本节点**（图片 / 视频 / 音频 / 图片模式智能节点）：菜单不应出现「复制内容」，仍只有「复制」「删除」。
- 右键**正文为空的文本节点**（未生成 / 生成失败）：同样不出现「复制内容」，避免复制出空串。
- 多结果文本节点复制的是当前主结果（`primaryTextId`）的正文；若只有单条结果则复制该条。
- 已在浏览器实测（headless Chrome + CDP，fixture 项目）：智能文本节点菜单为「复制内容 / 复制 / 删除」并复制出 331 字正文；智能图片节点与空内容智能文本节点菜单只有「复制 / 删除」；普通文本节点同样可复制正文；提示条展示「已复制」。

## 画布节点 Ctrl+C 复制修复

- 选中一张**已生成**的图片节点 Ctrl+C → Ctrl+V：应在画布中心粘贴出副本。
- 选中一张**未生成/生成失败**的图片或视频节点（无媒体内容）Ctrl+C → Ctrl+V：应能粘贴出同样结构的节点（提示词/模型配置/连线保留），不再毫无反应。
- 点击 H3 节点（焦点落入主提示词编辑器、未选中文字）后 Ctrl+C → Ctrl+V：应复制整个 H3 节点；若在编辑器里选中了文字再 Ctrl+C，仍是复制文字。
- 在浏览器 A 复制节点、浏览器/标签 B 打开同一画布 Ctrl+V：文本剪贴板里的画布 JSON 应被识别为节点复制，而不是新建一个内容为 JSON 的文字节点。
- 若系统剪贴板权限被拒：画布内 Ctrl+V 仍应可粘贴（应用内剪贴板兜底），仅在所有写入方式都失败时才弹「无法写入系统剪切板」。

## 缩小状态下「生成中」节点标记

- 触发任一生成（图片 / 智能生成 / H3 / 文本），把画布缩到节点进入概览壳（节点屏幕短边 < 100px）或紧凑壳（缩放 < 24%）：正在跑任务的节点应为活动色（浅色主题琥珀 `#d97706`、深色主题 `#fbbf24`）——底色泛橙、边框变活动色、带缩略图的节点叠一层淡橙蒙层，右上角有静态色点角标；普通节点仍是原来的灰底/灰边。
- 节点在屏幕上够宽（≥96px）时角标带进度百分比（`runProgress`），极小的节点只保留色点，不挤压成一团。
- 选中态仍显示蓝色（不被打断）；光环在低倍率下按屏幕像素补偿，缩小后依然看得见。
- 缩略壳内的标记**不应有动画**：转圈、呼吸、脉冲一律不要，缩略降级本身就是为省开销，持续重绘与之相悖。可在 DevTools 里检查 `.canvas-node-generating` 的 `animation` 为 `none`。
- 已在浏览器实测（headless Chrome + CDP，缩放 9% / 30% / 12%）：图片、智能生成、H3 三类生成中节点均出现活动色底色/边框/蒙层与静态色点角标（42% / 15%），`.canvas-node-generating` 计算样式 `animation: none`，idle 节点与普通文本节点保持原样。

## 画布资产自动归类

- 从已绑定剧目分集的画布保存文本、图片、视频或角色资产后，资产应自动归类到该剧目；从普通画布新存资产则保持未归属。
- 在剧目画布中覆盖同名角色资产时，该角色资产的剧目归属应更新为当前画布所属剧目。

## MCP 本地可观测性

- 调用直接画布、协作、浏览器兼容或动态插件 MCP 工具后，JSON 对象结果中应包含 `traceId`；调用 `mcp_observability_report` 应看到累计调用数、成功率、平均/最大耗时、按工具统计、错误码排行、恢复建议成功率和关联生成任务的当前终态。
- 对一次失败调用，把返回的 `traceId` 传给 `mcp_observability_report`，应只返回该调用的 `tool.started` 与 `tool.failed` 事件；成功调用对应 `tool.started` 与 `tool.succeeded`，生成调用还应关联 `operationId` 和 `taskId`。
- 在配置页进入「MCP 诊断」，应自动读取同一份本地累计报告；点击刷新只触发一次读取、不自动轮询。粘贴工具返回的 `traceId` 后，应展示 started/terminal 事件、工具名、耗时及脱敏后的项目、节点、任务或错误上下文。
- 诊断页应展示会话数、每会话调用量、全局及单工具 P95、每日调用趋势和“工具 × 错误代码”失败定位；有未闭合调用、低成功率、低恢复率、单工具高失败率或高尾延迟时给出对应诊断结论，健康数据则只显示健康结论。
- 每日趋势按 Backend 本地日期分组，不应在东八区午夜后仍显示前一天；“真实调用路径”应按同一 MCP 会话统计相邻工具，“异步任务结果”应按发起工具展示去重后的任务终态，任务失败热点必须独立告警，不能因提交工具本身返回成功而显示整体健康。恢复指标应分别显示建议数、下一步实际采纳数和采纳后成功数。
- 对协作、兼容和插件工具制造一次可控失败，确认返回与直接画布工具一致的 `error.code`、`currentState`、`recoverable`、`suggestedAction` 和 `traceId`；如果结果不是 JSON 文本，也应能从 MCP metadata 取得 traceId。
- 在诊断页点击「导出汇总」，确认下载的 JSON 只包含 `formatVersion`、导出时间和聚合报告（调用、会话、工具、趋势、错误、任务和诊断结论），不包含提示词正文、节点正文、媒体 URL、storageKey、base64 或单次 trace 事件。
- 在诊断页点击「载入基线」选择之前导出的汇总 JSON，确认页面只在当前浏览器内展示调用量、成功率、失败数和 P95 的变化；选择损坏或非汇总 JSON 时应提示错误，且不产生上传请求或 Backend 写入。

- 连续通过 MCP 使用同一参考节点创建两条以上图片/视频生成流，确认每条 prompt/config 节点仍与参考图同一行但沿右侧顺序展开，不互相覆盖；不带参考图时确认仍从画布最右侧开始。刷新或断线重连后再次连续创建，确认第二次调用读取到上一轮最新位置。
- 检查 SQLite 的 `mcp_observability_events`：`input_summary_json` 只应包含参数键、文本长度、引用/条目/操作数量和操作类型，不得包含提示词正文、节点正文、API Key、媒体 URL、storageKey 或 base64；数据仅保存在本机，当前版本不自动清理或上传。

## 多人实时画布：窗口排他认领与草稿找回

- Web Locks 可用时，入口先认领持久 owner，再加载原应用与 Store。普通 HTTP 无 Web Locks 时改由鉴权 Backend 维护进程内排他租约：15 秒续约，租约有效期 30 秒；正常关闭通过 keepalive 请求立即释放，崩溃、断网或请求未送达时约 30 秒后可接管。租约不写画布 JSON/SQLite、不增加 revision。
- 复制标签页即使继承同一份 sessionStorage，也会使用独立 holder；旧 owner 正被占用时自动分配新 owner。同一窗口刷新通过一次性交接 holder 继续原 owner。画布持久写入前再次确认租约；若发现已被接管则停止写入，并显示持续错误提示，不能与新窗口同时重放草稿。
