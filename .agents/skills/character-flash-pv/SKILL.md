# 人物快闪 PV

以用户指定的角色为唯一制作主体，完成角色形象、竖屏场景、两段连续视频和平台交付。每个项目使用独立画布；保留模型、提示词、参考图、任务和归档媒体之间的真实绑定，不能把临时工作台结果当作正式画布资产。

## 入口与约束

- 本 Skill 是自由画布短片流程，不建立剧目、分集或 Acheng 正式制作稿。画布持久编辑遵守仓库的画布数据契约；使用画布 MCP/受支持命令创建和编辑，不直写数据库。
- 调度纪律（标准批次、批量读写、批量等待、生成前门禁梯、恢复顺序）以 `../canvas-video-production-sop/references/native-mcp-operation-budget.md` 为准，本 Skill 只保留快闪专属参数与域内细节，不另立一套。
- 先读 `../canvas-video-production-sop/references/canvas-workspace.md` 和 `../canvas-video-production-sop/references/canvas-image-production.md` 中本次需要的小节；提交视频或恢复任务时读 `../canvas-video-production-sop/references/canvas-production-runs.md`。H3 的 Clip 参数和连续性沿用 `../canvas-video-production-sop/references/canvas-clip-production.md` 与 `.agents/rules/h3-production.md`。
- 正式画布媒体生成是有成本的动作。用户明确要求完整出片时，在本流程范围内生成角色图、场景图和两个 Clip；“帮我设计 Skill/流程/提示词”只交付设计，不触发真实生成。
- 生成前用 `models_list` 按 image 能力查模型目录，并用 `h3_list_models({view:"entries", categories:["loras"], query:"丝袜"})` 查 H3 LoRA。直接 Canvas 生成可用精确模型 ID，不要求先连接浏览器；只有依赖工作台 UI 的 `workbench_*_get_config` 才需要网页连接。“终极资产图模型”“2.1”在目录中有精确项时直接使用；无法唯一映射时，报告可用项并只询问该映射，不静默替换。
- 不修改全局模型默认值。单次项目用覆盖参数表达用户指定值；不支持的参数不得用其他含义相近的值代替。
- 自动发布时读取同目录集成的 [`social-auto-upload`](../social-auto-upload/SKILL.md) 并遵循其平台入口。先检查 `sau <平台> --help` 与账号状态；CLI 或平台专用 Skill 缺失时只按该 Skill 的安装说明补齐。用户已指定发布平台且本次要求自动发布、账号状态可用时直接执行，不重复询问授权。登录需要人工操作时保留成片与发布文案，标记该平台待登录；不得索要或保存密码、Cookie、令牌。

## 流程

### 1. 建立项目画布

1. 用 `canvas_create_project` 新建一张独立画布，标题以角色名和“快闪 PV”命名；记录真实 `projectId`，随后用它固定本会话活动画布。
2. 后续所有角色、场景、H3 节点、生成结果与最终成片都写入该画布。若创建结果未知，先按标题查询画布列表确认是否已创建，不能盲目重复创建。
3. 收集最少必要输入：角色名；用户是否提供形象参考图；若无参考图，采用随机原创设计；偏好的风格、性格/气质、场景意向和发布账号（如适用）。已有输入直接沿用，不逐项重复提问。

### 2. 设计角色并生成角色资产图

先选设计路径：

- **原创设计**：按用户描述设计角色身份、年龄观感、发型、服装、主色、辨识性配饰和整体气质。用户允许随机设计时，随机选择一套完整且自洽的方案，并先在对话中简述设计方向。
- **参考图反推**：先查看用户给的图，提取身份视觉特征、服装、配色、材质与气质；按用户要求使用当前可用的图像编辑/洗图能力形成设计参考。保留指定特征，不擅自改变角色身份。

用当前可用的“终极资产图”模型或其精确映射工作流生成正式角色资产图。用户提出的参考分工是：**图1负责头部身份与面部，图2负责身体比例、服装和整体体态**；如当前工作流需要其他输入形式，按配置映射并告知差异，不伪称模型收到未传入的参考。正式提交前用 `canvas_image_input_manifest` 核对图1/图2顺序、storageKey 与无阻断问题，并将返回的 `manifestHash` 传给生成工具，锁定本次实际输入。将真实归档输出绑定为角色资产；至少核对脸部、发型、服装轮廓、主色和配饰与设计方案一致。“终极资产图”可产出横幅式角色设定板，应作为角色身份参考，不能当作竖屏视频首帧。以任务回执的真实宽高核验输出构图，不能因请求了 9:16 就宣称实际输出也是 9:16；本轮 `2.1` 工作流请求竖幅后实际返回 2:3 竖图，后续按回执比例规划或适配，不重复请求相同比例期待其自动改变。比例不合时调整到已支持的模型尺寸或在视频消费前执行明确的裁切/适配。失败时保留已成功的输入和资产，针对失败目标恢复，不重复提交已成功任务。

角色图是场景和视频的身份锚点。角色资产图尚未成功归档前，不提交依赖它的下游生成。

### 3. 设计快闪场景并生成氛围图

围绕角色身份规划一组适合快速展示的场景与气氛节拍，例如开场剪影/登场、主体展示、收束定格。场景应有明确的色彩、光线、天气或粒子氛围，并服务角色气质；不要用无关的环境细节稀释人物主体。把场景画面提示词和氛围词分别整理，氛围词写光色、材质、运动感和情绪，不只堆泛化形容词。

通过当前配置中精确匹配用户所说“2.1”的生图模型/工作流生成竖屏场景图，并将成功结果归档、绑定到对应场景参考。生成前确认当前工作流支持的画幅；按 9:16 构图规划人物留白、视觉中心与可见轮廓。不得把角色身份图与场景图混成一个来源不明的参考。

### 4. 编排两段 H3 视频

基于角色资产图、场景图和场景节拍，使用仓库内的 [`h3-prompt-writing`](../acheng-director/modules/model/h3-prompt-writing/SKILL.md) Skill 规范视听提示，制作**两个有明确前后关系的 Clip，每段 8 秒**。用户没有另行指定镜头节奏时，默认**每秒 1 镜**，即每个 Clip 恰好 8 镜、每镜 1 秒；每次切镜落在音乐重音上，8 秒 Clip 边界也落在共同节拍线上。先确定音乐节拍，再按整秒重音编排切镜（例如 120 BPM 的 2/4 拍，每小节 1 秒、重音在小节首拍），不要后期把镜头切点与音乐重音错开。

镜头与动作组织按本目录 [`references/flash-shot-template.md`](references/flash-shot-template.md) 的**势能周期**执行：卡拍不等于有势能，每个 1 秒镜头是一个“蓄力→重音释放”周期，切点必须释放上一镜蓄满的动能，禁止等距空切；上一镜落幅蓄出下一镜起幅，Clip 1 末镜落幅跨段续接到 Clip 2 首镜。迷人/擦边尺度不预设档位，从**角色资产图**（气质、服装、丝袜等贴身元素、配饰、眼神）与**场景氛围**（光色、粒子、情绪）派生框选、慢放蓄势与近失/peekaboo 手法，末镜用带掌控感的定格收束，默认不露点且不破角色身份。每镜描述一个清晰可见动作、构图和镜头运动。最终是约 16 秒的竖屏快闪 PV。

按当前 H3 Clip 入口配置以下单次运行覆盖值：

| 参数 | 本 Skill 默认目标 |
|---|---|
| 画幅 | 9:16 |
| Clip 数 | 2，按时间线顺序排列 |
| 每段时长 | 8 秒 |
| 尺寸目标 | 2.0 MP |
| 连续性 | 开启潜空间 / Motion Context 接续，用于 Clip 1 → Clip 2 |
| LoRA | 丝袜质感，强度 0.5 |

提交前核验 H3 当前模型能接受 8 秒、9:16 和 2.0 MP 组合；用 `h3_preview_run(view:"full")` 检查每段实际生效的参数与参考映射。`h3_get_defaults` 仅用于识别当前默认值，不代表本项目已满足目标，也不要为本项目改全局默认值。精确确认 Motion Context 的有效开关及可用潜空间/音频上下文；LoRA 使用目录返回的精确 `value`，并核验提交快照中名称、启用状态和强度为丝袜质感 / 0.5。连续性只能通过前段指向后段的 Motion Context / latent 续接设置实现，不能用“有两个 Clip”推断已接续。若两个目标无法同时满足，先报告具体冲突和最接近的支持组合，不擅自降规格、替换 LoRA 或改用尾帧模式。

在画布中准备两个正式 H3 Clip，绑定真实角色/场景参考并按顺序编译、翻译、检查和生成。自由画布可用 `h3_apply_video_plan` 建段；按 Ref2VA 规范改写完整提示词后，用 `h3_update_clips` 对目标 Clip 只更新 `prompt` / `timeline` 字段，避免覆盖已保存的运行参数。生成前读取 `h3_get_clip_references` 核对最新活动图的 storageKey 与 Picture 顺序，再用 `h3_preview_run` 对**同一 nodeIds 范围**预检，并与实际提交保持一致：连续组从头运行时同时传 `runFromCurrent:true`、`skipCompleted:false`；把返回的 `planHash` 交给 `h3_run_all_clips`。若得到 `STALE_H3_PREVIEW`，该调用没有创建任务；保持原 `idempotencyKey`，按错误建议用完全相同的范围与标志重做预检，再用新 `planHash` 重提。Motion Context 要在首 Clip 登记到下一 Clip 的出边；独立预检第二 Clip 可能因缺少已完成前段 latent 而阻塞，整组从 Clip 1 预检与启动才是正确路径。

任务跟踪按[原生 MCP 操作预算](../canvas-video-production-sop/references/native-mcp-operation-budget.md)的批量等待规则执行：`canvas_wait_tasks` 一次等待全部原 taskId、事件流优先、不每分钟重复轮询，等待窗口取该文档的参考值。只有等待出错、需要人工确认或用户主动询问进度时，才用 `canvas_task_status` / `h3_get_task` 定向查看。若通过 Acheng 正式制作入口提交，遵守其翻译与编译步骤。生成后按原 taskId 跟踪状态，核对两段都已成功归档、时间线顺序、画幅、时长、实际运行参数及 Clip 1 → Clip 2 续接输入。若系统有 `ffprobe`，从归档/任务输出读取实际宽高、帧率、时长和音轨；预检尺寸只是估算，本轮 2.0 MP 的 9:16 预检得到 1088×1920 实际编码（约 2.09 MP），所以逐段报告实测值。用 scene-cut 检查或剪辑时间线复核实际切点，不能只凭提示词宣称切点符合节拍；若模型偏离整秒重音，从可用镜头动作中裁出稳定段，将每段校正为 1.0 秒，再按原音频节拍拼回，且保留原 H3 输出。若 Motion Context 续接 Clip 的 MP4 比保存时长短，且末镜已设计为定格，则保留原画布结果，另生成带末帧停留、音频垫长/淡出的准确时长交付副本后再拼接；报告交付副本长度，不覆写 H3 历史媒体。只在能力真实提供时拼接/导出最终视频；两个分段媒体存在不等于已得到连续播放的成片。

### 5. 交付与平台发布

先形成可审阅交付：最终视频（若当前流程支持拼接导出）、两段原始 Clip、角色图和场景图、所用提示词与各平台发布文案。平台包至少包括标题、简介/配文、标签、封面建议和视频文件；有平台专属格式限制时从当前平台规则或连接器读取，不凭旧经验声称符合最新限制。

若已有授权的官方/受支持发布连接，且用户明确要求自动发布：逐个平台提交内容，读取成功回执和发布链接；失败仅对该平台报告并保留可重试的发布包，不重复发布已成功的平台。四个平台分别确认：小红书、B站、抖音、视频号。只有收到平台成功回执才标记为“已发布”。

若没有发布连接或授权：交付待发布素材包，逐个平台说明当前阻塞原因和下一步；不索要或存储密码、Cookie、令牌，也不尝试模拟登录绕过平台权限。

## 验收回执

完成时用紧凑清单报告：

- 画布名称与 ID。
- 角色设计路径及角色资产的归档状态。
- 场景图与氛围设计的归档状态。
- 两个 Clip 的状态：画幅、时长、尺寸目标、Motion Context / latent 续接、LoRA 名称与强度；区分“请求参数”与“实际生效参数”。
- 最终视频是否已导出。
- 四个平台逐项列出发布状态；仅凭回执和链接标记已发布。
- 未完成项及精确阻塞原因。
