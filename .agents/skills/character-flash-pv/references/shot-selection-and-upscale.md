# 选镜与超分（H3 生成期二采与剪映后期超分）

适用：Clip 归档后的逐镜筛选和 H3 生成期二采。标准顺序为 **Clip 归档 → 选镜 → H3 二采 → 剪映草稿 → 用户导出 → 封面/发布**。若用户在已有剪映草稿上明确要求后期超分，走本文件 §2.6 的 FlashVSR+ 路径，不与 H3 二采混称。

## 为什么必须单列（2026-10-31 实测）

8 段全部 `success` / `hasResult:true`，交付时仍被用户当场追问「**镜头都没选呢，超分也没干吧**」。当时的真实状态：Clip 直接拼成人名 `master_raw.mp4`，1088×1920 原样交付，没有任何入选/剔除记录。

- 每段 5 镜里通常有一两镜不可用：解剖崩、表情死、构图废、画内冒出模型编的错字水印、一镜到底串场。整段丢进剪映，等于把筛选推给用户，还会让踩点、变速、美颜那一轮全部白做。
- 1088 宽进入剪辑会被平台再次压缩而发软；若目标是 H3 潜空间二采，必须在生成期打开，因为归档后拿不到 latent。用户明确要求对已有剪映镜头做后期超分时，改走 §2.6 的 FlashVSR+ 路线，不称作 H3 二采。

两件事都是**有真实产出的阶段**（镜头清单、二采任务与更宽的归档媒体），不是口头确认项。

## 1. 选镜

### 1.1 输入

- 每段**原始 Clip**（媒体归档或落盘原片），不是拼接副本、不是代理预览：拼接副本已经丢掉了单镜边界。
- 每段编译后的提示词（`h3_get_clip_prompt`，`view:"compiled"`）：用来比对「本该拍成什么」与「实际拍成什么」，判断是构图失败还是模型跑偏。
- 每段提示词里的 `[Shot N]` 时间码：换算成源入出点。

### 1.2 按镜切，不按段切

段是交付单位，**镜才是入选单位**。把每段 5 秒切成 5 个约 1 秒的候选；模型偏离整秒重音时按实际动作峰调整入出点，不为了凑整秒把一个完整动作劈开。切点尽量落在动作落点或遮挡处，避免入出点落在转场混合帧上。

### 1.3 先剔除，再挑选（逐镜硬性否决项）

命中任一项即整镜淘汰，不做「勉强能用」的挽留：

- **解剖**：多指、融指、缺指、断肢、脚趾翻折、关节肉瘤、脚与鞋/袜穿模（连脚丝袜高发，见 [`flash-fastpath.md`](flash-fastpath.md)）。
- **身份漂移**：脸型、瞳色、发型轮廓、服装结构在镜内突变，或与角色资产图明显不是同一人。
- **表情死亡**：整镜面无表情、眼神空洞，只有「冷艳」没有具体面部动作。
- **构图失败**：主体出画、被裁头、脸怼到糊、肢体突然从画外闯入前景、竖屏安全区里主体被截断。
- **画内文字**：模型自己编的错字、logo、水印、字幕条。
- **非设计叠影**：镜内出现没写进提示词的溶接、拖影、双重曝光（多为一镜到底残留）。
- **面部小动作崩坏**：半眨、连续抽搐、牙齿融合、嘴型对不上动作。
- **动作不成立**：支撑脚滑移、重心漂浮、道具穿模、衣服在不该动的地方跳动。

### 1.4 入选标准（按优先级排序，逐级比较）

1. 身份清晰：脸和辨识配饰在缩略图尺寸下也能认出。
2. 势能或表情强度：处在「蓄力→释放」的峰值，或稳定落幅。
3. 动作完整：有起有落，不是半截被切掉。
4. 构图可裁：竖屏安全区内能留出平台 UI 的位置。
5. 与邻镜差异：机位、景别、方向至少一维明显不同，避免连排同款。

同级打平时，取更贴合当前功能位、角色气质且动作更明确的那一镜，不一律选择情绪更外放的表演。

选完单镜后，按[整片五镜/六镜结构](flash-shot-template.md)复核整体：前 2 秒是否有核心锚点，是否建立清晰容貌与完整轮廓/空间，动态细节是否证明身份，收尾是否回到情绪。同一关键词可呼应，相邻景别/角度与动作不能整套重复；缺功能先用已有合格素材重组，不自动重跑全部 Clip。

### 1.5 产出：镜头清单

`selects/shot-list.md`（人读）与 `selects/selects.csv`（机读），字段固定：

| 字段 | 说明 |
|---|---|
| 镜号 | `c1-s3`（Clip 1 第 3 镜） |
| 整片功能位 | 视觉爆点 / 容貌侧影 / 全身空间 / 动态身份细节 / 情绪收束；实际镜头分别编号 |
| 源 Clip | 归档文件名或媒体键 |
| 源入点 / 出点 | 秒（三位小数）+ 帧号 |
| 时长 | 秒 |
| 入选理由 | 一句话，指到具体面部动作/势能/构图 |
| 剔除项 | 仅淘汰镜填，写具体硬伤 |

剪映草稿**只引用清单里的镜**。未入选镜保留在归档里（不删媒体、不删画布节点），但不进时间线。

**用户手动在剪映里删过镜之后，不再按清单恢复。** 重新对拍时以用户删减后的最新清单为准。

### 1.6 看图纪律

- 抽帧批量降采样到长边 ≤1024，做成一两张 contact sheet 一次看完；不逐张读原图。
- 关键镜（脸、手、脚）回**原分辨率 1:1** 复核，缩小图看着干净、原图糊掉或手指粘连是常见坑。
- 不新增打分表、评分卡或专门工具：清单加一句理由就够，流程工具越少越不会被跳过。

## 2. 超分

### 2.1 先认清能力边界

本节只说明 H3 的**生成期潜空间二采**（ComfyUI 节点 `NanFengH3LowPeakLatentUpscalerV15`，内部调用 `H3LatentUpscalerNodeMegapixels`），需要一采的 latent 才能继续。已剪映的成片后期超分是独立路径，见 §2.6。

因此：

- **不能对已归档的 mp4 补做二采**。已经出片、没开二采的素材，只能说「无 latent，不可补做」。
- 对旧素材，H3 二采只能用同 prompt / 同 seed 重跑并开启二采；若用户明确要求对已有剪映镜头后期超分，按 §2.6 使用 FlashVSR+ Turbo 2×，并标注「后期超分，非 H3 二采」。
- 交付说明里不得把 1088 宽的文件说成「已超分」。

### 2.2 两条入口

- **A. 生成前规划**：提交时 `latentUpscaleEnabled:true`，一采 2MP、二采放大，一次跑完。适合已知要交付高清、段数多且不需要逐镜取舍的项目。
- **B. 一采确认模式（本 Skill 推荐）**：`latentUpscaleEnabled:true` + `latentUpscaleConfirmationMode:true`。一采完成后 Clip 停在 `awaiting_confirmation` 并**保留一采 latent**，这时正好拿一采成片做选镜；只对通过选镜的段「确认一采并继续二采」，剔除段「保留一采」或「放弃任务」。

B 把「选镜」和「超分」接成一条链，且不白烧二采算力，是默认路径。逐段确认，先确认已入选的段；二采在后台顺序跑，前台继续准备剪映侧工作。

### 2.3 参数面（面板名 / 参数键 / 默认值）

| 面板 | 参数键 | 默认 | 说明 |
|---|---|---|---|
| 启用潜空间二采 | `latentUpscaleEnabled` | `false` | 打开后 `steps` 不再单独生效 |
| 一采确认模式 | `latentUpscaleConfirmationMode` | `false` | 一采后暂停等人工确认，保留 latent |
| 一采步数 | `h3FirstSteps` | `6` | 与二采步数相加为总步数 |
| 二采步数 | `h3SecondSteps` | `4` | 放大后再采样步数 |
| 放大模型 | `latentUpscaleModel` | 空 | 必须出现在 `NanFengH3LowPeakLatentUpscalerV15` 的 `model_name` 候选里 |
| 目标百万像素 | `latentUpscaleMegapixels` | `1` | 档位来自 NanFeng 节点「百万像素」+ 标准档合并，实际以面板为准 |
| 潜空间对齐 | `latentUpscaleAlign` | `2` | 2 / 4 / 8 / 16 / 32 |
| 潜空间精度 | `latentUpscalePrecision` | `bf16` | `fp16` / `bf16` / `fp32` |

- 开启二采时后端把总步数算成 `h3FirstSteps + h3SecondSteps`，并在 `h3FirstSteps` 处切 sigma：一采出低分辨率结果，交给放大节点，再用剩余步数去噪。所以调「steps」不会影响二采段，必须改这两个键。
- **预检在前**：后端 `assertH3LatentUpscalerReady` 会先查 ComfyUI 是否装了 `H3LatentUpscalerNodeMegapixels`、所选模型是否在候选列表里；缺任一项在**一采开始前**就报错，不会白跑一采。报「缺少节点」时先装节点并重刷模型列表，不要关掉二采硬跑。
- **互斥**：V15 潜空间续写（continuation）与潜空间放大二采不能同开，同开会被后端直接拒绝。本 Skill 默认关闭跨段续写，不受影响；需要跨段连续镜头的项目就别开二采。
- 二采确认**之前**不执行 RTX、人脸精修与 DLSS 等后处理；确认之后可以再追加人脸精修。

### 2.4 目标分辨率

- 一采参考：`9:16 + 2.0 MP` → `1088×1920`（约 2.09 MP）。
- 二采按目标百万像素重算，例如 4 MP 量级约 `1504×2656`；实际宽高以 `h3VideoDimensions` 的 16/32 对齐结果与归档回执为准，不用手算值当结论。
- **平台不需要 4K，但别交 1088 宽**：竖屏平台会再压一次，1088 宽在手机上发软。二采到约 1440 宽以上再进剪映。
- 若面板「目标百万像素」最大只到 2 MP，说明后端没上报 NanFeng 档位（`h3_list_models` 的 `nanfeng` 字段为空或被过滤）：此时二采等于原地重采样，**不要宣称提高了分辨率**，先修模型目录发现再重跑。

### 2.5 算力与失败处理

- **先选镜再超分**：只对入选镜开二采，剔除镜不开。
- 二采按批提交、后台顺序运行；不让「等超分」阻塞剪映草稿准备。
- 任一段二采失败：保留一采版本继续后续剪辑，不重复提交已成功段；失败段按需重试或降一档目标百万像素。
- 每段完成后按实际归档媒体（`media_files` 或 ffprobe）记录宽高、帧率、时长，不拿预检期望值当结果。

## 2.6 已有剪映镜头的后期超分（FlashVSR+ Turbo 2×）

这是独立于 H3 latent 二采的后期路径。快闪 PV 已选镜头后期放大默认使用 **FlashVSR+ Turbo、scale=2**；当次任务另有指定时以当次值为准。

- **输入源**：若目标是当前剪映时间线中的已选镜头，处理时间线实际引用的原始 H3 源片（只处理唯一源文件，不处理未入选候选）；若目标是最终合成画面，则使用用户从剪映导出的全分辨率成片。540×960 CLI 代理不含剪映原生滤镜与动态水印，不能作为正式超分输入。
- **回链方式**：对原始源片超分后，逐个映射到当前草稿中引用它的 Segment，使用 `capcut replace-media <project> <segment-id> <new-file>` 回链，不传 `--retime`，保留现有 segmentId、源范围、变速、镜头顺序、BGM、滤镜与水印；写后逐项读回核对。
- **提交方式**：经 `pi-comfyui-paint` 的 `flashvsr_plus_upscale` adapter 顺序提交，明确传 `--mode turbo --scale 2__。先跑一个已选源片，用 ffprobe 核对输出宽高恰为源宽高的 2 倍、帧率与音轨保留；通过后再顺序处理其他唯一源片。已有成功输出不得重复提交或覆盖。
- **成片边界**：超分源片不等于最终成片；最终剪辑仍保留在剪映草稿中，用户从剪映导出，并在导出设置里选择当前时间线分辨率的 2×。若输入是最终合成文件，则对该文件另存超分副本，不覆盖原片。不得把代理预览、H3 latent 二采或剪映导出分辨率混为一谈。
## 3. 进剪映前的最小门禁

- [ ] `selects/shot-list.md` 存在，每个入选镜都有源 Clip、入出点、入选理由。
- [ ] 每个入选镜的实际分辨率、帧率、时长已实测（不是请求值）。
- [ ] 超分是否执行、走哪条路径（H3 二采 / FlashVSR+ 后期 / 未做）、输入源、档位与实际输出宽高已记录。
- [ ] 剪映草稿只引用入选镜；未入选镜没有混进时间线。
- [ ] 交付口径已分档：`Clip 已归档` / `草稿就绪（待用户导出）` / `成片已导出`，且只对第三档说「成片」。

## 4. 自检

交付前问三句：

1. 现在拿着镜头清单，能逐条指到源 Clip 和入出点吗？答不上来就是没选。
2. 入选镜的实际宽度是多少？说 1088 就是没超分，说 1440 以上要能指到归档文件。
3. 如果没超分，交付说明里写清楚原因了吗？没写就是在拿低分辨率当成品交。
