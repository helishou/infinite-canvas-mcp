# H3 编排、提交与恢复

进入 H3 阶段时读取，并读取主入口指定的 H3 提示词和生产操作规则。

### 4. 编排 5 秒 H3 片段

基于角色资产图、场景图和场景节拍，使用仓库内的 [`h3-prompt-writing`](../../acheng-director/modules/model/h3-prompt-writing/SKILL.md) Skill 规范视听提示。**每个 Clip 固定 5 秒；默认 8 个 Clip，共 40 秒。** 用户指定其他总时长时，段数 = 总时长 ÷ 5；仅当明确指定生成总时长且不是 5 的整数倍时询问，不静默取整；成片目标时长由选镜剪辑实现，不据此改写生成预算。用户指定镜头数时严格保留；未指定时默认每秒 1 镜，即每 Clip 5 镜、每镜 1 秒。时间码必须完整覆盖 0–5 秒，每次切镜落在音乐重音上；先按镜头模板 §0.4–0.7 确定整片功能、记忆锚点和音乐节奏；源素材的整秒时间码只作候选规划，最终按实际重音与动作峰剪辑，不把 BPM 当作已验证的强拍位置。**每镜之间必须是硬切**：`[Shot N]` 只是文本分段标记，不是切镜指令；每个后续镜以 `hard cut to` 开头，并让机位/焦段与被摄状态同时跳变，不能用 `then`、`meanwhile` 或连续运镜串场——否则 H3 会把 5 镜合成一个一镜到底的长镜头（2026-10-31 实测故障，修法见 [`flash-shot-template.md`](flash-shot-template.md) 的 3.3）。

镜头与动作组织按本目录 [`flash-shot-template.md`](flash-shot-template.md) 的**势能周期**执行：卡拍不等于有势能，每镜是一个“蓄力→重音释放”周期，切点释放上一镜蓄满的动能，禁止等距空切。该文件第 0 节列出用户的七条固化要求（5 秒 / 5 镜 / 性擦边 / 多机位多角度 / 贴合角色 / 每镜微表情 / 默认 8 段且段间尽量不同），写提示词前先读；0.1 是机位库，**同一 Clip 内 5 镜的「高度 × 角度 × 运动」三元组不得重复；默认 8 段之间在大机位、场景氛围、动作主线、景别序列、框选焦点上至少 3 维不同**（按实际 N 段执行差异化检查）。3.1 是微表情规则：只写“冷艳”“目光锁定镜头”会得到五张一样的面无表情脸，用户会判为面瘫并要求重做；有脸镜给一个符合幅度规则的具体面部动作，无脸镜用材质与动作承载变化（嘴角单侧上扬、瞳孔收缩、眉峰下压一瞬、鼻息、喉头动、咬唇、眼尾上挑、慢眨一次），并连成一条递进走向线。每段必须独立成立：开场直接建立完整姿态与场景状态，结尾收在稳定落幅；不得依赖上一段的未完成动作、尾帧或 latent。默认关闭 Motion Context、AV latent 与 tail-frame continuation；仅在用户本轮明确要求跨段连续动作/同一连续摄影镜头时，才按需要开启相应机制。迷人/擦边尺度不预设档位，从**角色资产图**（气质、服装、丝袜等贴身元素、配饰、眼神）与**场景氛围**（光色、粒子、情绪）派生框选、慢放蓄势与近失/peekaboo 手法，末镜用带掌控感的定格收束，默认不露点且不破角色身份。每镜描述一个清晰可见动作、构图和镜头运动。

姿势规划优先检索 [`flash-shot-template.md` §2.1](flash-shot-template.md) 所述的画布在线姿势资产库，并采用用户偏好的胸前/上身、腿部、臀腿轮廓构图，减少无叙事作用的手部特写。完成全部 N 段镜头后必须执行该模板 §0.3 的整体去重检查；检查未通过时先修改镜头和姿势分配，不得提交媒体生成。

按当前 H3 Clip 入口配置以下单次运行覆盖值：

| 参数 | 本 Skill 默认目标 |
|---|---|
| 画幅 | `9:16 (Portrait Widescreen)`（统一使用完整标签） |
| Clip 数 | 默认 8（共 40 秒）；用户指定其他总时长时 N = 总时长 ÷ 5，不是整数时先询问 |
| 每段时长 | 固定 5 秒 |
| 尺寸目标 | 2.0 MP |
| 连续性 | 独立生成；默认关闭 Motion Context、AV latent 与 tail-frame continuation |
| LoRA | 丝袜质感，强度 0.5 |

提交前核验 H3 当前模型能接受 5 秒、9:16 和 2.0 MP 组合；用 `h3_preview_run(view:"full")` 检查每段实际生效的参数与参考映射。`h3_get_defaults` 仅用于识别当前默认值，不代表本项目已满足目标，也不要为本项目改全局默认值。每段必须保存为独立生成，不得因共享角色或场景参考而推断需要跨段续接。若目标参数组合不受支持，先报告具体冲突和最接近的支持组合，不擅自降规格、替换 LoRA 或开启上下文模式。

**2.0 MP 是快闪的强制项目参数，不得继承 H3 的全局默认值（当前可能是 0.4 MP）。** 每次正式提交必须显式设置 `megapixels: 2`，并为 8 个 Clip 全部核对 `h3_preview_run` 的 `effectiveRuntime.megapixels` 与 `expectedDimensions.final`。若 Clip 保存值与 2.0 不一致，先逐 Clip 保存覆盖参数再预检；预检仍显示 0.4、参数不匹配或输出尺寸不支持时，停止生成并报告，不得用默认值继续或静默降档。归档后还要逐段实测宽高；参数请求为 2.0 MP 不等于实际输出已达到目标。

在画布中准备 N 个正式 H3 Clip（默认 8 个），绑定真实角色/场景参考并按顺序编译、翻译、检查和生成。自由画布可用 `h3_apply_video_plan` 建段；按 Ref2VA 规范改写完整提示词后，用 `h3_update_clips` 对目标 Clip 只更新 `prompt` / `timeline` 字段，避免覆盖已保存的运行参数。提交前把状态读取一次拿全：`h3_get_clip_references`（活动图 storageKey 与 Picture 顺序）与 `h3_get_clip`（已保存的运行参数）在同一阶段读完；随后用 `h3_preview_run` 对**同一 nodeIds 范围**预检，并与实际提交保持一致，独立片段统一 `skipCompleted:false`，把返回的 `planHash` 交给 `h3_run_all_clips`。若得到 `STALE_H3_PREVIEW`，先按错误回执核实是否创建任务，并核对预检与提交的节点范围、起止段、skipCompleted 和覆盖参数。目标输入改变时刷新相同范围的预检，沿用原幂等键及新 hash 提交；输入未变仍失败时报告工具问题，保留计划，不省略 `expectedPlanHash` 绕过。传输超时先查原任务，不盲目重提。

画幅统一使用完整标签 `9:16 (Portrait Widescreen)`，当前入口也支持裸比例归一化；不得把旧版本的横屏回退当作当前行为。预检只读，运行覆盖值与保存值须在回执中核对，不因预检正确就宣称已写入。

提交后必须**两处对齐才算成**：预检返回的 `expectedDimensions.final`，与实际归档媒体的宽高（`media_files` 的 width/height，或 ffprobe 实测）都是竖屏。只有预检对、归档不对，说明写盘没传到运行侧；只有归档对、Clip 保存值不对，下次从 UI 运行还会翻车。发现横屏不要靠后期裁切补救，按上面两条重设后重跑。

**参考绑定写在段落里**：`h3_apply_video_plan` 的每个 segment 可用 `references:[{nodeId,role,order,storageKey,name,type,subjectId}]`（role 取 `character_identity` / `character_turnaround` / `scene` 等，order 从 0 递增，storageKey 是已归档媒体键），配合 `subjects:[{subjectId,name,role}]`。写完用预检的 `clips[].referenceMap.length` 核验，为 0 说明没绑上，别提交。

**段落已有运行状态时改计划会被拒**：`h3_apply_video_plan` 会报「字段 status 由后台任务维护」。先查询并等待原任务；确需废弃本项目任务且在授权范围内时才取消。不要为改计划自动取消在途生成，也不要重新提交已有任务。各片段不得登记跨段 latent/tail-frame 出边；其提示词须自足，不依赖其他 Clip 的状态。

任务跟踪按[原生 MCP 操作预算](../../canvas-video-production-sop/references/native-mcp-operation-budget.md)的批量等待规则执行：`canvas_wait_tasks` 一次等待全部原 taskId、事件流优先、不每分钟重复轮询，等待窗口取该文档的参考值。只有等待出错、需要人工确认或用户主动询问进度时，才用 `canvas_task_status` / `h3_get_task` 定向查看。若通过 Acheng 正式制作入口提交，遵守其翻译与编译步骤。生成后按原 taskId 跟踪状态，核对 N 段（默认 8 段）都已成功归档、时间线顺序、画幅、每段 5 秒时长、实际运行参数及段间独立性。若系统有 `ffprobe`，从归档/任务输出读取实际宽高、帧率、时长和音轨；预检尺寸只是估算（2026-10-28 实测：2.0 MP 的 9:16 预检对应 1088×1920 编码，约 2.09 MP，以当次回执为准），所以逐段报告实测值。用 scene-cut 检查或剪辑时间线复核实际切点，不能只凭提示词宣称切点符合节拍；若模型偏离整秒重音，从可用镜头动作中裁出稳定段，按实际动作峰与音乐重音确定入出点，在剪映中依剪辑规则调整，不为凑 1 秒截断完整动作，且保留原 H3 输出。若任一 Clip 的 MP4 比保存时长短，且末镜已设计为定格，则保留原画布结果，另生成带末帧停留、音频垫长/淡出的准确时长交付副本后再拼接；报告交付副本长度，不覆写 H3 历史媒体。拼接只能产生中间校验副本或代理预览（核对帧数、切点、总时长、响度）；**最终成片必须落成剪映草稿并由用户导出**——所有分段媒体存在、或 ffmpeg 已能连续播放，都不等于已得到成片。
