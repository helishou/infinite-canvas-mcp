# 剪映成片踩点重音剪辑（JianYing 5.9 草稿）

适用：Clip 导出/拼接后在剪映做快闪踩点重音成片，或对已有剪映草稿对齐重音、加淡出。CLI、draft schema、编辑器生命周期见 Hermes 侧 `capcut-edit` skill。

## 用户硬规则（违反会被当场纠正）

1. **素材内容一帧都不裁**——时长压力全部靠变速解决。
2. 变速范围克制：**加速上限 ~1.45×**（≥2× 被明确否决为"太多"）；氛围镜（行走/特写）可轻度慢速 0.65–0.9×；**高潮镜不许慢速蓄力**（慢速蓄力被否决），高潮用正常速收刀落在最强锤上。
3. **同一镜头不许在连续动作中被拆成不同速度的两段**——会被看成"同一个动作重复了两遍"。同镜跨拍要么整段一速（拍点在镜内不切），要么只在锤点做 ±0.2 内的轻 ramp。
4. **切点必须落在明显重音上**（spectral-flux 强度 ≥400 量级），弱前奏轻点不切；长镜跨过强锤会被质问。
5. **镜头长短按鼓点间隔分配**：密集连拍给短切片/快切镜（手部、双足等细节镜），宽间隔给主镜。开场放定场长镜，细节特写放中段快切位。
6. 用户手动改过草稿后：**顺序绝对不动**，只移动时间线边界+调速来吸附重音；用户手设 1.0× 的段会把相邻切点锁死，动之前先问。改坏了用 `draft_content.json.bak` 还原。
7. 音乐默认采用**重音＋短余韵**：末镜切入落在清晰重音，保留短暂冲击，再让短混响或回声淡出；根据实际音乐与画面调整长度，不把单纯全曲渐弱当作默认。用户指定其他收尾时从其要求。
8. **成片只能在剪映里生成**：Clip 归档后必须落成剪映草稿，由用户在剪映手动导出；ffmpeg 直接 concat 出的 mp4 是代理预览，不算成片（见下节）。

## 不许用 ffmpeg 直出冒充成片（2026-10-31 实测）

**故障**：8 段 H3 Clip 全部归档后，跳过剪映，用 ffmpeg 把 8 段 concat、加 `eq` 调色 + softlight 柔光、`drawtext` 浮动水印、`loudnorm` 归一，产出一条 40 秒 mp4，并按「成片」写进交付说明。用户反应是：「你在逗我，咋就跳过剪映剪辑了呢？？？」——片子本身能播，但交付路径错了：没有草稿，没有变速、没有剪映调色美颜预设、没有剪映原生水印轨道，用户无法继续接手调整。

**根因**：把「有连续播放的 mp4」当成了「成片」。ffmpeg 能做的事只覆盖剪映工作流的一小部分（拼接、滤镜近似、写死水印），漏掉的是用户真正要编辑的东西：可改的草稿、可调的变速与重音切点、可保存的美颜与滤镜预设、可拖动的水印关键帧。

**规则**：

- **交付分三档**，不许混称：`Clip 已归档` → `草稿就绪（待用户导出）` → `成片已导出（用户导出文件路径）`。只有第三档能说成片。
- **ffmpeg 合法用途白名单**：从**剪映导出的成片**抽帧做封面与封面比例裁切、核验帧数/切点/宽高/响度、生成代理预览、验证穿帮补丁覆盖、音频响度测量。白名单之外不得用 ffmpeg 产出交付文件。
- **必须存在的东西**：草稿目录与草稿名、视频/音频/文字/滤镜/特效轨道结构、水印 `global_alpha` 与首末关键帧、每段变速值、调色与美颜预设数值、BGM 轨道。缺任一项即「草稿未就绪」。
- **例外只有一条**：用户当次明确说「不用剪映、直接给我 mp4」。此时可以直出，但交付说明必须写明「直出版，未经剪映」，并且不把该文件当作可继续编辑的成片。
- **不得用 ffmpeg 的近似效果代替剪映验收**：`eq`/`colorbalance` 近似柔光、`drawtext` 近似浮动水印、`loudnorm` 近似剪映音量，都只能用于看片，不能写进验收回执当作「调色/水印已生效」。

**自检**：交付前问自己一句——「用户现在打开剪映，能在项目列表里看到这条草稿并继续改吗？」答不上来就是没做完。

## 前置：先有镜头清单和超分结论

生成期 H3 二采的标准顺序为 **Clip 归档 → 选镜 → H3 二采 → 剪映草稿 → 用户导出 → 封面/发布**。若用户在已有剪映草稿上明确要求 FlashVSR+ 后期超分，则按 [`shot-selection-and-upscale.md`](shot-selection-and-upscale.md) §2.6 处理当前时间线实际引用的源片，保留草稿镜头与剪辑关系；不得用 540p 代理替代正式源。草稿只引用 `selects/shot-list.md` 里的入选镜，不把整段 5 秒原样丢上时间线。本文件第 3 步所说的「用户删减后最新镜头清单」就是这份清单的更新版，不是另起一份。

## 流程

1. 修改快闪草稿前核对目标与最新落盘内容，并备份草稿。用户已授权：剪映仍在运行时，自行关闭对应剪映进程（`Stop-Process -Name JianYingPro`），不再要求用户手动退出或重复确认；等待进程确实退出，关闭后重读草稿，以最终落盘内容为修改基线。若仍有进程占用或落盘发生冲突，先定位原因，不用 `--force-write` 绕过。完成修改和回读验证后，从实际存在的程序路径正常显示剪映窗口，不用隐藏窗口启动用户需要操作的编辑器；快捷方式失效时核实实际程序路径再修正。此授权仅适用于本流程的剪映草稿编辑，不扩展到其他应用或服务。
2. 重音检测：BGM 转 wav → numpy 谱通量（frame 1024/hop 256、Hanning、[1,2,3,2,1] 平滑、24 帧移动均值 +0.35 delta 阈值），取局部峰、强度 ≥400 为"必须切"的重音，边界吸附到 30fps 网格 `round(t*30)/30`。
3. 对每段：优先在原边界附近吸附重音，保持单调且满足整镜速度范围；逐点最近邻无法同时满足时，联合分配各镜时长，不能硬凑整秒或仅按提示词切镜。`speed = srcDur/tgtDur` 同步写入段与引用的 speed material（`curve_speed: null`），不能只写段字段。重新对拍使用用户删减后最新镜头清单和当前 BGM 的实际源起点，不恢复已删除镜头，不替换用户选曲。确认用户手设的 1.0× 与从生成模板继承的 1.0×，不要把所有默认 1.0× 都误判成用户锁定。
4. 帧边界和预览：按实测源帧率确定整数帧区间 `[startFrame,endFrame)`。微秒时间码的四舍五入仍可能略早于准确帧边界；出现上一镜尾帧闪回时，不要只重复写相同小数时间。可将当前已选镜头无损编码为独立无声副本，用 `trim=start_frame=...:end_frame=...,setpts=PTS-STARTPTS` 精确选帧，草稿改用从 0 开始的副本并保留原时间线位置；保留原片，不扩大或截去用户选定内容。核对副本帧数、解码像素以及每镜首两帧/末两帧，确认没有邻镜画面。代理预览逐段核对目标帧数，再检查切点与音乐重音；JSON、编译成功或近似预览不能替代剪映实际消费验证，不能把可见的错误帧一概归为转采样噪声。
5. 收尾默认先找末镜重音并保留其冲击，随后加入短余韵并淡出；先试听、核对画面与音乐，不能未分离音轨就声称独立去掉鼓点或只留下旋律。处理后音频另存，保留原曲以便恢复，避免原音轨和处理音轨叠响；用户指定其他音乐收尾时，以当次要求为准。
6. 以最终画面结尾收齐 BGM、全片滤镜和水印长度，保留短余韵，不让整首音乐在画面结束后留下长段黑屏；缩短全片时同步缩放水印关键帧时间，保留已选轨迹。重开剪映，让用户手动导出（用户偏好手动导出，CLI render 只出代理预览，不可用于正式成片）。导出前在剪映页面核对浮动水印的透明度与漂移，导出后从成片抽帧做封面。

## 原视频声音与剪辑 BGM

- “去掉原视频的声音”指 H3 素材自带音轨，不代表删除、静音或替换用户选好的独立 BGM。分别列出视频内嵌音轨与独立音乐轨道，再按职责处理；用户未要求全片无声时不得移除 BGM。
- 先将视频段音量设为 0；若实际播放仍有原声，另存只保留视频流的无声副本（`-map 0:v:0 -c:v copy -an`），替换相应视频素材并保留原始文件。用 ffprobe 验证所有实际消费的视频副本均无音频流；镜头范围、顺序、速度、效果和独立 BGM 保持不变。
- 每次后续编辑都保留当前 BGM 音轨和用户调整。只对用户授权的配乐收尾另存处理音频，不能把旧项目预览音乐重新盖回来，也不能叠放原曲与处理副本。

## 草稿与素材登记

- 读取当前实际消费的时间线及镜像文件；编辑器退出后重读，权威新稿为基线。不要用旧备份整稿覆盖用户后来删镜、调速、换曲等调整。
- 复用模板创建新草稿时，先确认工具是否保留模板原轨道；移除误带的模板视频、音乐或重复水印，只保留本片实际需要的轨道和效果。
- 新素材要登记到本草稿并正确关联 `local_material_id`；优先在现有草稿中更新，不为每次修复再登记一份项目。路径比较须规范化大小写、分隔符和绝对路径，同一 draft ID 与同一实际目录只能保留一条首页记录。
- 发现重复草稿时先区分列表重复与不同目录的真实副本。仅有相同 ID、相同规范化路径的重复记录可备份后合并；保持草稿内容哈希不变，不删用户草稿或媒体。

## 重音转场试版

- 用户授权尝试转场时，先保留当前硬切版备份，在少量适合的重音切点试加短转场；不要默认每镜都上特效。按相邻镜头的运动方向、景别和构图选择推移、吸入、轻震或闪光/闪黑，避免无关花哨模板和连续闪烁遮挡人物。
- 切点和总时长保持已对齐结果，优先约 4–8 个输出帧的短效果，实际长度应小于相邻镜头且不能盖住动作主体。原生转场只引用真实目录项和可用资源，核实是否已缓存、是否需会员；不伪造资源 ID，不把近似 FFmpeg 效果称为原生渲染。
- 正常的有意转场混合帧与错误残留尾帧分开检查。逐个检查转场前后，确认不引入邻镜外画面、不改变 BGM、不偏离重音；保留必要的硬切作为节奏对比。原生界面或导出效果未看见时，只报告已写入的名称、位置与时长，不能宣称视觉验收通过。

## 浮动水印（每条快闪片默认加）

**规格固定**：文字「热王小鸟鸟」，半透明，慢速飘动，覆盖全片。

- **透明度**：默认不透明度约 15%，按背景明暗微调，不能抢主体或挡脸。剪映原生文字面板的不透明度使用 `materials.texts[].global_alpha`（15% 对应 `0.15`）；仅修改 `text_alpha` 或段级 `clip.alpha` 不足以控制该滑块，段级值还可能在打开后被重置为 1。以已有原生草稿结构为依据，普通文字整体透明度使用 `global_alpha`，`text_alpha` 与 `clip.alpha` 保持原生默认 1，避免重复叠乘。修改后须在剪映打开并保存后再读回 `global_alpha`，并核对面板与实际画面；不能只凭打开前的文件值宣称生效。亮背景需要阴影/描边时保持低透明度，不出现实心白块。
- **随机轨迹**：每次制作新的快闪剪辑时重新随机生成水印轨迹，起点、终点、方向、中间路径及横竖移动范围均不固定；不要套用固定左上→右下、固定往返或首尾回到原点的模板。横向与竖向都应有正常播放可辨的较大位移，不再使用仅在小角落轻微晃动的范围；按当片安全区选点，不机械套用固定百分比。随机结果保存为草稿关键帧，同一草稿播放与导出保持一致；重开草稿或修改其他内容时不重新抽取，用户要求重随机时才替换已有轨迹。
- **漂移速度**：同时设置位置关键帧 `KFTypePositionX` / `KFTypePositionY`，`curveType:"Line"`，不加缓动、弹性、旋转和缩放。随机的是路径，不是逐帧抖动或忽快忽慢；按相邻点实际距离分配时间，保持缓慢、近似恒定的移动速度，不要求关键帧等时距，不强制折返。整条路径保持文字完整在画内，并按安全区避让主体。
- **全片覆盖**：一条**独立文字轨道**，从 0 覆盖到成片末尾（含淡出段），不逐镜复制、不挂在字幕轨上（字幕轨会被自动识别/模板改写）。文字段 `render_index` 高于视频段，不被滤镜或遮罩轨道盖住。
- **短片持续运动**：首末位置关键帧放在文字段的首尾；短于一个漂移周期时保持单程匀速，不在镜内停顿或折返。不能仅凭存在关键帧就宣称浮动完成；须检查开头、中间、结尾位置持续变化，位移应在正常播放下可辨，并以剪映实际播放或原生导出样片验收。
- **安全区**：避开右下角平台文案与进度、右侧点赞/评论按钮列、顶部标题区；不压眼睛和嘴。默认在画面上部或左下的空白区域飘动，人物主体居中时优先上部。
- **实现要点**：文字素材字段是 `materials.texts[]`（`content` 是 JSON 字符串，含 `text` 与 `styles[].size`），段级位置动画走 `segments[].common_keyframes[{property_type, keyframe_list:[{time_offset, values, curveType}]}]`，坐标是半画布单位 `[-1,1]`。`time_offset` 相对段起点还是绝对时间线，先在样片上用小段核对，不靠猜；写完回读确认关键帧覆盖整段而不是被夹在首尾。
- **只在剪辑层加**：水印不写进 H3 提示词，也不让视频模型“生成文字水印”。模型会把中文字画歪、还会随镜头一起运动，且无法控制透明度与周期；H3 侧继续保留“不要字幕/文字/水印”的约束。
- **已有水印不叠加**：草稿里已有同文案水印时按用户当次要求处理，不重复加第二层。
- **验收**：文件回读只能证明字段写入。必须在剪映实际页面看透明度与飘动，再导出 2–3 秒样片抽帧对比两三个时间点的位置，确认“慢、淡、一直在动且不挡脸”。代理预览不能复现的差异如实说明。

## 穿帮打码（纯 CLI 方案）

剪映"局部马赛克"资源本机没缓存时，用已缓存的「模糊」场景特效（resource_id `6739752823140913675`，effect_id `634025`，在 `Cache/effect/634025`）代替：
1. `capcut duplicate <proj> <seg> --new-track` 复制穿帮段到上层轨道；
2. JSON 把复制段 `source_timerange` 裁到穿帮窗口（整数源帧）、`target_timerange` 按原速度换算回时间线位置；
3. `capcut mask <proj> <dup> rectangle --center-x --center-y --size --rect-width --round-corner 60 --feather 25`（坐标是半画布单位 [-1,1]：`x/画布宽*2-1`；size 为画布高占比）；重设要先 `--off` 再 apply（同段只允许一个 mask）；
4. `capcut add-effect "模糊" <start> <dur> --bind <dup> --resource-id ...` 实际会建独立特效轨道——要段级贴法：删掉它建的 effect track 段，把返回的 material id 直接 append 进复制段的 `extra_material_refs`（material 存在 `materials.video_effects`，段级引用即剪映的段效果）。
5. 遮罩范围宁大勿小：以检测框外扩 30–80px；用 ffmpeg boxblur 近似渲预览验证覆盖，逐帧像素差证明补丁每帧生效。

## BGM 选择（用户授权自己找）

- 找**重音密度高的 remix 版**。基线参考：客官不可以 remix `cbed8462…mp3`，15.3s，~94BPM 双拍，重音间隔 0.63s，top 锤强度 566。判定：谱通量重音 ≥400 的个数 ≥ 每 1.5s 一个才算"够炸"。
- 剪映音乐库定位法：`key_value.json` 的 searchKeyword/materialName → `downLoadcfg` → `Cache/music/<hash>.mp3` → faster-whisper 转首 45s 对歌词。候选不足时用本地 chatgpt2api 搜"歌名 remix 高潮版"，让用户先导入到剪映音乐库再取缓存文件。
- BGM 从爆点段起播（前奏弱铺垫段不要），整曲铺满时长优先于切尾；切尾只用作压缩总长的最后手段。

## 封面：从成片里取全片最强高光帧

用户 2026-10-29 明确否决“无脑截首帧”：**封面必须是全片最有冲击力的那一帧**，不是第一帧，也不是平台自动截的那张。

1. **候选来源**：复用本文件流程第 2 步的谱通量结果，取强度最高的 3–5 个锤点（≥400，含末镜落幅锤）。只在锤点 ±0.2 秒内抽帧，每 1/30 秒一张，单锤点上限 13 张。
2. **从最终成片抽**：用导出的成片（已含调色、美颜、水印），`ffmpeg -ss <t> -i final.mp4 -frames:v 1` 精确抽帧；不要用原始 Clip 或调色前帧冒充，否则封面与视频不一致。
3. **先剔除**：转场混合帧（前后镜叠影）、运动模糊、闭眼或半眨、嘴型过渡帧、字幕/贴纸压脸、水印压脸、主体出画、构图不完整。剔除后仍有候选才进入挑选。
4. **排序标准**：身份清晰（脸和辨识配饰可读）> 势能/表情强度（重音释放瞬间或稳定落幅）> 缩略图尺寸下主体可辨 > 与标题文案匹配。末镜定格若姿态最强可优先，但不是默认答案。
5. **看图纪律**：候选批量降采样到长边 ≤1024 一次看完，不逐张读原图；选定后回**原分辨率 1:1** 复核清晰度和噪点，缩小图看着清楚、原图糊掉是常见坑。
6. **按平台裁切**：抖音/视频号默认 3:4（1080×1440，另可给 4:3 1440×1080）；B站、小红书按当次 `--thumbnail` 要求，至少短边 ≥720。居中裁切，脸放在平台 UI 不遮挡的安全区（避开右下角文案、右侧按钮列）。
7. **落盘命名**：`cover_<平台>_<比例>.jpg`，与成片同目录。交付时报告选中时间点、锤点强度、对应镜号与文件路径，并注明“未使用首帧”。
8. **没有可用高光帧时**（全片都在糊、都在转场、脸一直被挡）先问用户选哪一镜，不静默回退首帧，也不让平台自动截取。
