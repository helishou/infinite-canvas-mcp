# 通用经典运镜 · 白膜参考视频库

一套可复用的**镜头运动参照素材**，用于讲戏、对齐运镜意图、做 previs 参考。
每个运镜一段独立 MP4，白膜只作镜头运动参照物，不代表最终成片的人物外观。

## 规格

| 项 | 值 |
|---|---|
| 分辨率 | 1920 × 1080 |
| 帧率 | 24 fps |
| 时长 | 4.0 秒 / 段（96 帧） |
| 编码 | H.264 / MP4 |
| 片段数 | **132**（120 段人物固定 + 12 段带主体位移） |
| 场景 | 棋盘格地面(2m 格) + 环形参考柱 + 近景立柱 + 主角白膜 |
| 主角 | `liu_whitebox_male_default.fbx`（Codex 全局库规范白膜） |

> **为什么场景里有柱子和格子地面？**
> 纯色空场景里推拉摇移看起来一模一样——没有参照物就读不出镜头在动。
> 柱子和地面网格提供视差参照，让每种运镜都能被清晰辨认。

> **两组片段的主体状态不同**：
> · **01–36 人物固定**：主体静立，只考察镜头运动。
> · **37–48 带主体位移**：主体套用 Mixamo 走/跑动作真实行进（走 4.16m / 跑 9.76m），
>   相机可跟拍或固定。详见下方「带主体位移」章节。

> **速度标定的两条教训**
> 1. **快了会糊**：初版「超速穿越」设 35 m/s，相机掠过几何体内部，
>    实测画面标准差仅 0.028、主体不可见（只剩模糊拉丝）。降为 22 m/s 后正常。
> 2. **快≠瞬移**：初版「急速甩镜」把 200° 旋转压在 0.09s（8 帧）内，
>    单帧转角 28°、峰值 228 m/s，渲染后相邻帧几乎无差异——观感是瞬移。
>    摊到 0.76s（18 帧）后，既保有高速感、运动又真正可见。

## 带主体位移批次：核心机制

与 01–36 的根本差别是**主体在动**。实现要点（含三个已修正的坑）：

1. **动作无需重定向**：白膜源自 Mixamo 的 X/Y Bot，
   与动作库骨架**100% 同名**（83/83 骨骼），直接绑定即可。
2. **剥离根位移**：Mixamo 走/跑动作自带位移，不处理会与脚本推进
   **双重计数**（主体飞出画面）、循环时位置「跳回」。
   做法是对 Hips 的**全部 3 个 location 通道**减去线性净漂移：
   ⚠ 只处理局部 X/Y 会漏掉前进轴 —— 实测该动作的前进漂移落在
   `array_index=2`（局部 Z）。用「压成常量」虽然也能消漂移，
   但会一并抹掉髋部起伏（实测 8.4cm → 0），破坏脚地配合。
3. **推进速度按「足部着地」标定，不能抄动画文件的根位移**：
   动画是为**另一具骨架**制作的（本动作 83 骨骼 / 腿长 0.615m；
   白膜 65 骨骼 / 腿长 0.893m）。同一组关节角度套到不同腿长上，
   脚迈出的实际距离不同 —— 抄文件位移必然打滑。
   正确做法：走路时支撑脚应相对地面静止，据此反解应施加的速度
   （`calib_foot.py`）。该方法与骨架比例、根位移均无关。
4. **落地偏移**：剥离根位移后角色会悬空（实测 4.1cm / 5.5cm），
   需下移使脚底接触地面（`z_offset`）。
5. **相机坐标系**：`co`/`ao` 为**主体相对偏移**，主体位移由 `rel()` 自动跟随，
   因此偏移的 fwd 分量应保持常数。
   ⚠ 初版把速度错加到 fwd 上，导致相机漂到主体前方、末帧画面失效。

动作与速度参数（`calib_foot.py` 标定）：

| 动作 | 文件 | 周期 | 标定速度 | 落地偏移 | 打滑 |
|---|---|---|---|---|---|
| 走 | `Walking Forward.fbx` | 41 帧 / 1.708s | **0.765 m/s** | −4.05 cm | **0.0018 m/帧** ✅ |
| 跑 | `Running Forward.fbx` | 24 帧 / 1.000s | **2.062 m/s** | −5.50 cm | 0.0110 m/帧 ⚠ |

### 关于跑步的打滑（已知限制）

跑步动作**左右脚隐含速度本身不一致**，不存在单一速度能同时满足两脚：

| 骨骼 | 隐含速度中位数 |
|---|---|
| 左脚踝 | 2.163 m/s |
| 左脚趾 | 1.599 m/s |
| 右脚踝 | 2.193 m/s |
| 右脚趾 | 1.471 m/s |

同一只脚的**踝与趾相差约 0.6 m/s**，说明脚在着地时会"搓地"，
属动作文件固有缺陷（走路动作无此问题：踝 0.779 / 0.780，高度一致）。
故跑步取折中速度 2.062；要彻底消除需换用其他跑步动作，
或对单脚做 IK 修正。

> ⚠ **选动作必须实测摆臂，不能只看文件名**
> 库里存在两套命名只差一个字母、质量却天差地别的动作：
>
> | 文件 | 摆臂幅度 | 左右手相关系数 | 评价 |
> |---|---|---|---|
> | `Walking Forwards.fbx` | 0.094 m | **+0.977** | ❌ 双臂架在胸前同进同退 |
> | `Walking Forward.fbx` | 0.707 m | **−0.965** | ✅ 自然反相摆动 |
> | `Running Forwards.fbx` | — | — | ❌ 抱胸不动 |
> | `Running Forward.fbx` | 0.588 m | −0.960 | ✅ 自然摆臂 |
>
> 相关系数是关键判据：**自然走路时左右手必须反相（负相关）**，
> 双肩同进退（正相关）就是"端着走"的病征。
> 已固化为 `verify_gait_quality.py` 自动检查。

## 参数怎么改

全部运镜定义在 `blender-cli/build_camera_moves.py`。

**架构**：每个运镜提供一个采样函数 `sample(t) -> dict`，`t ∈ [0,1]` 为归一化时间，
返回该时刻的机位/注视点/焦距/滚转/景深。脚本逐帧烘焙成相机关键帧。
因此**变焦、滚转、缓动、手持噪声、景深都能自由表达**。

```python
def s_dolly_in(t):
    return dict(pos=L3((0, -9.5, 1.35), (0, -4.6, 1.30), t),   # 机位插值
                aim=AIM0,                                        # 注视点
                lens=42.0,                                       # 焦距(mm)
                roll=0.0)                                        # 滚转(°)
                # dof=(对焦距离_m, 光圈f值)                       # 可选：景深
```

可用工具函数：

| 函数 | 用途 |
|---|---|
| `L3(p0, p1, t)` | 三维点插值 |
| `L1(v0, v1, t)` | 标量插值（焦距、滚转、对焦距离） |
| `ease(kind, t)` | 缓动曲线：`linear`/`smooth`/`smoother`/`snap`/`whip` |
| `hnoise(seed, t, amp)` | 确定性伪噪声（手持抖动，可复现） |
| `env_spike(t, c, w)` | 高斯脉冲包络（撞击类瞬时事件） |
| `_vertigo(p0, p1, t, ratio)` | 眩晕变焦（焦距自动按距离等比补偿） |

- **加减运镜**：往 `MOVES` 列表增删条目，`key` 决定输出文件名
- **改时长**：脚本顶部 `DUR`（秒）　**改分辨率**：`RES`　**换主角**：`SUBJECT_FBX`
- **加带主体位移的运镜**：在返回值里加 `arm=(x,y,z)` 即可（见 `s_follow`）

改完务必先跑 `probe` 校验取景，再渲染。

## 技术备注

本库在 **Blender 5.2 + Mixamo 系白膜** 环境下生产，以下坑均已解决：

1. **帧率**：Blender 5.2 的 FFMPEG muxer 会把输出强制成 30fps，`scene.render.fps` 不生效。
   因此改为**渲染 PNG 序列 → ffmpeg 编码**，帧率与帧数都可精确验证。
2. **视频格式开关**：5.2 起 `image_settings` 新增 `media_type`，
   必须先设 `media_type="VIDEO"` 才能选 `file_format="FFMPEG"`。
3. **姿态被覆盖**：Mixamo 系 FBX 自带 action，渲染帧求值会把骨骼打回 T-pose，
   必须导入后 `animation_data_clear()` 并清空 `bpy.data.actions`，手动摆姿才生效。
4. **摆姿轴**：FBX 导入的骨架自带旋转，臂骨旋转必须绕**骨骼头部**而非世界原点，
   否则手臂会被甩出躯干。正确角度由 `probe_pose.py` 数值求解得出。
5. **滚转必须烘焙朝向**：相机不能用 TRACK_TO 约束——约束会覆盖朝向导致滚转失效。
   本库改为直接构造相机世界矩阵（`cam_matrix()`），再用四元数写入。
6. **Action 结构变更**：5.2 起 Action 引入 slots/layers，`action.fcurves` 被移除，
   需经 `layers[].strips[].channelbags[].fcurves` 访问（`iter_fcurves()` 已兼容）。
7. **景深需要足够几何深度**：EEVEE 景深本身有效（探针实测对比度 15.6×），
   但前景若离主体太近（<3m）则散焦量不足、肉眼不可见。
   本库让前景遮挡柱贴近机位（1.2m）并跟随，才做出可辨的移焦（见 `probe_dof.py`）。
8. **渲染稳定性**：连续大量渲染可能触发内存越界崩溃，建议每段独立进程。
9. **不可对主体骨架清动画**：主体同时承载走/跑动作，若对它调用
   `animation_data_clear()` 会把动作一并删除，表现为「姿势冻结、只有整体平移」
   （实测清理后骨骼四元数在 4 帧间完全不变）。只清理相机与注视点。
10. **根位移剥离要用「压常量」而非「减线性趋势」**：Mixamo 骨骼的局部轴
    与世界轴不一致，按局部 X/Y 减趋势会删错轴 —— 实测仍残留每周期约 1.55m 漂移，
    导致相机跟拍失效。压成常量则与轴向无关，髋骨相对主体的漂移降到 0.003m。
11. **取景校验要用「形变后网格顶点」**：物体 `bound_box` 是原始网格包围盒、
    不含骨架变形，行走姿态下会明显偏大（接近 T-pose 臂展），据此判定会误报。
    应用 `evaluated_get()` + `to_mesh()` 取实际顶点。
12. **验证步态要按「相位」抽帧，不能按固定间隔**：走路周期 34 帧，
    若按每 8 帧抽样，采样点恰好落在周期 1/4 的相似相位上，
    会得出「姿势冻结」的错误结论。正确做法是**按周期比例抽帧**
    （如一个周期内均匀取 6 帧），或直接做「相对髋骨的顶点分布」数值测量
    （隔离掉整体位移后，肢体动作的位移量为 0.037–0.061m，同帧自比为 0）。
13. **Windows 文件操作会保留 mtime，导致 Python 字节码缓存失效判断出错**：
    曾用 `Copy-Item` 还原脚本，因 mtime 被保留，Python 认为 `__pycache__`
    仍然有效，继续执行**旧代码**，造成「源码已是新动作、运行结果却是旧动作」
    的诡异现象（排查耗费多轮）。已在 `run.py` 中自动清理 `__pycache__`
    并设 `PYTHONDONTWRITEBYTECODE=1` 根治。
