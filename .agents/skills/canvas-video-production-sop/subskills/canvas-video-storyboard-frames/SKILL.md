# 分镜关键帧

## 内嵌 Neo Image 规则与默认输出

常规叙事关键帧、正反打和状态板直接使用本 Skill，不要完整读取 Neo Image 大规范。

- **建与改分流**：新关键帧用 Neo Image 2 重型 prompt；只调整现成帧的一处用 Neo Nano Pro：`<只改这一处>。其他全部保持不变。` 同时改三项以上、换姿态、换结构或换机位时，回到 Image 2 重建，不连续微调到身份熔化。
- **六段式**：`参考图标注 → 主体 → 特效层（按需）→ PRESERVE/CONSTRAINTS → PHOTOGRAPHIC TONE → Avoid → size/quality`。每张参考写唯一职责与“不提供什么”；形态、数量、NO-FACE 等硬禁令放 CONSTRAINTS，不只放 Avoid。
- **叙事帧职责**：角色参考负责脸、发型、服装和体型，prompt 负责构图、姿势、占比、光线、景别和前景，不重复描写五官。一张图只设一个主要视觉锚点。
- **多角色防串脸**：身份参考逐张绑定画面位置；CONSTRAINTS 写不得串脸；Avoid 写 `faces swapped or merged`。双人/越肩镜头明确双方体位、相对高度和视线锁到对方脸/眼，不能只写“朝向”。
- **角色帧光影**：写清光从哪侧来、哪半脸亮/暗、具体高光位置，以及 `shallow DoF / wide aperture / background heavily out of focus`；四视图、色卡和灰底物料除外。
- **位置用构图关系**：使用屏幕左/右、前中后景、脚下留空、家具边缘和画面占比，不用难以兑现的米数。已建立的色卡只选本镜所需 HEX 与功能，不在每镜抄整张色表。
- **反 AI Avoid**：按本镜需要排除塑料磨皮、过饱和、HDR glow、generic AI look、3D/CG、cartoon/anime/game render、身份互换、错误轴线、错误道具状态与文字水印。复杂帧尽量不超过 500 词，简单帧不超过 350 词。
- **图型边界**：普通单镜使用图型 02 的逻辑；双人对话关系板使用图型 31 的 180°轴线逻辑——A 恒左朝右、B 恒右朝左、同一场景/主光/戏服/时刻。多格只用于关系或状态审查，实际 H3 输入仍优先单张 16:9 帧。

默认输出一张完整横向 16:9 写实电影画面，不是宫格、联系表、拼图或关系板；不要边框、编号、字幕、水印、Logo 或 UI。只有用户明确要求时才生成关系板或四宫格。只有遇到本 Skill 未覆盖的特殊静帧图型，才在 [Neo Image 图型库](../../references/neoimage-prompt-engine-公开版.md) 中按图型标题局部查阅，不得完整读取全文。

## 静态提示词分层

静帧只冻结一个可验收的视觉状态。不要传给图片模型：人物台词正文、说话人、语气/重音/停顿、呼吸节拍、环境音、动作音、BGM，以及“先 A→再 B→最后 C”的完整动态执行链。

提示词保留：静态动作阶段、姿态与微表情、视线、手部接触、道具持有者/位置/朝向/物理状态、空间站位、轴线、构图、光线和必要承接。单张图不得同时描绘动作起点、中段和终点。

顺序为：

1. 项目、段、镜头 ID 与冻结状态。
2. 按实际输入顺序说明每张参考图的唯一职责。
3. 相邻镜头承接与切换方式。
4. 视角、景别、焦段、构图、轴线、位置与视线。
5. 可见表演和动作。
6. 场景、家具、灯位与相对关系。
7. 色卡 HEX、曝光、材质、景深与胶片质感。
8. 针对本镜的排除项。

## 提交前闸门

- 从画布实时回读目标 smart config 的 `metadata.prompt` 与 `metadata.composerContent`，阻断 `DIALOGUE / DELIVERY`、`Dialogue:`、`Delivery:`、`AUDIO INTENT`、`声音/音效/BGM`、`DYNAMIC EXECUTION`、`planned duration` 等视频/声音字段。
- 写入后再回读，确认两字段相等且泄漏计数为 0；任务成功或媒体存在不能替代此检查。
- 比较镜头 manifest 的 required 与 actual references；意外参考非空时阻断，缺失参考非空时保持 `idle`。提示词 `Image N`、连线 `role/order`、`referenceNodeIds` 和 `characterReferences` 必须同构。
- 确认 `metadata.model` 有值、prompt 已更新、参考连线数正确、精确节点 ID 与结果槽正确，并记录生成前布局快照。
- 用户要求试跑一张时只提交一张；互不依赖且已授权的静帧才可并行。

## 生成与回读

- 使用原 `type: "config"`、`metadata.smart=true`、`generationMode: "image"` 的节点与结果槽，以 `resultPolicy: "replace-active"` 原位回写，不另建普通 image 结果节点。
- 为每张图使用独立、稳定、带版本的幂等键，保存真实 `directTasks[].taskId`。用有界 `canvas_wait_tasks` 收口，终态按精确任务 ID 核对。
- 成功必须同时具备：`status=succeeded`、真实 storage key、像素尺寸、目标节点、prompt 版本、generation log 中真实参考输入，以及生成前后布局完全一致。
- 失败时先判断参考选择、职责冲突、构图、色彩或过渡描述的主要问题，一次只修一个主要问题。

## 关键帧验收与返修

每张关键帧生成后立即在本 Skill 内验收：

- 人物身份、时代服装、数量与参考白名单正确。
- 场景拓扑、物理区域、遮挡、180°轴线、视线和家具尺度正确。
- 道具持有者、左右手、位置、朝向、开合/折叠/收鞘状态正确。
- 画面只冻结一个状态，动作可读，手部和画外身体连接合理；相邻镜头的开始/结束状态连续。
- 色卡功能、曝光、光线、画幅正确，且没有字幕、水印、Logo、UI 或其他禁用元素。
- 节点、taskId、storageKey、prompt 版本、真实参考输入和布局证据齐全。

使用 `accepted / needs-redo / needs-single-review / waiting-user / blocked-upstream` 记录结论。返修先定位一个主要问题，只重跑该镜及必要依赖；连续失败两次后返回资产、站位或镜头设计排查，不盲目继续。

用户授权批量检查时，先建立当前帧 manifest，再按场景和镜号确定性拼成 3×3 九宫格初筛；九宫格只用于验收，不作 H3 参考。初筛输出 `明确通过 / 明显问题 / 无法确认 / 必须重跑 / 需要单图复核`，缩略图看不清的身份、手部、文字或兵器尾部必须进入高清单图复核，不能猜测通过。

## 2×2 状态板

GPT Image 四宫格只作为四个独立静态状态缩略图，用于审查构图与动作逻辑，不模拟连续视频。每格只表现一个已经完成的状态，不追踪复杂运动；整张设为 16:9，不要求每格再是 16:9。H3 的实际输入优先使用单张完整关键帧。

四格共享场景、服装、光线、家具尺度和轴线；逐格写清人物数量、左右关系与唯一状态。排除鬼影、动作残影、重复身体、额外肢体、人物融合、家具比例变化、镜像和参考拼贴。空镜必须由前格的离场、追出和关门形成因果。

## 清理闸门

只有用户确认正式替代版本并要求清理时才执行：先记录获批身份图、四视图、色卡、场景锚、道具锚、站位图、提示词与计划节点的精确保护白名单；再建立已否决、已有替代、失败或测试版本的精确作废集合。按生成链成组核对，按 ID 删除，随后回读确认作废项消失且保护项仍在。

## 阶段输出

为每镜记录节点 ID、prompt 版本、taskId、storageKey、像素尺寸、真实参考、布局核对与验收状态。只有 `accepted` 关键帧可进入 Clip 阶段；用户要求逐张确认时，自检后标记 `waiting-user` 并停在本阶段。
