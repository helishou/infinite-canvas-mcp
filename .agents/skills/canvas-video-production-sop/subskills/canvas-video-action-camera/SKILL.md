# 动作片题材（叠加层）

## 触发条件

命中以下任一关键词就加载，**在进入镜头设计 / 分镜关键帧 / Clip 视频任一阶段之前**：

`打斗` `动作戏` `格斗` `徒手` `对打` `打击感` `重击` `元素对轰` `技能对打` `放法术` `法相` `召唤` `万剑` `长镜头` `一镜到底` `别切` `立体机动` `赛车` `飙车` `追车` `漂移`

用户用别的词描述同一题材（例：「近身互殴」「法术轰来轰去」「跟着一个人跑到底」「打得特别狠」）也算命中。**判断不了就不问，直接加载**——多读一份文件的代价小于漏读。

## 加载顺序

```
阶段子 Skill（先读，决定本阶段产物与闸门）
  └─ 本叠加层（再读，拿到优先级与下面两份索引）
        ├─ references/action-camera-principles.md  ← 跨阶段通用，按 § 一~§ 七 小节名引用
        └─ references/action-camera-playbook.md    ← 题材玩法，按 (a)分支 /(b)镜头语言 /(c)运镜节拍 /(d)冲击感 /(e)招式来源 /(f)建议区间 引用
```

**按小节名引用，不通读全文。** 阶段 Skill 内已内嵌本阶段该执行的那部分，本文件只负责：题材判定、冲突裁决、补充索引。

## 优先级（冲突时从上往下）

1. 主 `SKILL.md`「项目级不变量」与用户当轮点名。
2. H3 段内镜数实测预算（`references/prevention-by-construction.md` §四：7 秒段 ≤3 镜、每镜 ≥2.0s）。
3. 本叠加层的题材规则。
4. `action-camera-principles.md` 的镜头逻辑五自查。

## 冲突处理：切镜密度

题材密度（playbook (f)）与第 2 条预算冲突时，**SOP 预算是默认路径**。用户点名更密时按顺序做三件事，缺一不可：

1. **写明后果**：段内镜位过密会导致姿态跳变（实测 4~5 镜/段全部判超载，唯一合规的那段也是动作最准的一段）。
2. **给出替代**：拆段 / 改 Clip 分组 / 靠镜内运镜补观感。
3. **用户显式坚持才按其指令执行**，并在 `storyboard.md` 记一行「用户授权越界 + 风险」。

**不静默合并或拆分镜头。**

## 动作因果

动作设计按「发起 → 应对 → 接触/结果 → 继续」建立因果，并写明准备、主力、余势及受击后的身体和道具状态；视效只强化已确定的动作结果，不反向改写胜负。跨 Clip 的下一拍从上一拍真实尾态继续，不能让角色、武器或弹药无动作复位。用户提供可访问的运镜白模时，可按需核对机位与视差；目录命中不等于已观看或已绑定媒体。

## 不做什么

- 不设题材默认分支（徒手 / 对轰 / 召唤，快剪 / 长镜头）——由用户点名，他没说就问。
- 不把建议区间当禁令：playbook (f) 里的数字必须标注为建议。
- 不用「脸只取四视图最左格」——沿用 `canvas-video-asset-preparation` 的四格位置口径（左上正脸 / 右上侧脸 / 左下无头正面服装全身 / 右下完整背面）。
- 不改变交付形态：制作目录仍是 `productions/<canvasProjectId>/` 五件套，分镜图仍进画布有序组。
- 不引用任何现成成片提示词原文作为模板。
