# 影调一致性与跨段连续性（实测沉淀）

> 主用于：站位与色彩基准 / 分镜关键帧（`canvas-video-staging-color` / `canvas-video-storyboard-frames`）

本文件记录「多段宫格 → 洗图/超分 → H3 多段视频」链路里，跨段/段内不一致的**根因与已验证解法**。
规则来自实测数据，不是推测；标了数字的都是量过的。

---

## 一、判断问题的分层（先定位，再修）

一致性至少有四层，**工具和代价完全不同**。修错层 = 白做功：

| 层 | 症状 | 能事后补救吗 |
|---|---|---|
| 影调 | 色温/曝光/影调不统一 | ✅ 纯数学，确定性，秒级 |
| 身份+空间 | 换脸、换房间 | ⚠️ 靠参考图条件化，基本够用 |
| 姿态状态 | 该站着的变成坐着 | ❌ 事后无解，必须条件化 |
| 动作因果 | 看不到「站起来」这个过程 | ❌ 事后无解，只能重构 |

**教训**：曾先怀疑「提示词没写好」（第 3 层），实际第 1 层（宫格色温）就已经坏了。
**动手前先逐级量一遍**（原图 → 切分 → 洗图 → 超分 → 视频），看指标在哪一级开始漂 —— 这就是 bisect。

## 二、色彩/影调对齐：绝不用扩散模型

### 实测对照（同一张 S03 单格 → 基准 场景图 b\*=+4.72）

| 方法 | b\* 偏差 | **结构梯度 r** | 结论 |
|---|---|---|---|
| 原图 | +6.94 | — | — |
| krea2（用户写的 palette 提示词） | +2.89 | **-0.008** | 重绘，结构丢失 |
| flux2-klein | +1.37 | **0.029** | 重绘，结构丢失 |
| **纯数学 LAB 均值/方差匹配** | **+0.18** | **0.9972** | ✅ 唯一可用 |

**判据是「结构梯度 r」**：扩散模型的梯度 r ≈ 0，说明它不是「调色」，是**重新画了一张**。
画质对比永远赢不了这种情况 —— 内容已经不是原来那张分镜了。

### 结论

1. **色彩匹配是数学问题**，用 LAB 空间均值/方差对齐即可，精确到 0.2、可复现、秒级（16 张 < 20 秒）。
2. **扩散模型每次跑都在掷骰子**，不可复现 —— 这类需求不要交给它们。
3. 只对齐 `a*`/`b*`（色度）**保留 L** → 保住每张图自己的曝光与反差（实测 b\* 偏差 0.80，肉眼不可辨）；
   三个通道全对齐 → 偏差更小（0.26）但会把明暗反差抹平。**默认只调色度。**
4. 参考实现：`ImageColorMatch+`（LAB，factor=1.0）等价于本地脚本里的均值/方差对齐。

## 三、从源头控制影调：生成时锚定，不要事后修

### 无人场景锚的验收闭环

场景锚决定后续人物关键帧和正反打的综合色调，不能只看任务 `succeeded` 就进入下一阶段：

1. 先从画布读取已有场景、综合色卡和目标位置，避免重复生成或覆盖旧版；新版标题使用清晰的 `v2/v3`，保留可比较的上一版。
2. 提示词同时锁定**空间用途**与**综合色彩**：写明表演区、进出口、对坐/对峙位置、正反打机位、叙事道具；另写中性雾白高光、中性灰褐木色、可读冷灰阴影、极少暖边缘光和小面积朱红焦点。
3. 生成后查询任务终态与真实 `storageKey`，从媒体记录取得实际文件；不得凭配置节点成功或猜测文件名宣布完成。
4. 对实际图片逐张检查：人物/文字污染、白点是否中性、木色是否偏黄橙、阴影是否偏青或死黑、木纹/家具结构是否可读、空间是否真的支持后续镜头。
5. 首轮出现综合色偏差时，第二轮必须把问题量化成相对调整，例如“曝光提高半档、阴影提高一档、黄橙饱和度降低、黑位抬起、局部对比降低”；不要仅重复“更雾白”。两轮仍不合格则停止继续抽卡，改用已确认的同类场景成品作参考锚或转确定性调色。
6. 三个以上同剧场景使用同一冻结色彩段，地点描述只改变空间与剧情功能；不得为不同地点或势力另写一套综合色科学。
7. 真人剧综合色彩术语只约束色相和明度，不得自动扩展成材质风格：“纸本白/雾白”不等于宣纸纹理、水墨、粉雾或过度柔焦。提示词要明确真实皮肤、木纹、织物、自然锐度与镜头扩散边界。
8. “低饱和＋抬黑＋低微反差”容易叠加成既淡又暗。用户反馈整体太淡太暗时，不再重复“更雾白”：以实际图为准，提高中间调和场景曝光，恢复适量综合色饱和度与木色密度，同时保持高光中性、暗部可读；未经确认不得继续批量生成下游人物关键帧。

视觉验收服务临时不可用时，可调用技能随附的 `scripts/vision_via_api.py <image> <question> <model>` 检查实际文件；先从当前可用模型列表选支持图片且有活动账户的模型，并以一次真实图片调用验证，不要因模型名出现在列表里就假定可用。这只是替代入口，验收标准不变。

### 用户参考图必须直接入画布

当用户认为文字描述没有抓准参考图时，不要继续改综合色彩形容词；把原图变成可追溯的画布参考：

1. 对本地附件调用 Backend `POST /media/upload-binary`，原始二进制作为 body，显式传 `Content-Type`、URL 编码的 `X-Media-Name`、`X-Media-Category: input` 和真实宽高；不要误用只接收 JSON `dataUrl` 的 `/media/upload`。
2. 用 `canvas_create_node(nodeType="image")` 创建图片节点，metadata 至少写入真实 `storageKey`、带 token 的 `url/content`、`mimeType`、`source` 和 `status: success`。
3. 后续 `canvas_generate_image` 把该图片节点放入 `referenceNodeIds`，提示词只规定新场景的空间与剧情功能，并明确“综合色彩/曝光/饱和度/材质直接跟参考图；忽略参考图的版式、标签和人物”。
4. 回读生成任务终态和输出 `storageKey`，下载实际图片交付；只有配置节点创建成功不算生成完成。

这条路径用于**生成新场景**。如果只是把既有分镜精确匹配到参考综合色彩，仍按本文件的 LAB 确定性调色流程处理，不能用扩散重绘代替调色。

### 为什么「每张都传场景图」没用

四张宫格生成时**都传了同一张场景图**、提示词也写了「图1 是场景，作为空间与光线的唯一基准」，
结果四张仍各偏各的（S01 +3.9 / S02 +4.5 / **S03 +6.9** / S04 +5.7）。

**原因**：场景图在提示词里是「空间参考」（要照着它构图），**色调约束被稀释**了；
而扩散模型把参考图当「参考」而不是「硬约束」，每次生成都会重新解释色调。

### 有效解：用「本片第一张同类宫格成品」当色调锚

同一任务、同内容，唯一变量是**加不加第 4 张参考**：

| | 参考图 | S03 输出 |
|---|---|---|
| 旧 | 3 张（场景 + 两角色四视图） | b\*=+6.94（偏差 +2.22） |
| 新 | **4 张**（+S01 宫格成品） | **b\*=+4.23（偏差 -0.49）** |

且 L 与锚点几乎一致（18.14 vs 18.15）、对比度 σ 也收敛（17.72 vs 18.37）——
说明它**真的在跟锚点的影调走**，不是巧合。

**为什么同类产物更有效**：S01 宫格和 S02/S03/S04 是**同类产物**（都是分镜图、同样的台灯光位、
同样的低饱和处理），它传达的色调信号比场景图强得多。

### 落地规则

1. **锚点必须是已确认合格的第一段成品**（先量一遍它的 b\*，确认靠基准）。
2. **都锚到第一张，不要链式锚上一张** —— 链式会让误差累积。
3. 提示词里加**色调锚定段**，并给出**冲突时的优先级裁决**（关键，避免模型在「画剧情」和「保色调」间摇摆）：
   ```
   【色调锚定 — 必须严格遵守】
   图N 是本片已确认的色调基准。本图四格的色调、色温、曝光、白平衡、影调对比必须与图N 完全一致。
   本段剧情与图N 不同，只允许改变画面内容，不允许改变色调风格。
   若与前面的描述冲突，以「保持与图N 同色调」为准。
   ```
4. 参考图顺序按 `order` 数组顺序，与提示词里的「图1/图2/图3/图4」**一一对应**，写配置时统一。

## 四、跨段连续性

### 机制（`h3-runner.ts` `resolveClipContinuation`）

两个开关**都必须显式打开**，且**只在链式续跑（`runFromCurrent`）时生效**：

- `tailFrameContinuation`（标在**前一段**上）= 抓该段尾帧，当下一段首帧参考图；
- `previousVideoAsReference`（标在**本段**上）= 把上一段成品整体当参考视频（默认关）。

> 别再引入隐式触发。历史上 `motionContextEnabled` 会隐式触发后者，而该链路已实证失效
> （南风 V10 主节点无任何 motion/context 输入），注入的视频实际落成了「视频1（参考视频）」，
> 静默改变出片且 UI 与生成日志都看不出来。

### 但先问：这个边界「该不该连续」

**段间断裂刺眼，不是因为断了，而是因为在「不该断的地方」断了。**
电影里的硬切观众完全接受 —— 前提是切在动作的间隙。

所以每个边界要**在生成前**声明：

```
S01→S02  CONTINUE   （同段动作延续，开尾帧续接）
S02→S03  CUT        （剧本切点，允许断）
```

**哪些必须连续、哪些允许断，是剧本决定的，不是模型决定的。**

### 段内断裂：镜头数超载

7 秒段塞 4 个镜位→ 每个切点都是模型重新推导场景的机会，也就多一次漂移风险。

**实测**：S01（3 镜/7 秒 = 2.33s/镜）是唯一合规段，也是动作最准的一段；
S02/S03（4 镜 = 1.75s/镜）、S04（5 镜 = 1.60s/镜）全部出现姿态跳变。

**硬规则：7 秒 ≤ 3 镜（每镜 ≥ 2.0 秒）。** 超出就合并镜头，或加长该段。

合并相邻镜时的写法（否则模型会把两个镜塞进一格当两个画面）：
```
本格为一镜到底（机位全程不变），按时间顺序在同一画面内连续完成以下动作：
  · 前半段（0.0-1.0s）…
  · 后半段（1.0-3.5s）…
```

## 五、提示词装配：不要「写」，要「装配」

### 反例（实测漂移量）

四段提示词里，**本该逐字相同**的影调段，相似度只有 **0.10 ~ 0.33**：
```
S01: realistic cinematic apartment drama style ...
S02: realistic cinematic night-interior style ...
S03: realistic cinematic nighttime apartment style ...
S04: realistic cinematic drama scene in a deep-night apartment living room ...
```
角色外观段更糟：S01 vs S04 相似度 **0.06**（S04 甚至整段变回了中文）。

**根因**：不是「写提示词」，而是**为每段独立写了一遍** —— 同一份光位规格写了 4 遍、措辞全不同，
那 4 次生成当然收敛不到一起。

### 正解：Bible（单一事实来源）+ 装配器

把这几块**逐字冻结**，在每段提示词里原样出现，禁止改写/翻译/省略：

| 块 | 内容 |
|---|---|
| `identity` | 角色外观+体态+微动作（含 `<Subject N>`/`<Picture N>` 绑定） |
| `scene_and_light` | 唯一主光源、方向、压暗面、暗部、色偏取向 |
| `negative` | 无字幕/文字/水印/Logo/第五人/未指定道具 |
| `color_baseline` | LAB 目标值（以场景图为基准） |

只有 `detailed_description` 的剧情部分按段不同。

**装配器要做三道自动校验**：
1. **覆盖校验**：`引用 <Picture N> 数 == 实际参考数`（否则某张参考模型根本不知道是什么）；
2. **冻结块完整性**：每个冻结块必须**逐字存在**；
3. **相似度报告**：冻结块跨段相似度必须 = 1.0000。

**实测效果**：影调段/角色段/负向清单跨段相似度 0.06~0.33 → **全部 1.0000**。

### 分镜引用必须逐格展开

反例：四段都只提了一句笼统的 `<Picture 4>` —— 而实际有 3~5 张分镜参考，
`<Picture 5/6/7/8>` **从未被提及**。模型拿到 5 张分镜图，不知道它们是什么。

正解：每张分镜参考一条独立条目，写明**对应镜号 + 秒数 + 构图 + 动作**：
```
<Picture 4> is the storyboard keyframe for [S02-1, S02-2] (0.0-3.5s of segment S02),
rendered as one continuous shot: <镜头> Composition to hold: <构图>
The action to realise across this shot is: <动作>
```

## 六、防屏显字幕/文字

### 根因

南风的防字幕是靠 `NanFengH3PromptDraft` 节点的「不要字幕水印Logo」开关，往提示词尾部追加一句约束：
```python
if no_text_watermark:
    constraints.append("画面不要额外字幕、文字、水印或Logo。")
```
**但后端直连 `NanFengH3MultiReferenceGeneratorV10`，不经过 PromptDraft** —— 那个开关永远不生效。
而段上的 `noCaption: true` 只是参数白名单里的一个字符串，**从没被写进 ComfyUI 输入**。

### 解法：后端统一注入尾缀

在 `bridge.ts` 加共用函数，两条提示词构造路径都接上：
```typescript
const H3_NO_TEXT_CONSTRAINT = "\n画面不要额外字幕、文字、水印或Logo。";
function withNoTextConstraint(prompt: string): string {
    const body = String(prompt || "");
    if (!body.trim()) return body;
    if (body.includes("不要额外字幕")) return body;   // 幂等
    return body.trimEnd() + H3_NO_TEXT_CONSTRAINT;
}
```

### 但光靠这一句不够

**实测对照**（同一批时间点抽帧）：
- S01 提示词正文**缺** `subtitle`/`watermark` 英文措辞 → **出字幕**（且内容正是台词本身）；
- S02/S03 正文**有** `subtitle`/`watermark` → **零字幕**。

**结论：防字幕靠多重表述叠加。** 南风那句中文尾缀在英文六段式提示词里权重被稀释，
必须靠正文里的英文措辞补强。正文里要显式写出：
```
No subtitles, no captions, no on-screen text of any kind, no visible writing,
no watermarks, no logos, no subtitle bars, and no UI elements appear anywhere in the frame.
Mouth movement only produces speech and never creates screen text.
```
放在**提示词最后一块**（离生成最近，权重最高），且四段逐字一致。

## 七、H3 节点写入的两个坑

1. **`h3_apply_video_plan` 会重新生成 prompt，丢弃你传的 `prompt`**
   （`normalizePlannedSegment` 按 `timeline`/`openingState` 等字段自己拼）。
   → 必须**先 apply plan，再 `h3_update_clip` 覆写 prompt**。
2. **`h3_apply_video_plan` 会把 `noiseSeedMode` 强制改回 `random`**
   → 覆写 prompt 时一并写 `{noiseSeed, noiseSeedMode: "fixed", seed}`。

### `replaceSegments` 的陷阱

`replaceSegments: true` 是**整个 segments 数组替换**，不是追加。
逐段跑时若不一次传齐，**每跑一段就抹掉上一段**（画布上只剩当前段）。

**两条纪律**：
1. 要四段都在画布上 → **一次传齐 4 段**（`replaceSegments: true` + 完整数组）。
2. 之后**只跑不重建**：用 `h3_run_clip`，绝不再调 `h3_apply_video_plan`；
   跑之前打印其余段状态确认没被破坏，并加断言「prompt 长度未变，变了就中止」。

### 回写静默丢弃

`db.ts` 的 `writeBackH3Task` 原先要求 `segments[i].runtimeTaskId === task.id`，
而 `h3_update_clip` 整段合并（`{...segment, ...patch}`）时若 patch 带了 `runtimeTaskId: ""`，
会把正在跑的 taskId 清空 → **任务成功却静默丢结果**。

修正：**只在「非空且不匹配」时才放弃**（空值 = 没有更新的任务接管，必须照常回写）：
```typescript
const currentTaskId = index >= 0 ? String(segments[index].runtimeTaskId || "") : "";
if (index < 0 || (currentTaskId && currentTaskId !== task.id)) { COMMIT; return null; }
```

**另一条纪律**：覆写 prompt / 回填结果时，patch **不要带 `runtimeTaskId`**。

## 八、清理画布节点：不能靠标题猜

**切勿**用「标题是通用名 + 无连线」判定废节点 —— 角色形象图的标题就是通用的「图片生成｜结果」
且生图后无连线，会被误删。

**删除前必做**：
1. 从 `generation_logs`（按 `storageKey` 查 `node_id`/`prompt`）或实际文件核对它是什么；
2. 算出**保护清单**（H3 各段 `refs` + `resultStorageKey` + 场景/四视图/形象图）；
3. **校验交集 = 0** 再删；
4. 删 image 节点时**连带它的 config/text 孤儿节点**一起删（否则画布留一堆空壳）。

恢复手段：`media_files.file_path` + `generation_logs.prompt`。
