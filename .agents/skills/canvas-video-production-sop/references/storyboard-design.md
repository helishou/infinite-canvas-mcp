# 分镜设计：透传、状态连续性、机位与轴线

> 主用于：分镜关键帧（`canvas-video-storyboard-frames`）与镜头设计（`canvas-video-shot-design`）

SKILL.md「制作流水线门」的展开。管的是**分镜图提示词怎么来、怎么保证格与格之间接得上**，
与 `shot-asset-pipeline.md`（宫格出图→切分→洗图的机械链路）互补。

---

## 一、设计与撰写一律透传，不要自己逐格硬编

**分镜的镜头设计、逐格画面描述、以及最终的宫格生图提示词，全部交给文本模型产出；自己只做搬运与校验。**

自己逐格手写的失败模式是固定的：**只写「这一格长什么样」，不写「从上一格怎么变过来」**，
结果是相邻格之间人物姿态、道具状态、视线方向各自跳变（上一格站着、下一格没交代就坐下；
票上一格对折、下一格没交代就摊平）。这不是措辞问题，是结构性缺失 —— 补形容词补不回来。

**透传分两步走，每一步都要用户过目再往下**：

1. **格子设计**：把素材（场景、人物、道具、台词、段落边界）打包给文本模型，要它输出 12 格的分镜设计。
2. **宫格提示词**：把上一步的定稿 + 机位方案再喂一次，要它输出**一条**可直接生图的提示词。

调用口径（本地 chatgpt2api，不支持 tool calling，只能纯对话）：
`http://127.0.0.1:8000/v1/chat/completions`，`Authorization: Bearer chatgpt2api`，模型 `gpt-5-6`。
用一个薄封装脚本收发，输出原样落文件，**不要自己在中间改写或「优化」模型给的东西**。

### 产出必过的校验（机器查，不靠眼看）

- 格数 == 声明格数；
- 每格含机位方位（`摄影机位于` 计数 == 格数）；
- 轴线声明存在（人物镜头都要有，非人物镜头要明确标注「不涉及轴线」）；
- **不含「台词」字样**；
- 含目标画幅（如 `1448`/`4:3`）；
- 若模型返回被 ```` ``` ```` 包裹，先剥掉代码块围栏再落库。

## 二、分镜图不写台词

**分镜图是静态画面，台词在它上面没有任何用处，而且有害。**

- **诱导副作用**：写「台词：…」会让模型去画张嘴/口型，甚至把台词烧成画面文字。
- **污染主体**：把 B 的动作或台词挂到 A 的镜头上，模型只能硬塞 ——
  **表现为画面里凭空多出一只手、或者背景人物的动作与前景对不上**。

台词属于**视频阶段**（H3 的 `<d>[Chinese] …</d>`），不属于分镜图。素材交给模型时可以附台词让它理解剧情，
但**必须明确要求分镜画面描述里不出现台词**。

---

## 三、每格写三态，后格开场 = 前格收尾

**每格固定三段：`开场状态` / `动作与过程` / `收尾状态`。**
`开场状态` 必须显式复述上一格的收尾（写「承接第 N 格结束状态」+ 复述内容），第 1 格写「本段开场」。

逐格必须跟踪的**可变状态**（缺一项就会跳变）：

- 每个人物的**位置**（画面左/中/右）、**姿态**（站/坐/蹲）、**重心与朝向**
- 每个人物的**头部朝向**与**视线落点**
- **电影票**：对折 / 有折痕 / 摊平 / 放在茶几上 / 在谁手里
- **手机**：倒扣 / 被拿起 / 在谁手里
- 人物**与茶几的远近关系**

**任何姿态或道具状态的变化，必须在它发生的那一格里有明确的动作描写**（「双手慢慢展开票面，压平折痕」），
不能两格之间无声跳变。

**段落边界要在素材里显式给出**，让模型知道哪些相邻格**允许**不连续（剧本切点）：

```
S01→S02  CONTINUE   （同段动作延续）
S02→S03  CUT        （剧本切点，允许断）
```

边界定义与 H3 侧的 `tailFrameContinuation` 口径同源，见 `tone-consistency-and-continuity.md`。

## 四、每格必须写机位方位 + 180° 轴线

**只写「景别 + 焦段」不等于写了机位。** 这是「方位对不上」的直接原因：
景别只说画面里多大，机位才决定**人物在画面里的左右关系**与**背景里能看到什么**。

每格补这四项：

| 项 | 内容 |
|---|---|
| 机位方位 | 摄影机在空间的哪个具体位置、朝哪个方向（如「位于茶几正前方偏左约 1.5m，朝向沙发方向」） |
| 俯仰与高度 | 平视 / 略俯 / 略仰；齐腰 / 齐胸 / 齐眼 |
| 画面轴向 | 该机位下谁在画面左、谁在画面右 |
| 背景可见 | 该机位下背景里应出现哪些场景元素 |

**硬性轴线约束**：全片保持同一 180° 轴线 —— A 角恒在画面左、B 角恒在画面右，
**任何人物镜头都不得跳轴**（不得出现两人左右互换）。
插入镜 / 手部特写 / 空镜**非人物镜头**，必须逐格注明「本格不涉及轴线」，不要静默省略。

写机位前先把**场景关键方位**列给模型当基准（沙发在画面右、餐边柜+主光在左后、茶几中央偏前、走廊右后暗部），
否则它会自己编一套空间关系，格与格之间就对不上。

### 6 格正反打关系板

制作 `2 列 × 3 行` 的正反打关系板时，按以下顺序执行：

1. 引用顺序固定为「A 角获批高清定妆、B 角获批高清定妆、获批无人场景」，人物参考只负责身份/妆发/服装，场景参考只负责空间/光线/色彩；不要把参考提示词里的角色动作、地点和夜昼照搬到当前剧情。
2. 先写死动作轴线和银幕方向，再写六个机位：A 恒在 screen-left 看右，B 恒在 screen-right 看左；1/2 为成对越肩中景，3/4 为无遮挡单人近景，5/6 为带对方柔焦前景的中近景。
3. 明确全图只有两名角色、同一时刻、同一服装和同一光位；道具动作只放进承担叙事功能的格子，避免六格各自生成不同状态。
4. `2 × 3` 个 `16:9` 单格的理论总画幅是 `32:27`（约 `6:5`）。提交前查模型支持的真实尺寸；模型只支持方形时，不要把 `1024×1024` 回显当成已满足 `6:5`，生成后必须读取实际像素并如实标注画幅偏差。
5. 视觉验收逐格检查：格数和编号、身份与服装、A/B 视线、越轴、前景归属、第三人、场景和光位。**不要把第 3/4 格缺少对方肩部判为失败**，它们按设计就是无前景的单人近景；只有 1/2 与 5/6 需要明确越肩或柔焦前景。
6. 将通过验收的媒体回写画布并交付真实文件；若只有单格出错，按第七节修单格，不重跑整板。

## 五、手部错位：改设计维度，不要加禁止词

**「背景里有人坐着，前景却多出一只没有归属的手」这类问题，加「手部规范」约束治不了。**

### 机制（决定了什么办法有用）

扩散模型内部**没有 `hand.owner = 角色` 这种绑定变量**。它看到的是「一只手 + 一个模糊人形色块 + 文本说『女人坐在后面』」，
「这只手属于谁」不是它天然具备的变量。而**景深虚化恰好摧毁了唯一的身份连接线索** ——
手臂轮廓、肩线、衣服纹理连续性全被抹掉，模型只剩「一只手 + 一个色块」，
于是回落到训练数据里更常见的模式：**桌面插入镜头 = 一只手从画外伸进来**。

**负面约束（「不得出现漂浮手」「不得有无归属的手掌」）对扩散模型几乎无效** —— 它对「不要发生什么」理解很弱。

doc: 判据是「模型有没有可以依附的身体结构」，不是「约束写得够不够严」。

### 有效改法：过肩插入（over-the-shoulder insert）

**让肩膀进入画面，手和身体共享同一视觉区域** —— 这是唯一既保留「她按着手机」的表演、
又给模型提供身体依附的改法。改写要点：

- 机位：摄影机位于该角色**肩部后侧**、沿其手臂方向拍，而不是从桌面外部俯拍；
- **袖口必须可见**，明确写「袖口连接手腕与手掌」—— 袖口是最有效的身份锚点；
- 手臂写成**连续的人体连接线**（肩膀→手臂→手腕→手掌），并写「绝不可从画外凭空伸入」；
- 背景人物**保留坐姿轮廓、肩线与手臂方向**，明确写「不可虚化成无结构的人形色块」；
- 加一条归属锚点：「观众第一眼必须确认这只手属于画面中同一位角色」。

**提示词要从「否定句」改成「描述连接路径」**：不是「手属于 A」（模型会拆成 `A + hand` 两个不连接的 token），
而是「A 的肩膀、手臂、手腕、手掌形成一条连续的人体连接线」。

### 元素数量纪律

宫格单格只有约 480×266，手本身只有几十像素。**插入镜里元素越少越稳** ——
一格只放「一只手 + 一件道具」。同一格里既要「一只手按手机」又要「另一只手拿票」，
会让元素数量控制失稳，实测产出**三只手**（且袖口颜色各不同 = 不同来源的手被拼在一起）。

**已被用户否掉的三个改法，不要再提**：① 改成纯道具特写（丢掉表演）；
② 改成人物中近景（放弃插入镜）；③ 去掉背景人物（牺牲空间关系）。
遇到这类问题时，**把机制与候选设计摆给文本模型，让它出构图方案**，不要自己在这三个里挑。

## 六、宫格策略：一次出全片，别逐段各出一张

一次生成全片宫格，格间色彩基准天然一致；逐段各出一张会多一层色温漂移。
布局口径（行=段、列=镜）与尺寸换算见 `shot-asset-pipeline.md` 第二节。

**用户坚持用宫格（而非逐格单独出图）的理由是色调一致性** —— 逐格单独生成会失去「同一次成像」的色彩基准。
所以**不要在被建议「改成分格单独生成」时自行切换**；要解决单格问题，用下面第七节的办法。

**跑之前先把提示词摆给用户确认**，确认后再提交生成 —— 分镜是下游全部资产的基准，返工最贵。

---

## 七、单格有问题就修那一格，不要重跑整张宫格

**用户明确的口径：某一格出问题（多手、错位等）时，不重跑整张宫格，只重做有问题的那一格。**

理由：重跑整张会改掉其余 11 格的构图与人物（它们本来是对的），而单格修复的成本只有一次图像编辑。

做法：`custom/krea2改图.json` 是 image→image 的**编辑流**（`denoise=1` + `Krea2EditModelPatch` 的 `source_latent`），
整张图内容由输入图决定 —— 把出事的那一格切出来喂进去、提示词只写要改什么，输出即修好的单格。
字段位置与洗图同一套（`node 8` = LoadImage、`node 17` = 提示词），详见 `shot-asset-pipeline.md` 第四节。

修完贴回宫格时，**必须把那格拉回统一色温**（LAB 均值/方差对齐，`factor=1.0`），
否则单格与相邻格会出现可见的质感差异。

⚠️ 这条路走的是本地 ComfyUI，**不消耗 chatgpt2api 的生图额度** —— 图像额度耗尽时仍可推进单格修复。
