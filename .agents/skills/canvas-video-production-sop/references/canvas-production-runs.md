# 媒体运行与恢复

触发：授权生成、跟踪、暂停、继续、处理占用或恢复任务。先读取本次[图片](canvas-image-production.md)或[Clip](canvas-clip-production.md)执行参考。

## 运行范围与回执

内容交付模式为自动文件批处理或逐 Segment 互动；媒体生产模式为仅提示词、逐项生成或按依赖自动生产。只有用户点击生产目标，或调用 `*_start_production_run` 时才授权媒体生成。每批使用稳定 `runId`/`idempotencyKey`，保存范围、发布版本、设置、引擎和 taskId；重复请求返回原批次。自动范围在审核后继续同一 runId 时，只扩展至当前依赖刚就绪的目标；逐项范围不扩张。`*_pause_production_run` 在当前任务边界暂停，`*_resume_production_run` 继续相同 runId；失败或退回的目标不能因恢复而重新提交，重生成须明确新开 runId。

智能节点生成复用原 ID 与结果槽，保持 position/尺寸/layout；同名节点按精确 ID 操作。每次提交保存真实 taskId，超时查原任务，不重复付费提交。任务、日志、归档媒体、活动节点绑定需要对应；原结果保留。

同目标新运行被旧 runId 占用时，先用 `*_get_production_batch` 回读精确运行及 taskId。暂停只保留原运行，不结束它，也不释放目标；不得以“暂停后换新 runId 再试”处理占用。旧运行处于 `awaiting_review` 且媒体任务成功时，先查看真实结果，沿用则完成审核，用户要求重做则用正式审核操作退回并记录原因；回读确认无在途任务且旧批次已结束后，才在已有生成授权范围内启动新 runId。在途任务保持占用，不重复提交，不自行批准媒体或扩大生成范围。

## 完成与恢复

保留 prompt-only 与授权执行的区别，自动/逐步模式沿用用户选择，不重复问。图片与关键帧需要实际查看并记录证据；待用户确认不假写 approved。Clip 默认只核对 taskId、终态、媒体可访问性与结果回写，不主动评分、试听、返修或重抽。

恢复先读取 Backend 修订、导演模块游标、本机当前激活的 Skill/编译脚本版本及原 taskId。提示词产物就绪、媒体已生成、技术自检和用户验收分别记录。局部修改只使依赖项失效，不重算无关目标，也不重做整项目；禁止以摘要替代完整对白、镜头或提示词。

## 目标清单与失败恢复

批量制作或恢复先读取授权范围的目标索引、targetStatus、运行及任务短回执，区分当前输入完成、历史成功但输入已变化、失败/取消、未运行、在途、待审核和阻塞。只有诊断需要时定向读取源稿或日志，不为建立清单整段回读提示词。字段缺失标为未知，不按标题或历史视频数量推断完成。

进度清单引用正式记录：owner/场次、targetId、nodeId/segmentId/Clip ID、源 revision/hash、编译版本及有效性、发布与 referenceSync、连续组和前置依赖、runId/idempotencyKey/taskId、终态、归档媒体及活动绑定。重试记录新旧运行关系和失败阶段。使用已有记录与任务历史，不另建一份可独立改写的制作真值。

正式导演稿生产的当前版本技术完成，需要有效编译与发布、目标输入同步、对应输入的任务成功、媒体归档可访问且活动目标已绑定该结果。跨版本等价投影仅沿 Backend 核验结果认可，保留原任务版本。历史成功但输入变化的媒体保留历史，不算当前输入完成；任务成功但未归档或未回写时先恢复归档/绑定，不直接重新生成。普通画布人工输入生成沿画布契约核对其冻结输入，不强加导演稿编译或发布前置条件。技术完成不表示视觉审核或用户验收通过。

遇到 `fetch failed`、超时或断连，先区分提交结果未知与已确认失败：

1. 沿原 runId、幂等键和已有 taskId 查询或恢复回执；未知结果不换 ID 重提，在途继续跟踪。
2. 已确认失败时，按错误阶段轻量检查目标可读性、绑定、参考媒体可访问性和输入完整性；只查与错误有关的输入，不重做整场复核。
3. 无在途任务且旧运行结束、占用已释放后，才在已有授权内新开 runId 重试失败目标。新任务 ID 由正式服务创建，不手工补造。独立成功项保留；连续组按 Clip 参考核对上下文并确定恢复范围。
4. 待审核、stale 或 blocked 按实际状态与 nextActions 处理；暂停不释放目标，不自行批准媒体或通过换 ID 绕过阻塞。

输入稳定后仅对依赖允许独立执行的目标分批启动；写入与启动按 revision 顺序提交，渲染由现有渠道和执行器容量调度。相同错误连续出现时停止扩批，记录阶段、目标、输入版本和错误代码，取得能区分原因的新证据再修；目标局部故障不阻塞无关就绪分支，共同输入或服务故障停止受影响批次。不新增超时、重试次数或并发上限，也不为诊断重复提交收费任务。
