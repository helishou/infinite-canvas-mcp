# 跨段空间锚定：左右、朝向、动线与反打方向

本文件只管一件事：**相邻 Clip（Segment）之间的可见空间状态怎么接上、接不上怎么办**。镜头级左右与轴线记录已由 [120 逐镜检查](../../acheng-director/references/120-precompile-shot-visibility-audit.md#逐镜检查)第 1 项与 [K6](../../acheng-director/references/decisions/continuity.md) 负责，本文件不重写那两层，只补它们之间的空档。

来源：李先生 AI 影视全流程 Skill v2.4.1 的位置截图与纯白站位做法，按画布合同改写。原文的 `对象参考@文件名` 绑定写法**不采用**——画布正式 Prompt 只由编译器从结构字段组装，见 SKILL.md「不手工维护正式 Prompt」。

## 一、四层职责分工，不许互相顶替

| 层 | 载体 | 管什么 | 不管什么 |
|---|---|---|---|
| 场景级 | `scene_registry[]` 的 space／landmarks／entrances／exits／prompt_description（acheng 口径叫"场景地图"） | 固定地标、方位、轴线、通路——**靠文案，无机器校验** | 主体在某镜的具体状态 |
| 镜头级 | `Shot.characters[].position`（`[x,y]` 0–1 归一化）/ `Shot.camera` / `Shot.visual` | 本镜画内锚点、机位与运动、动作与一阶变化 | 跨段状态（含位置与朝向，那在账本） |
| 状态级 | `ledger.facts` + `initial`/`events` + 该镜 `continuityFactIds`（`requirements` 负责断言） | 朝向、分区、动线、接触面、视线在某镜的**取值** | 地标叫什么名字（那在场景文案） |
| 段边界 | `from/to/tailFrame/motionContext` 与尾帧参考 | 跨段的可见起态 | 身份与造型 |
| 参考用途 | `subject_usages` | 该素材本镜出现、干什么用 | **不证明位置或姿态连续**（K6 原文） |

`subject_usages` 里挂了场景图和角色图，不等于位置就接上了。位置连续由**锚点 + 账本状态**共同成立，正文只负责本镜的可见动作。

## 二、位置与朝向由账本保证，正文不重述

位置不是靠正文描写"求"出来的，是靠**连续性账本声明状态、按镜投影**保证的。契约写得很直接（`source-contract.py:90`）：

> Subject Prompt v2 includes only facts selected in `subject_usages[].continuityFactIds`; **ledger.requirements and events validate and replay state but do not add unselected facts to prompt text.**

也就是说：账本是位置的权威，`continuityFactIds` / `stateRequirements` 是"本镜用哪几条"的开关。正文再写一遍就是**双写**——120 第 30 项明确要求"局部画面正文避免再次复述状态字段"，两处不一致时没人知道听谁的。

### 六项各归哪一层

| # | 项 | 落哪里 | 怎么写 |
|---|---|---|---|
| 1 | 画内左右 | **结构化字段**：acheng 生产稿用 `characters[].position`；canvas v2 稿没有该字段，落 ledger fact | `[x,y]` 归一化 0–1（如 `[0.35,0.55]`／`[0.7,0.55]`），编译时渲染成 "normalized screen anchor x=…, y=…"；不写进正文，也不把东／西方位当画面左右（120 第 1 项） |
| 2 | 朝向 | **账本** fact | 面向谁／背向谁；脸朝镜头还是背朝镜头 |
| 3 | 相对地标的分区 | **账本** fact（词来自场景文案） | 值必须是「地标＋方位」，禁止“旁边／一侧／附近”；地标词只能取自 `scene_registry` 的 space／landmarks／entrances；可读描述写进 `value_descriptions` |
| 4 | 动线方向 | **账本** fact（change） | 从哪个入口进、经哪个地标、朝哪去；有位移才登记 |
| 5 | 定位物与接触面 | **账本** fact | 站地面还是台阶／座上；在供案／桌的哪一侧 |
| 6 | 视线锚点 | **账本** fact | 看谁、看哪个地标；也可用 `camera.attention_subject_ids` |

第 1 项连正文都不进：它是**本镜构图**的产物（换机位就变），已经有结构化落点（`characters[].position`，v2 稿则用 fact），写进正文就是多写一份、还多一个会漂移的来源。

官方样例（`examples/0*.production.json`）每镜的 `characters[].position` 都是齐的——画内左右从来不是靠正文描出来的，编译时会渲染成 "normalized screen anchor x=…, y=…"。

### 事实怎么变成提示词（照渲染代码走，不照感觉写）

`canvas_subject_prompt_v2.py` 的渲染就一句话：`"{主体} {property}: {value_descriptions[值]}"`，而且 **`if not description: continue`**。所以下面三处必须齐：

1. `ledger.facts` 定义事实：`id`、`object_kind` + `object_id`、`property`（如 `standing_position`）、**`value_descriptions`（值 → 描述文本）**
2. `ledger.initial` 给基线值（`{timeline_id, fact_id, value}`）；本段发生变化用 `events`（`before` / `after` / `frame` / `shot_id`）
3. 该镜 `subject_usages[].continuityFactIds` 勾上这条事实

渲染取的是**重放轨迹**（`initial` + `events` 推出来的 start / end），不是 `requirements[].value`。`requirements` 的 `hold` / `change` 用来断言"这镜该值不变／变了"，供校验与覆盖检查，不提供渲染文本。

**两个静默失效点，症状都是"编译出来没有位置"：**

- 账本登记了，但 `continuityFactIds` 没勾 → 不投影（契约原文：only facts selected …）；
- 勾了，但 `value_descriptions` 里没有当前值的条目 → `continue`，一个字都不出。

所以"位置靠账本保证"不是登记一次就成立，是这三处齐了才成立。每次改 `visual`，在同一个 `production_edit` 事务里回头核对一遍。

### 正文骨架（动作向，不含方位）

```text
从【账本锁定的状态】继续：【动作】，【一阶变化】，落到【可见尾态】；
<d>台词</d>
```

画内锚点在 `characters[].position` 里，机位在 `camera` 里——正文两样都不写。

正文不重述分区与朝向——那些已经在账本里、已经投影进提示词。正文要写的是**这一镜发生了什么**：谁做了什么、反应是什么、画面落在哪个可见尾态。

**焦段与景别也不进 `visual`**：`camera.framing`（景别枚举）、`camera.lens_mm` / `camera.lens`（焦段）是独立字段，编译时由 `camera` 单独渲染。

### 真实翻车（EP2 成片回看，说明白为什么要这六项）

| # | 翻车 | 根因 |
|---|---|---|
| 2 | S18 成片背对声源 | 朝向没进账本 |
| 3 | S17 只写“庙前” → 走到庙对面 | 分区值写模糊，且没登记为事实 |
| 4 | S01 人流从朱漆大门涌进（应从前院侧入） | 动线没登记 |
| 5 | S15 成片站上供桌 | 接触面没登记 |
| 6 | S18 余光方向随机 | 视线锚点没登记 |

**这 6 条里有 5 条现在的检查都落在账本上**，不是因为正文写得不够漂亮。

### 禁止位置不许写成否定句

正文只写正向可见事实（120 第 3 项：不得写不存在的对象或动作）。所以“禁止上供桌”不能写成“不得站上供桌”，要写成账本 fact 的正向值——“供桌右侧地面，双脚着地”。靠正文里的否定句兜底会被格式门判为防错话术。

### 分区名只来自场景文案，不临场造

「入口／主位／案左／高台／地面」这类分区名**没有结构化校验，唯一来源是场景文案**。别把它当成能靠账本自动保证的东西——账本管的是"某主体在某镜处于某值"，不管"这个地标在这个场景里叫什么"。

场景地图就在 `scene_registry[]` 上，已经够用，**不需要改 schema**：

| 字段 | 用途 |
|---|---|
| `space` | 空间的一句话概括（"正殿，供桌居中，左后方立神龛"） |
| `landmarks[]` | 固定地标的枚举，写镜头时的取词来源 |
| `entrances[]` / `exits[]` | 动线起终点，第 4 项直接从这里取 |
| `prompt_description` | 给模型看的场景描述，同一场所有镜头共用 |

写法要求：**分区名必须是上面任一字段里出现过的词**，不临场造一个。文案里没有就先补文案，再写镜头——否则下一镜换个词，两镜对不上，而且没有任何东西会报错。

因为这条靠文案、没有机器校验，`spatial-lint.py` 只能做**可追溯性检查**：把状态值里的候选地标（2–4 字中文片段，去掉"地面／中央／一侧"这类通用位置词）拿回该镜 `scene_id` 对应的场景文案里找，找不到就报 `UNSOURCED_PARTITION`。它抓的是"临场造了个场景里不存在的地标"，抓不到"文案里有两个近义词各写了一次"——那属于人工核对。

场景文案是英文时不做这个判断（中文值对英文文案比不出结论），不制造噪音。

### 体检脚本

```bash
python -B -X utf8 scripts/acheng/spatial-lint.py <production.json> [--json]
```

查三件可复现的事：

- `MISSING_SHOT_STATE_BASELINE`：某个 Clip 首镜既没有 `hold`/`change` 要求，也没有 `stateRequirements`，也没勾 `continuityFactIds` —— 跨段边界一条状态都没接上，位置只能靠模型自己编；
- `VAGUE_STATE_VALUE`：账本里的状态值用了「旁边／一侧／附近」这类模糊方位 —— `value_descriptions` 会被原样投影进提示词，模糊词等于把选位权交给模型；
- `NO_STRUCTURED_SCREEN_POSITION`：首镜有在场角色，但既没有 `characters[].position`，也没有账本状态事实——屏幕位置没有结构化来源。**在正文里写「在画面左侧」不算**，那只是描写，不产生锚点。
- `UNSOURCED_PARTITION`：状态值里的地标在该镜场景的文案/landmarks 里找不到——分区名是临场造的。

**脚本不查正文里的方位词了**——正文不该承担方位，查它只会把双写推回去。

### 为什么锚点图不够

锚点图锁得住「这两人在哪、从哪个角度看」，锁不住「人流该从哪个门进」「主位是哪个座」「能不能站到桌上」。EP2 那 6 条位置失败里，**4 条属于这类语义错误，锚点图一条也帮不上**——图只能证明曾经是这样，证明不了应该怎样。所以它们要进账本，才可能被逐镜重放和校验。

**不套用的镜头**：POV、蚁视、航拍垂直视角、微距、纯空镜等没有“人物左右”概念的镜头，写清主体在画面内的位置与运动方向即可，不强行编左右。这条只免掉左右，不免掉账本里的空间事实。

**为什么绑了尾帧还要登记状态**：模型看到锚点图仍会把左右对调、把位置漂移；锚点图是证据，账本 + 投影才是主控。这一条在真实项目里被反复撞过，不是冗余。

这两条都是**镜头设计输入**（落 `Shot.visual` 与 ledger），不是手工往 `segments[].prompt` 里拼句子。

## 三、空间锚点的三种来源，按优先级取用

### 1. 尾帧参考（默认）

既有机制，见 [连续性边界](canvas-clip-production.md#连续性边界)。新建边界的末镜本就优先落在 MS 中景／WS 远景／FS 全景／EWS 大远景，所以尾帧天生比段内其他帧更容易看清空间关系。**先看尾帧够不够，不够才往下一步。**

### 2. 人工位置截图（尾帧拍不清时）

从当前段成片里挑**任意一帧**符合下列四项的画面，作为下一 Clip 的空间锚点：

1. 所有在场角色都在画内，或相对位置可辨
2. 能看出谁在左、谁在右
3. 决定构图的地标（门／柜台／桌／柱）在画内
4. 朝向与视线可读

处置方式：

- 命名 `<场>-<段>-<镜>位置.png`，一次定名不改不重排，台账编号只追加
- 挂到目标 Clip 的 `shots[].keyframes`（主体／锚点／局部帧）或 `pictureBindings`，用途写「空间关系锚点」
- **只锁位置、朝向、视线、遮挡、屏幕正反面**；身份与造型走角色四视图，不被这张图覆盖
- 一场第一段、换场后第一段没有前段可截，不写
- 没有真实图片就整项省略，**不虚构素材名**

这张图和尾帧参考可以并存，也可以只用它——本质是「把自动取尾帧换成人工取帧」，不新增机制。

### 3. 空间简图（前两者都拿不到时）

见第五节。放在最后，因为它是资产动作，有生成成本。

## 四、取哪个锚点：判定顺序

```text
末镜景别是否 MS/WS/FS/EWS 且第三节四项全过？
├─ 是 → 用尾帧参考（默认，零额外成本）
└─ 否 → 本段是否有任意一帧四项全过？
        ├─ 有 → 用人工位置截图
        └─ 没有 → 该场是否需要交代这个方向？
                ├─ 需要 → 空间简图（经用户同意）或报缺口
                └─ 不需要（全程特写/同一轴线） → 不绑，靠账本状态 + 场景地图
```

**整段特写是合法状态，不是错误。** 特写看不到某人不代表他离场；此时省略锚点、靠账本状态撑住即可，不必硬凑一张图。

## 五、单视角场景母图的方向缺口

### 问题

场景母图只有一个视角。反打时要拍摄影机背后的那面墙，母图里没有。

### 现有压制机制（不要重复造）

- 场景地图登记方位、轴线、通路 → **不越轴**就永远拍不到母图没覆盖的那面
- 正反打与过肩都在同一 180° 半圆内，两边背景分别是对方身后那片，母图里本来就有
- `camera.path` 记录相对地标的机位，换机位可改变视野与遮挡，**不能自行新增建筑、树木、人物或事件**

### 补法，按成本排序

1. **不越轴**（默认，零成本）。这一条能覆盖绝大多数文戏。
2. **反向补充图**：同一场景做第二张母图，命名 `<场景>-反向`，作为**该场景资产的第二个版本**，须标注同一空间、同一固定陈设；不得变成独立场景实体，不得改建筑或加设备。
3. **空间简图**：只表达方位与遮挡时用它，比写实图更好用——没有材质、颜值、光色干扰。
4. **报缺口**：空间不明确必须指出具体缺哪面、缺什么地标，**不许用固定镜头或俯视全景掩盖**。

## 六、空间简图（纯白站位）范式

仅在用户明确选择时制作，作为可选资产，不进默认流程。

只表达：**人数、相对比例、位置、朝向、视线、遮挡、屏幕正反面**。

不做：身份面貌、服装材质、装饰、灯光氛围；不强制 4K；不冒充成片定帧或角色资产。

```text
按【用户给的方向或当前镜头状态】制作【场景名】的空间简图。
画面用【准确人数】个白色人物简模，加【表达关系必需的空间、门窗、桌椅与道具简模】，
保持【相对比例、站位、朝向、视线、遮挡与屏幕正反面】。
只表达空间与人物关系，白色形体清楚可辨，不增加无依据设施或动作，不出现文字。
```

验收只问一件事：**图上能不能说清「谁在左、门在哪、各自朝哪」**。能说清就合格，画风与清晰度不参与判定。

## 七、边界（这四件不许做）

- ❌ 手工在 `segments[].prompt` 或 Clip 里拼参考写法。锚点一律走 `keyframes`／`pictureBindings`
- ❌ 把位置截图当身份资产用，让它覆盖角色四视图的脸和服装
- ❌ 用位置截图**重演**上一段的动作过程。只描述从该状态继续发生的事，否则会覆盖锚点（与尾帧参考纪律一致）
- ❌ 为了凑一张宽景锚点去改 Shot 的景别、构图、顺序或增删镜头。分段边界规则只影响分段，不改镜头设计

## 八、逐段交付前核对

按当前目标 Clip 逐条过，缺项写清具体缺什么：

1. 首镜的**五项账本事实**（朝向／分区／动线／接触面／视线）登记了吗：`ledger.facts` 有值、该镜有 `hold`/`change` 要求、`continuityFactIds` 勾选齐全；值与前一个 Clip 的尾态一致
2. 这五项的值用的是不是**具体地标＋方位**，而不是“旁边／一侧／附近”；分区名是否都能在该镜场景的 `scene_registry` 文案／landmarks 里找到（靠文案，没有自动校验，要人看）
3. 首镜 `characters[].position` 给了吗（`[x,y]` 0–1，两人镜要分得开，如 0.35 / 0.7）；正文里不要用文字描述左右
4. 正文有没有复述账本里的方位段落（应删掉，只留动作与一阶变化）
5. 锚点取的是尾帧、人工截图、简图，还是不绑；理由是否成立
6. 人工截图是否四项全过、是否只锁位置不锁身份
7. 本段是否越轴；若越，反向方向的依据是什么
8. 空间是否有已知缺口，是否已报告而不是被固定镜头掩盖
9. 有没有虚构素材名或占位图
