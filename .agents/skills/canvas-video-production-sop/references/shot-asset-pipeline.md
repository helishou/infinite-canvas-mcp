# 分镜素材管线：宫格出图 → MCP 切分 →（可选）洗图/超分 → 挂进 H3

> 主用于：分镜关键帧生成后期（`canvas-video-storyboard-frames`）

SKILL.md「分镜数量」一节的展开。全部为实测口径。

## 一、先数镜头，再定宫格

**分镜数量 = 该段的镜头数**，不是「一段一张」。地面真值：`segment.timeline` 每条动作的「运镜：」字段 —— 出现「切至」就是新镜头。实测一段 7–8s 文戏含 3–5 镜（含无台词反应镜、手部/道具插入镜、空镜）。

## 二、宫格尺寸换算（每格必须 16:9）

每格宽高比 = `(W/cols) : (H/rows)`。要让每格 = 16:9，出图尺寸须满足 `W:H = 16×cols : 9×rows`：

| 布局 | 源图尺寸 | 每格 | 用途 |
|---|---|---|---|
| 2×2 | 16:9（如 `1536x864`） | 768×432 | 4 镜及以下 |
| 3×2（3列2行） | **8:3**（`2048x768`） | 682×384 | 5–6 镜 |
| 3×4（3列4行） | **4:3（`1448x1086`）** | 483×272 | 12 镜（全片一次出） |
| 1×N 竖排 | — | 非 16:9 | ❌ 不要用 |

### ★ 3×4 宫格的正确尺寸是 4:3，不是 16:9

**极易算错**：`W:H = 16×cols : 9×rows`。3 列 4 行 → `48:36` = **4:3**。传 16:9 会把每格压成 2.37:1 的扁条。

### ★ `gpt-image-2` 的 `size` 只认预设档位的精确值，其余一律吸附

实测档位地图（同尺寸参数、3 张参考图）：

| 请求 | 实际返回 | 每格（3列4行） |
|---|---|---|
| `1448x1086` | **`1448x1086`（4:3）** | **1.778 ✓** |
| `2048x1536` / `1536x1152` / `1024x768` / `1536x1024` | `1672x941`（16:9） | 2.369 ❌ |
| `1024x1024` | `1254x1254`（1:1） | 1.333 ❌ |

**结论：4:3 的唯一可用档位就是 `1448x1086`**。请求别的尺寸会被静默吸附到最近的档，比例保留但**不是你算的那个比例**。
所以「为什么我按 4:3 算好比例，出来的格子还是扁的」——先看返回的实际像素，不要相信请求参数。

⚠️ **改完尺寸必须重新提交，并回读 `tasks.input_json.size` 确认真的是新值。**
实测踩过：改尺寸与提交时序错开，跑的是**改之前**的旧尺寸，却把结果归因成「上游强转尺寸」，
白查一轮。**报「上游不听尺寸」之前，先确认提交用的就是这个尺寸。**

**gpt-image-2 的 `size` 只要宽高比对就能用，但必须实测校验**：请求 `1536x864` → 实得 **1672×941**（16:9 ✓，实测）；请求 `3072x1152` → 被压到 **2048×768**（8:3 ✓）。**分辨率有上限（约 2048 长边）**，超过就归一化，比例保留。

### ★ `no available image quota` 是账号配额，先看服务日志的 `restore_at`

报 `HTTP 429 {"error":{"message":"no available image quota","type":"insufficient_quota"}}` 时：

- **重试一次仍失败就不是瞬时限流** —— 去看 chatgpt2api 启动日志里那行账号状态：
  `quota: 0`、`status: "限流"`、`restore_at: <ISO 时间>` 就是账号额度真的用完了。
  **`restore_at` 就是恢复时间，直接换算成用户时区报给他，不要反复重试浪费用户时间。**
- **chatgpt2api 进程没跑时，报错是 `WinError 10061 目标计算机积极拒绝`**（不是 429）。
  重启用 `.venv/Scripts/python.exe main.py`（在 chatgpt2api 仓库根目录），**启动约需 15–20 秒**，探测：
  `curl -s -m 5 http://127.0.0.1:8000/v1/models -H "authorization: Bearer chatgpt2api"`。
  它同时是**识图通道**，服务挂了所有画面核对也会一起挂。
- **额度耗尽时本地 ComfyUI 链路不受影响** —— 单格修复/切分/本地工作流照常能跑，不要因此整条停摆。

出图后先验尺寸再切：

```python
from PIL import Image
w, h = Image.open(path).size
assert abs(w/h - 16/9) < 0.02        # 2×2
assert abs(w/h - 8/3)  < 0.02        # 3×2
```

## 三、MCP 切分（`canvas_split_image`）

```
canvas_split_image(nodeId, rows, columns, inset, gap)
```

- 行为与前端「分割」工具**同一算法**（等分口径 `floor(index*size/count)`），切出的节点排在被切节点右侧并自动连线。
- **`inset` 是必备参数，不是可选项**：宫格图的分隔线正好压在切割线上，不内缩会把白线切进每块边缘（实测源图竖线在 x=834–837、横线在 y=469–471，各 3–4px 宽）。`inset=4` 后 8 条内边缘亮度从 241/255 降到 30–102，白线彻底消失。
- **切之前必须确认切的是整张宫格，不是已切出的子块**：拿 `metadata.naturalWidth/naturalHeight` 与预期源尺寸比对（子块只有源图的一半）。实测连续两次切错子块，产出 412×229 的碎块。
- 切完逐块验比例（每块应为 16:9）。

**先切一张试，确认格子干净、无残留格线、内容没被切歪，再批量做其余段。**

## 四、洗图（`custom/krea2改图.json`）与超分（`custom/seevr图像放大.json`）——**可选，默认不做**

### ★ 先读这条：洗图+超分对 H3 是负收益（同 seed A/B 实测）

**默认把切分原图直接喂 H3，不要先洗图再超分。** 这两步是可选增强，除非做了 A/B 并确认有收益。

同 seed、同一段、同一提示词，**唯一变量 = `storyboard` 那几张参考的处理程度**（场景图与四视图不变）：

| 参考图 | 全图 b\* | 中间调 b\* | 亮度 L\* | 锐度 |
|---|---|---|---|---|
| 洗图+超分 | +5.3 | +11.2 | 17.1 | 2.17 |
| **切分原图** | **+2.8** | **+6.0** | **18.4** | 2.10 |

机制：H3 会**学习参考图的色调风格**，所以 krea2 那 +3.0 b\* 的暖偏被放大后传进视频；原图直接喂反而比参考图更中性（H3 自身的电影质感 LoRA 在往回拉）。**洗图 → 更黄、更暗，锐度无优势。**

做这个 A/B 的两个前提，缺一个结论就无效：
1. **固定种子**：`h3_apply_video_plan` 会把 `noiseSeedMode` 静默改回 `random`，apply 之后必须补 `h3_update_clip({seed, noiseSeed, noiseSeedMode:"fixed"})`。
2. **别被上一轮结果骗**：重复跑同一 segment 时 `resultStorageKey` 在新结果落库前**一直保持上一轮的值**，只判 `status==="success"` 会读到旧结果、得出「两轮一模一样」。提交前记下旧值，**必须等它变了才算新结果**（或盯底层 `comfyui:minimax-h3` 那个新任务 id）。

用户说「放弃洗图」时要把链拆干净：H3 参考换回切分原图，并删掉洗图/超分的中间节点（实测 107 个），不要留着占画布。

### 何时还是可以用

**想要更「电影感」的质感、且愿意接受暖偏**时可用。要校正色偏就在 SaveImage 前插 `ImageColorMatch+`（`color_space=LAB`、`reference`=原图、`factor=1.0`；实测全图 b\* 精确回到 +3.3）。**色偏校正要在超分之后做**（统计对齐更准）。

### 执行细节（走 MCP，不需要外部脚本或浏览器）

```
canvas_generate_image(model="custom/krea2改图.json",
                      prompt=<内置洗图提示词>,
                      referenceNodeIds=[<单格节点 id>])
```

### 洗图工作流的内置提示词

`custom/krea2改图.json` 的 `node 17` (`PrimitiveStringMultiline`) 已内置默认提示词，`fields_json` 里标了 `isPrompt: true`，**默认就是它**，无需用户提供：

```
keep everything unchanged,
only improve cinematic texture
soft diffusion,
film color,
natural skin,
cinematic lighting
```

image field 是 `node 8` (`LoadImage`)，单图。

### 尺寸：洗图输出会被工作流重设，不是原尺寸

工作流内含 `ImageScaleToTotalPixels(megapixels=1)`，**所有输入都会被归一到约 1MP**：832×466 与 678×380 的输入，输出**统一是 1368×768**。提前告诉用户最终尺寸，别让他以为会保持原尺寸。

### SeedVR2 超分的 `resolution` 不是倍数，是「最短边目标」

`custom/seevr图像放大.json` 的可编辑字段（`workflow_configs.fields_json`）：

| field | node | 含义 | 默认 |
|---|---|---|---|
| `Image` | 6 (`LoadImage`) | 输入图 | — |
| `缩放（图片太大的时候需要缩小）` | 10 | 前置 `ImageScaleToTotalPixels` megapixels | 0.3 |
| `Resolution` | 2 | **最短边目标分辨率**（不是倍数） | 2048 |
| `Max resolution` | 2 | 任一边上限（0=不限） | 4096 |

源码依据：`SeedVR2VideoUpscaler` 的 `setup_video_transform()` 文档串为 `resolution: Target resolution for shortest edge`。

**所以「超分 2 倍」要自己换算**：短边 470 → `resolution=940` 得 1664×940；用默认 2048 则短边直接拉到 2048（约 3–4.4 倍，不是 2 倍）。**用户说「2 倍」时先算给他看，不要直接把 2048 当 2 倍传。**

## 五、批量执行纪律

- **逐张提交 + 失败自动重试**，不要一口气全推。理由：本地 ComfyUI 出图是重负载，且单张失败后重跑的成本远低于整批重来。
- **贵的步骤先跑一个单元验证再全量跑**（与 SKILL.md「制作流水线门」同一条纪律）。洗完一张让用户看效果，再决定剩下 15 张怎么跑。
- **轮询任务状态查 `tasks` 表**（`status`），产物查 `result_json.media[].storageKey` → `media_files.file_path`。
- **每张产物都要与源图逐项对照**：构图是否被重画、人物朝向有无被改、有没有新增/丢失人物、画面文字水印。洗图工作流会重绘，**画质提示词不保证结构完全不变**。

## 六、清理画布节点后必须查 H3 参考有没有悬空

**删节点会静默孤立 H3 段的参考。** `segments[].refs` 存的是 `{nodeId, storageKey}` 快照，`validateVideoPlan` 只校验这两个字段**存在**，不校验节点是否还在画布上——**不报错**，只是那路输入凭空少了。

清理前后各跑一次全段悬空检查：对每个 segment 的 `refs.image[].nodeId` 核对是否还在 `nodes[].id` 里；**删节点前先用 `refs` 的 nodeId 集合把在用的节点排除掉**（实测 107 个待删节点里就有 3 张正被 H3 引用，靠这步拦下）。

## 七、产出后的画布布局（用户偏好）

用户明确要求「同功能的整合在一个区域，不要东一块西一块」。分区并按功能归位：

| 区 | x 范围 | 内容 |
|---|---|---|
| 角色资产 | 最左负坐标 | 各角色身份图（+ 各自 config）、四视图、场景图 |
| 分镜素材 | 中段正坐标 | **每段一行**：config → 宫格原图 → 该段所有单格 |
| H3 节点 | 最右 | 编排节点 |

- 每段严格同行对齐（同一 `y`），段间按固定 `row_h` 递增（如 1200）；单格在其宫格右下方成矩阵。
- 移动用 `canvas_move_nodes(projectId, items=[{id, x, y}])` —— 参数名是 **`items`**（不是 `deltas`），每项 `{id, x, y}` 或 `{id, dx, dy}`。
- 归位前先 dump 一次画布拿准每个节点 id 与所属段落。
