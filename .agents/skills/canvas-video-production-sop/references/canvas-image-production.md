# 图片生产

触发：登记资产或关键帧参考、生成、审核图片。使用当前激活 Acheng 的 assets/model 合同；准备节点与共享归属见[工作台与布局](canvas-workspace.md)，提交任务另读[运行与恢复](canvas-production-runs.md)。

assets 映射保存实际 nodeId、assetId、storageKey、sha256 和 version；只有执行了真实审核才记录批准证据。每张图一项主要职责并写保留/排除范围。生成成功的媒体保持 `generated`，技术条件满足且被当前目标选用时可以作为参考，不要求先点击审核。未生成的必需图片保留为待生成目标；它只阻止实际依赖它的镜头生成。

用户主动启用审核时，`review_director_asset` 绑定版本、项目节点、归档 storageKey、媒体摘要和审核理由；Backend 校验实际文件后才将资产标为 `approved` 或 `rejected`。缺少审核证据不能伪造批准记录。旧稿在兼容区原样查看，接入 Acheng 时只补本轮缺项，不能自动重做历史媒体。

静帧冻结一个可见状态，声音和完整动作链归视频。

### 关键帧参考核对

编写或修改关键帧前，逐镜对照完整画面描述登记出场对象，包含前景、远处和背景中明确身份的角色，以及场景、道具和风格参考。对齐 `shots.required_assets`、`shotInputs.assetIds`、关键帧资产的 `depends_on` 与编号 `asset_cards.references`；身份图只保留登记特征，参考卡明确 preserve/exclude。画面正文新增对象时重新核对，不能把未入镜的身份图缺失当作纯显示问题。程序校验登记清单的覆盖，不能可靠发现自然语言中的所有漏登角色；这一步由导演逐镜核查。

素材身份节点与图像生成节点分开：角色、场景、道具先登记正式实体，由 Backend 建对应类型节点；缺失身份节点使用 `entity:<character|scene|prop>:<实体ID>` 准备。Subject 图片可绑定角色／场景／道具节点或智能图片节点，读取当前有效内容与真实归档来源。

正式图片沿 `production_prepare_targets` 准备，回读 Backend 的正式图片输入投影及参考连线后再提交；缺失、过期或顺序不一致时先修正式源并重编译。不能另拼临时 references 掩盖空面板，也不能把生成结果自身或角色节点的全部服装图混入编号参考。画布增删/排序参考会回写正式源并使编译过期，已有任务继续使用自己的冻结清单。

### 图片并发调度

- 用户授权多张资产图或关键帧后，从正式 readiness 和资产依赖中找出授权范围内的 `ready` 目标，先提交这些目标，再统一跟踪结果。共同依赖的已归档角色图或风格图可供下游使用，无需审批；缺失文件、错误绑定或哈希不一致只阻塞消费它的目标，不阻塞其他已就绪分支。任务成功不代表视觉验收通过，也不能虚写 `approved`。
- Backend 对一个自动批次中的独立 ready 图片目标并发提交，并按依赖复用同一个前置任务；图片服务继续用自身队列和容量控制。`mediaProductionMode: per_item` 仍要求每个 run 只含一个目标。用户明确授权多个独立目标、但当前模式要求逐项时，为每个目标建立独立稳定的 `runId`/`idempotencyKey`，收到启动回执后即可提交下一个，不等前一个生成结束；独立运行使用 `scope: selected`，不扩张成 `all_ready`。已有运行保持原范围，不拆分、暂停或换键重提。
- 制作写入与运行启动按顺序提交，不能用同一个旧 `expectedRevision` 并发写同一制作记录。每次启动前回读当前 revision、发布版本和目标状态；携带 `workId` 时先沿同一 workId 把 `currentWork` 指向该目标，再用更新后的 revision 启动。游标展示一个当前目标，多任务进度以各自正式 run/task 记录汇总，不能把最后一个游标当全部任务。
- `mediaProductionMode: per_item` 限制每个 run 的目标数量，不代表多个独立 run 必须逐张等待。用户明确选择逐项确认或单张试跑时才只启动一个目标；`prompt_only` 不提交媒体。保持用户授权范围和现有模式，不为实现并发改成自动全项目生产。
- 各目标保留独立回执和 taskId，提交阶段结束后统一回读运行/任务并查看已完成图片。某目标缺依赖、被占用、失败或回执未知时，只处理其原运行及受影响下游，继续推进无关就绪目标；审核仅在本轮明确启用时等待。按实际输入变化重算受影响提示词，再读取 readiness 后启动下一批刚就绪目标。实际并发由模型渠道与执行器已有容量控制，不提高并发上限、不绕过队列、不重复付费提交。

例如：必需的角色身份图尚未生成时，先生成并归档该图，再生成依赖它的镜头；不使用该图的角色、场景、道具目标仍可独立推进。若用户主动启用审核，才按明确的审核策略等待审核结果。
