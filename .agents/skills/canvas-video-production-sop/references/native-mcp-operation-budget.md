# 原生 MCP 操作预算

## 一、适用与优先级

用于画布生产操作提速，不改变剧情、生成参数、质量检查授权或并发保护。
原生入口门禁优先于旧文档中的脚本建议和整图快照建议。
本地脚本只允许离线准备、测量和媒体处理，不调用画布服务。

## 二、标准执行批次

1. 集中读取本轮实际需要的 schema；本轮已确认且未变化就复用。
2. ID 未知先一次 h3_get_node；已知则直接定向读 Clip。
3. h3_get_clip 用 include 一次读取本次需要的 prompt/references/runtime；实时 schema 提供 fields 时，只检查交接/timeline 等小字段用 fields，不附带两份完整 prompt。
   多个独立 Clip 读取在同一轮通过 parallel 调度，不串行拆成 N 轮。
4. 用读取结果离线准备所有 patch；完整 prompt 不用摘要或占位符代替。实时 schema 提供原生文件/句柄入口时，按 §九把完整数据留在文件，不让模型再次抄成内联参数。
5. 同一 Clip 的关联字段合到一次写入。共享项目的提交批次串行，不要求每段各调一次。
   同一 H3 节点的多个已有 Clip 配置，实时 schema 提供 h3_update_clips 时，
   按 §六合为一次原子批量提交；不是并行调用 N 次单段写入。
   未注册或语义不适用时用已注册单段工具串行，不切换脚本客户端。
6. 简单配置修改结束后集中定向回读。复杂引用变更、活动任务、并发编辑、
   CAS 冲突或部分成功时立即定向回读受影响目标，再重算后续操作。
7. 任务等待用精确 taskId、有界等待；未结束时查原任务，不重提生成。

## 三、不必要操作

普通改字段不扫描源码，不重新定位同一个工作目录，不重复加载整套规范。
禁止检查、反射或调用 `hermes_tools._call` 等私有入口来调画布，也不探测未公开的工具 RPC。`execute_code` 可离线处理文件和已取得结果，不是绕过 `tool_describe` / `tool_call` 的服务入口。
只读查询失败先核对 schema、参数、精确目标，不能立即升级为代码修改。
已有明确目标不调用无过滤 canvas_export_snapshot 或素材全库列表。
canvas_get_state 默认目录与 nodeIds 定向完整 metadata 不是同一种返回成本。
有 spillover 时本地处理已保存结果，不重请求远端相同全量报告。

## 四、核验不得削弱

小回执的 updatedFields 只证明操作范围，不证明字段值与期望一致。
结束前回读所有目标实际字段、引用身份及历史/本轮结果来源。
核对创建节点时比较完整节点 ID 目录即可，不为此载入全图 prompt/媒体。
不要并行写共享 revision；不靠永久缓存跳过并发核对。
角色组仍走专用验证工具，不能用通用 op 手拼派生 binding 逃避验证。
用户未要求质量检查时只做技术性收口，不默认看片、评分和返修。

## 五、固定复测

使用六个已存在、空闲、无引用变更的测试 Clip，各改一组关联配置，不生成。
记录 schema 发现轮、初始读取轮、单段串行基线或原生批量写入轮、末尾核验轮及实际错误；两条写入路径分开标注。
目标是去掉冗余轮次，不保证固定墙钟秒数，不把等待生成算成写入延迟。
至少三次同模型复测；测量分别列工具时间、轮间间隔、输出大小和未匹配回执。

## 六、H3 已有 Clip 原子批量配置

- 先通过本轮 `tool_describe` 确认 `h3_update_clips` 的注册及 schema。源码声明、插件版本、独立 stdio 探针都不能代替当前 Hermes 的 HTTP 工具可用性。
- 同一 `projectId`、同一 H3 `nodeId` 下的已有 Clip 用 `updates: [{segmentId, patch}, ...]`，每批 1–100 项、不允许重复 `segmentId`；单段关联字段合在一个非空 patch 中。若实时 schema 提供 edits/dryRun，局部叙事改动优先按 §八使用增量方式，不重传整篇正文。不能用它创建 Clip、启动生成或修改角色组及后台运行/结果字段。
- 已读取 revision 时传 `expectedRevision`。即使省略，服务端仍在整批预检后按其读取的 revision 严格提交一次事务；不自动 rebase。任一目标无效、引用编译失败或版本冲突，整批拒绝。允许的保存稿编辑不解除运行绑定、不改变已提交任务的输入快照或旧媒体，也不自动取消任务；旧结果与新稿分开记录。节点级参数投影按输入顺序逐字段最后写入生效。
- 返回 `atomic`、`revision`、`count` 和按输入顺序排列的 `items`，不返回整图。`values` 是提交后读取的短值；长文本/对象使用 `fieldSummaries`，其 `sha256` 对 **JSON.stringify(value)** 的 UTF-8 字节计算，`bytes` 是该序列化值的字节数。完整字段需要时仍定向回读，不拿 `updatedFields` 当值核验。
- 明确的整批预检/事务拒绝与未知网络结果分开：拒绝后核对 revision 和目标字段再重算；超时、断连或回执不完整时不能假定没有提交，先定向回读，不整批盲重跑。
- 不为上线工具自动重启 Backend。须有本轮授权并重新确认没有 queued/running/awaiting_confirmation 任务；有任务则停止重载，不取消、不改状态。HTTP Backend 加载新声明后，仍需验证 Hermes 当前目录能发现工具；不可临时改成 stdio/脚本生产入口。

以下仅为参数形状示例，ID 和 revision 必须替换成本轮真实读取值，不直接发送：

```json
{
  "projectId": "<当前项目ID>",
  "nodeId": "<当前H3节点ID>",
  "expectedRevision": 9,
  "updates": [
    {"segmentId": "<当前Clip-ID-1>", "patch": {"title": "片段一", "duration": 7}},
    {"segmentId": "<当前Clip-ID-2>", "patch": {"title": "片段二", "duration": 7}}
  ]
}
```

## 七、生产委派与单一写入负责人

### 职责与提交边界

- 主代理是唯一画布写入负责人，负责原生能力发现、当前目标读取、引用绑定、配置提交、生成/取消和最终回读。默认子代理只做离线准备、静态校验或对主代理已取得结果的独立审查，不把整项“写入并回读”委派出去。确需独立只读调查时，委派必须列出精确项目/节点范围及允许的原生只读工具；这不授予写入、生成、取消或备用通道权限。
- 串行的是提交批次，不是每个 Clip 都必须各写一次。多个已有 Clip 的配置变更先核对 `h3_update_clips`，实时 schema 可用且契约适用时按 §六合批；缺失、不适用或超限时由主代理说明原因，再选择当前注册的单段/分批路径。不能跳过发现步骤后声称批量工具不存在，也不能因原子批次拒绝就降级成逐段写入来绕过校验。
- 主代理的固定顺序：集中发现 schema 与定向读取 → 离线准备完整 payload → 按真实契约创建缺失 Clip、核对稳定 ID → 通过专用工具完成必要角色/引用绑定并核对映射 → 读取提交所需最新 revision、原生批量写配置 → 集中核对全部目标。新建段不覆盖已有内容；引用编译不允许拆开保存的关联字段须使用合适的原子契约，不写临时占位 prompt 来凑通过。
- `h3_update_clips` 只改已有 Clip 配置，不创建 Clip、不改角色组、不提交生成。专用绑定调用仍按共享项目顺序执行；不能把派生角色 binding 手工写入通用 patch，以伪造“一次完成”。有依赖的生成仍遵守阶段闸门，不因为配置已经合批就并行生成。
- 完整提示词留在文件或完整 payload 中，主代理在实际提交所需环节读取原文；其他进度汇报只列目标、文件路径、计数、长度、摘要及问题。不让子代理反复把同一批全文打印回来，不把文件路径、摘要或省略号当成 `patch.prompt`。回读摘要按 §六的序列化规则比较；编译后正文有合法映射改写时还须核对实体/引用语义，不把长度相同当作一致。
- 局部清理的子代理交接与主代理复核按 §九执行：主代理先取本轮必要字段并保存基线，子代理只读离线输入；交付后只审差异和明确问题，不默认重新创作整批。修改范围不能在交接后悄悄扩展。
- 失败先核对原请求与目标；未知网络结果先恢复原生只读查询，不重提成功批次。已完成目标只读核对，不为采用新流程而整批重写。旧会话和在途子代理不自动更新已有委派；恢复时重读本节并核对已有成果后才能安排新提交，不改历史记录来伪装新流程已生效。

### 离线准备委派模板

主代理用下面的职责文本构造 `delegate_task`；占位内容由本轮真实信息替换。子代理输出的是离线产物，不是已写入画布的回执。

```text
任务：离线整理本轮已批准稿件和配置补丁，不访问或修改画布服务。
输入：本轮实际源文件路径、目标清单、主代理已核实的目标/参考快照文件、用户限制。
职责：仅处理给定修改范围，保留完整正文、逐字台词、目标时长和顺序；静态校验并准备完整 payload 文件。
      局部改稿交付每段原始 before 和 update，采用 §九格式；不要反复打印整批 before/after。
权限：只读取上述本地文件和写入指定离线产物目录；不得改批准源稿。
禁止：画布 MCP/HTTP/SQLite 查询或写入、生成、取消、读取服务凭据、备用客户端、
      检查/反射/调用 hermes_tools._call 等私有入口、生产任务扫描 MCP 源码。
缺失信息：列出精确缺项交主代理查询，不猜 ID、引用身份或新增工具权限。
交付：payload 文件路径与原始字节 SHA-256、完整目标 ID/源稿映射、目标数、各段长度/校验摘要、问题清单；
      未核实 ID 标为待主代理解析，不把预计 ID 冒充真实目标。
停止：离线交付完成即结束；不承担画布提交或回读，也不声称“已写入/已生成”。
```

### 主代理交付前核验

检查实际调用记录，不只看最终成功：是否先发现适用的批量工具、写入是否全部来自原生 `tool_call`、每个已提交目标是否核对实际值、是否出现私有入口探索或未授权服务客户端。单段路径须给出实际契约原因；离线脚本正常使用不计为绕过。记录 `已准备/已写入/已提交生成/已完成` 的区别；本节是 Skill/委派约束，不是 Hermes 运行时权限硬拦截。

## 八、叙事局部修改：少传全文、先查关联范围

1. 先确认本轮原生 schema 提供 `h3_update_clips.updates[].edits` / `dryRun` 和 `h3_get_clip.fields`，不能因本地代码或新版本号就使用未注册参数。
2. 为道具/对白/时长变更列出本轮相关字段：prompt、首末状态、continuityIn/Out、timeline、相关声景。不是所有字段都必须改；只提交获批且实际变化的字段。已有当前源稿/回读文件可离线统计精确原文与命中次数，不让模型再次输出未变化的全文，不另调用服务脚本。
3. 每条 edits 使用精确 `field/find/replace/expectedMatches`；匹配区分大小写、不是正则，按数组顺序执行。字符串字段及 timeline 列以实时 enum 为准；timeline 只改选定字符串列，不改时间码或其他列。`patch` 与 edits 不能覆盖同一根字段，台词或另一道具不在本轮授权中则不替换。
4. 首次或范围存疑时先用 `dryRun: true`；它返回 `applied: false`、`valueSource: proposed`，不保存。整批最多给出有界差异样例，不能拿样例当完整修改列表；核对匹配总数/byField、更新字段及摘要。`remainingLiteralFields` 表示声明的叙事字段仍命中本次原文字串，供核对遗漏交接/声景；这是字面提醒，不自动补写、不等于语义有错或已通过。
5. 核对后提交相同 edits，并将预览 revision 作为 `expectedRevision`。找不到原文、次数不符、编译或版本失败时整批拒绝，先回读再重算，不用单段路径强行写入。未知回执仍先原生读取，不能重复应用文本替换。
6. 验证小字段用 `h3_get_clip(fields: [...])`，不要为此读取整个 H3 节点。只需保存稿正文时可选 fields 中的 prompt；要核对编译映射才显式 include prompt。缺失字段看 `missingFields`，不能当成空串。保存稿更新不代表已有视频改变或任务重新执行。

以下是形状示例，ID、revision、原文及次数均须替换成本轮已核实值；新参数未被 tool_describe 确认时不直接发送：

```json
{
  "projectId": "<当前项目ID>",
  "nodeId": "<当前H3节点ID>",
  "expectedRevision": 9,
  "dryRun": true,
  "updates": [{
    "segmentId": "<当前Clip-ID>",
    "edits": [
      {"field": "prompt", "find": "golden bell", "replace": "thin jade pendant", "expectedMatches": 1},
      {"field": "continuityOut", "find": "golden bell", "replace": "thin jade pendant", "expectedMatches": 1},
      {"field": "timeline[].action", "find": "golden bell", "replace": "thin jade pendant", "expectedMatches": 2}
    ]
  }]
}
```

## 九、修改稿文件与一次复核交接

1. 已有 Clip 批量改稿时先发现 `h3_prepare_clip_updates`、`h3_update_clips.preparedId` 和 `h3_discard_clip_updates`。三项尚未注册则说明部署边界；绝不使用私有 RPC 或服务脚本冒充原生文件入口。内联 edits/patch 旧路径仍可在真实契约适用时使用。
2. 主代理把本轮必要字段、精确 ID、画布 revision 和修改范围一次集中取回，保存离线基线后再委派。不让每个子代理重复调查画布。子代理只改授权范围，完整 before/after 留在文件，报告只给路径、SHA、计数、校验结果和具体问题。
3. 文件采用 `formatVersion:1`、`projectId`、`nodeId`、`expectedRevision`、`items`；每项 `{segmentId,before,update:{segmentId,patch或edits}}`。所有实际修改的已有根字段都需 before，缺失字段不伪造空值。默认保护 `<d>...</d>` 对白、duration、timeline 时间边界和正文时间码；仅用户明确授权这些变化时才在文件的 `allowChanges` 列出 `dialogue` 或 `timing`。它是执行声明，不是用户授权的替代品。
4. 主代理集中复核一次修改差异与问题清单：无具体问题就进入预检，不把整批重新写一遍。有矛盾只打开相关段/字段；若新问题改变授权范围，先说明，不夹带修剧情。机械校验由离线代码和原生预检完成，不为让模型“再看一遍”打印全部提示词。有界预览只是样例，不能替代完整字段清单或必要的定向原文审查。
5. 本地可计算原始 JSON 文件 SHA-256，不能执行画布服务。把 `filePath` 与 `fileSha256` 直接交给原生 `h3_prepare_clip_updates`：默认只读 Backend 用户的 Hermes `cache/scratch`，一个 `INFINITE_CANVAS_PREPARED_UPDATES_ROOT` 可覆盖源目录；路径穿越/目录外符号链接/摘要错误均拒绝。文件大小沿用已有本地导入上限，不扩张生成/媒体限制。
6. 载入工具核对全部 before、版本、引用和保护条件，并按字段选择字节更小且能精确产生同一最终值的 edits 或 patch；不强迫密集改稿变成几百条替换。它冻结原子操作，不写画布；返回 preparedId、修改字段、摘要和有界差异。载入已是预检，不默认再复制一轮完整 dryRun；需要重新确认版本时只传句柄做 dryRun。
7. 复核通过后用 `h3_update_clips` 传目标和 preparedId，不再输出全文 updates。冻结文件独立于源稿，源稿后续改动不会偷偷改变已预览方案；需改方案就新载入，不能改旧句柄的目标、版本或内容。提交保持严格 revision、不自动 rebase。冲突先定向核对发生变化的字段，其他已准备段不重新创作；重建方案前完整核对本次基线。
8. 未知提交结果先恢复原生连接，再按同一句柄/operationId 查询原事务回执，后续以实际字段核对；不要新建句柄重试写入。`replayed:true` 回的是历史提交值和 revision，不代表当前未发生其他编辑；必须定向读取当前状态，不能用回执覆盖新稿。
9. 完成实际字段核验或明确放弃后，通过 `h3_discard_clip_updates` 清理精确句柄，保留原始修改文件、画布、媒体和既有事务回执。没有用户授权不重跑历史视频，也不为测试新方式重写已完成稿。

句柄提交形状示例（全部标识替换为当前已核实值）：

```json
{
  "projectId": "<当前项目ID>",
  "nodeId": "<当前H3节点ID>",
  "preparedId": "<载入工具返回的冻结句柄>"
}
```

功能正确性、文件/HTTP协议时间、模型准备与端到端墙钟分别记录。不得拿隔离事务毫秒数宣称原生产改稿已从分钟降为秒；本节的集中复核约束仍是生产编排规则，不是模型行为的运行时硬拦截。
