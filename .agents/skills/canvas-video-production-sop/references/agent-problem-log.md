# 制作问题自动记录

制作中发现制作、编译、同步、任务执行、素材归档、回写或验收问题时，立即在**当前制作项目根目录**的 `.agentproblem/问题记录.md` 记录。不要等到问题解决或本轮结束再补记。目录不存在时按需创建；没有问题时不创建空目录或空文件。

## 定位与写入

- 使用当前正式制作对象对应的项目根目录。优先采用用户明确提供或当前制作工作区明确给出的项目目录；不能把代码仓库根目录、剧目目录、分集目录或画布节点目录互相猜作项目根目录。
- 若当前会话没有可写入该项目根目录的文件能力，保留问题详情并说明尚未落档；不要把问题写进另一个目录冒充完成。拿到可用路径后补写。
- 文件不存在时，复制 `assets/rework-log-template.md` 作为初始内容；之后只追加新问题或在原问题下追加进展，不覆盖已有记录。`.agentproblem` 是制作项目内的问题记录目录，不是代码仓库的 `.agents` 技能目录。
- 每条问题用稳定编号 `RW-YYYY-MM-DD-NN`，并绑定可用的稳定对象 ID（如 `targetId`、`segmentId`、`shotId`、资产 ID、`nodeId` 或 taskId）。编号不得因返修、恢复或重新生成而变化。

## 何时记录与记录内容

以下事件发生后，先记录再进入重试、回退或下一步排查；不得等排查结束后凭记忆补记：

- 任一 Agent 工具、MCP、API、脚本、文件读写或服务调用返回错误、超时、断连、拒绝或结果不明。
- 返回数据与预期不符、关键状态/文件/任务/媒体缺失、校验失败、引用/绑定不一致，或同一操作需要改参数、换入口、回退后再试。
- 制作输入或生成结果不满足已声明标准，导致目标暂停、返修、阻塞或验收不确定。

记录一次具体失败或异常，即使随后立即恢复；它仍是后续复现与判断是否重复故障的证据。同一根因在同一目标上的连续重试沿原条目追加每次操作及结果；根因或目标不同则另开条目。对成功且符合预期的常规调用、普通创作取舍、未影响制作的假设和一次性偏好不建故障条目。

每次失败/异常至少记发生时间、阶段、调用工具或操作、目标 ID、原始错误摘要、当时输入/状态、尝试序号及下一步；能取得时再补充：

- 问题现象、影响范围与明确的预期/验收标准。
- 项目和稳定目标 ID；源 revision/hash、输入或编译版本、runId、父/子 taskId、storageKey。
- 直接证据及其来源。根因未经验证标为“待核对”，不要把推测写成事实。
- 已采取的操作、用户授权边界、当前状态和下一步。不要记录密钥、完整私有配置或无关的大段媒体/提示词。

任务终态与质量验收分开记；修复后保留原证据并注明验证范围和结论，将状态改为 `resolved`，不得删除失败历史或覆盖旧媒体。尚未确认解决时保持 `open`、`waiting-user` 或 `blocked-upstream` 等准确状态。

问题记录是排障和返修索引，不是制作事实源。正式源稿、编译回执、任务状态和媒体归属仍以画布/Backend 权威记录为准；日志中的摘要不能代替回读核实。写入或更新条目前，先读取文件现状并保留已有内容。

记录格式使用 [`assets/rework-log-template.md`](../assets/rework-log-template.md)。
