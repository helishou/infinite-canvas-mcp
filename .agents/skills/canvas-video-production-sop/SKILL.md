# 无限画布短片生产 SOP

## 目标

把短片制作组织成可逐步审查的生产流程：

`项目约束 → 资产准备 → 站位与色彩基准 → 镜头设计 → 分镜关键帧 → Clip 视频 → 逐段验收 → 交付`

本技能只规定创作和生产操作；平台工程问题另行处理。

## 技能协作

- **所有静帧生图提示词的唯一规范来源**：先读取本技能内的 [`references/neoimage-prompt-engine-公开版.md`](references/neoimage-prompt-engine-公开版.md)，再编写或改写色卡、场景图、人物定妆、四视图、站位图、正反打关系板、分镜关键帧和物料图提示词。不得由本 SOP 另造一套提示词结构；本 SOP 只负责生产顺序、画布编排和验收。
- **即梦 5 / Midjourney / GPT Image 的角色与无人场景首轮建档**：同时读取 [`references/角色资产与场景生成-即梦5或MJ.md`](references/角色资产与场景生成-即梦5或MJ.md)。角色提示词采用中文单段，按“画质光线→身份年龄与东亚限定→气质体型→哑光皮肤→妆发五官与双眼→服装鞋履配饰→姿态→镜头和棚拍背景”装配；场景提示词按“空间结构→具体物件布局与材质磨损→光源方向和色温→空气环境→摄影风格→胶片→焦段光圈景深”装配，默认空镜无人。不得机械照抄示例中的现代服装、固定滤镜或具体导演名；必须替换为当前剧本、时代和已批准综合色彩。
- **规则优先级**：上述文档是即梦5、Midjourney 与 GPT Image 生成角色、场景时共同使用的内容清单和单段表达模板。GPT Image 也必须使用，不得跳过。它不取代 Neo Image 的参考图职责、身份锁定、色卡职责、画幅、负向约束和逐项验收；若当前引擎是 Neo Image 2 / Neo Nano Pro，则在使用该内容清单的同时，以 `neoimage-prompt-engine-公开版.md` 补齐其专属六段式和参考驱动规则。
- 提示词类型与该规范的图型对应：综合色卡用图型 23，角色四视图用图型 14，双人正反打关系板用图型 31，其余静帧按其中的分类路由选择。用户指定 GPT Image / Neo Image 2 时，仍须遵守该规范的参考图职责、锁定段、画幅和逐项校对要求。
- H3 视频提示词：使用 `h3-prompt-writer`，遵守其模式和 `<Picture N>` / `<Subject N>` 引用规则。
- 图生视频与 H3 运行：使用 `generate-video` 或项目现有 H3 生成能力。

### 色卡生成规则

- 色卡属于生产美术资产，必须先于新角色、场景和分镜图确定；色卡未经用户批准，不进入后续批量生成。
- 项目已有获批场景图时，以这些正式场景图作为色彩真值。把所有相关场景图按实际顺序接入图生图节点，仅提取它们共有的主色、辅色、强调色、曝光与冷暖关系；提示词必须明确：`只提取颜色，不复制构图、家具、人物或场景内容`。
- 项目只有一张综合色彩参考图时，可以该图作为提色来源；已有三张或更多获批场景时，不再用无关参考图或纯文字想象综合色彩。
- 使用 Neo Image 2 / Neo Nano Pro 时采用图型 23：图生图、16:9、2K，支持时开启 Thinking Mode。参考图职责写成 `palette-extraction source ONLY`，禁止继承空间和内容。
- 色卡版式必须为纯平面数字设计：中性纯色背景、单行等尺寸矩形色块、锐利边缘、清晰 HEX 和功能标签；整体像 Figma / Adobe Illustrator 的电影生产设计文档。
- 禁止摄影渲染、纸张或桌面纹理、景深、镜头虚化、胶片颗粒、渐变、色块光效、投影、光泽、3D、手绘、水彩、实体色卡 mockup 或真实物体模拟。
- 用户给出精确 HEX 时逐项照用，不允许生成模型自行换色。生成完成后程序化抽样核对每个目标 HEX；扩散模型不能精确保色时，改用确定性 SVG/PNG 生成，并在画布中保留获批场景参考连线作为色彩来源记录。
- 色卡节点必须标明版本与来源，例如 `P1·三场景V2综合色卡·精确色值版`；错误版本连同专属 prompt、config 和结果节点成组删除，不能留作正式参考。

## 1. 建立项目约束

开始前读取交接文档、画布现有资产和用户要求，确认：

- 故事人物、场景、总时长、段数与每段目标时长。
- 逐字台词、说话人、声音设计及是否允许调整台词。
- 画面比例、目标模型、色卡、摄影风格和输出规格。
- 字幕、文字、水印、Logo、BGM、现代物件等禁令。
- 本轮是规划、连线、试跑一张，还是允许继续生成。

用户要求“先检查”“先连线”“不要运行”或“不要连续跑”时，停在相应人工验收点。

用户已授权连续或批量制作时，在约定镜头、模型和预算范围内逐项自检后继续，不额外插入逐镜人工确认。只有用户明确要求验收、关键创作选择无法从现有要求确定，或继续执行将超出授权范围时才暂停询问；自检通过不等于用户已验收。

## 2. 建立资产与参考图职责表

记录现有场景图、人物形象图、四视图、站位图、关系板、上一镜关键帧和已完成视频。每张输入参考图必须按实际顺序写明唯一职责：

```text
Image 1：场景基准，只锁空间、家具、光线和色彩。
Image 2：角色 A 形象图，只锁脸、发型、服装和体型。
Image 3：角色 B 形象图，只锁脸、发型、服装和体型。
Image 4：站位图，只锁人物位置、朝向、全身关系和 180° 轴线。
Image 5：上一镜关键帧，只锁上一镜结束状态和曝光连续性。
```

选择参考图时遵循：

- 不涉及大幅转身、换方向或复杂全身动作，优先使用人物形象图。
- 需要全身站位、人物相对家具位置、动作路线或轴线时，使用站位图。
- 站位图已充分说明空间关系时，可省略场景图；本镜需要锁定材质、家具或灯位时再加入场景图。
- 正反打关系板用于规划和选镜；用于视频时优先裁切目标单格，不把整张宫格直接作为镜头参考。
- 只传当前镜头真正需要的参考图，避免身份、构图和空间职责互相干扰。

## 3. 先设计站位、动作与连续性

### 站位表

记录每个角色的画面方位、身体状态、视线、与家具的关系、镜头轴线和可见范围。家具要明确为与基准图相同的家具、尺度和相对位置。

### 镜头过渡表

每个镜头至少写清：

```text
镜头 ID / 时间范围 / 台词或声音
上一镜结束状态 → 本镜开始状态 → 本镜结束状态
人物动作、情绪和视线变化
相机位置、焦段、景别与轴线
人物和家具的固定关系
本镜参考图及其职责
```

不要用静态末帧替代动作设计。下一镜若出现蹲下、起身、转身、冲出门、追出门、关门或空镜，必须说明人物如何从上一状态移动到下一状态。

情绪应随剧情递进。为对白标出音量、语速、停顿、呼吸、哭腔或愤怒程度；画面中不渲染对白文字。

## 4. 生成分镜关键帧

默认输出一张完整横向 16:9 写实电影画面，不是宫格、联系表、拼图或关系板，不要边框、编号、字幕、水印、Logo 或 UI。只有用户明确要求关系板或四宫格时才生成宫格。

单张关键帧提示词按以下顺序编写：

1. 项目、段、镜头 ID，以及本镜台词或动作。
2. 按实际输入顺序逐张说明参考图职责。
3. 上一镜结束状态、本镜开始与结束状态，以及切换方式。
4. 视角、景别、焦段、构图、轴线、人物位置和视线。
5. 可见表演和动作，不用抽象情绪替代具体动作。
6. 场景、家具、灯位和人物相对关系。
7. 项目色卡、曝光、材质、景深和胶片质感。
8. 本镜针对性的排除项。

手部特写仍要交代手腕、袖口、前臂和画外人物的连接。桌面插入镜头要锁定桌面尺寸与高度、道具朝向和角色所在方向。近景要明确必须保留的腿、沙发边缘或前景元素。

执行时：

- 生成前核对画布参考连线、槽位顺序与提示词中的 Image 编号。
- 用户要求单张试跑时，只生成一张并等待验收。
- 每张生成后检查身份、服装、站位、轴线、家具尺度、动作状态、色彩和画幅。
- 失败时先判断是参考选择、职责冲突、构图还是过渡描述的问题；一次只调整主要问题，再重跑该镜。
- 按本轮约定的验收点继续下一镜；清理废图仍需用户确认替代版本和清理范围。

### 4.1 GPT Image 四宫格：只做状态板，不模拟连续视频

GPT Image 的 2×2 四宫格不适合同时承担“四张高清 16:9 电影帧、复杂连续动作、多人身份一致、空间轴线一致”这几项任务。四宫格应定位为四个独立的分镜状态缩略图，用于审查构图和动作逻辑；需要交给 H3 的镜头仍应裁切或单独生成一张完整横向 16:9 关键帧。

编写四宫格提示词时遵循：

- 明确“四个独立静态状态”，不要写“连续动作帧”“动作连拍”或“每格完整 16:9 成片”。
- 每格只表现一个已经完成的状态，不描绘起身、转身、伸手、跨门等动作过程；用“已经蹲下”“已经站起”“已经走到门口”等状态词替代进行时。
- 保持同一场景、服装、光线、家具比例和 180° 轴线，但不要要求模型在一张图里追踪复杂运动轨迹。
- 参考图按职责最小化：场景图锁空间与家具，人物图锁身份与服装，站位图锁位置、朝向、尺度和轴线；不要同时加入旧关系板、俯瞰图和多张重复场景图。
- 站位图只提供空间关系，不提供人物外观、光线或画面风格；不要让模型复制站位图的俯瞰视角或人物轮廓。
- 每格的家具、人物数量和左右关系必须单独写清，尤其要锁定沙发、茶几、门口等连续性锚点。茶几要写“与场景基准同一张、同一真实尺寸和高度”，避免变小或变矮。
- 需要空镜时，必须把“人物离场”作为前序格子的因果链：先离开、再追出、再关门，最后才是空房间；禁止第一格直接空无一人。
- 排除项加入鬼影、动作残影、半透明重复身体、额外手脚、人物融合、家具比例变化、左右镜像和参考图拼贴；不要堆叠与当前镜头无关的限制词。

推荐结构：

```text
图生图。使用 GPT Image 生成 [段落/主题] 的 2×2 独立分镜状态板。
整张横向 16:9；四格为四个独立的静态分镜缩略图，不是连续视频帧、不是动作连拍、不是正反打关系板。

【参考图职责——严格按输入顺序】
Image 1：场景基准，只锁空间、家具、比例和光线。
Image 2：角色 A，只锁脸、发型、服装和体型。
Image 3：角色 B，只锁脸、发型、服装和体型。
Image 4：站位图，只锁位置、朝向、家具关系和 180° 轴线；不复制其视角和人物轮廓。

【全局连续性】
同一场景、同一家具尺度、同一光线、同一服装、同一轴线。

【四格状态】
左上：状态一（动作已完成后的静止瞬间）。
右上：状态二（只改变一个明确状态）。
左下：状态三（情绪或空间关系进一步变化）。
右下：状态四（为下一镜留下明确结果）。

每格只出现该格需要的人物和一个明确状态，不表现动作过程，不产生残影。
```

四宫格中每个格子的内部画幅不应再强行描述为独立 16:9；整张图设为 16:9 即可。若目标是 H3 的实际参考输入，优先使用单张关键帧，四宫格仅作为规划和选镜资产。

## 5. 生成 H3 Clip

每个 Clip 开始前确认：

- 精确时长与对应镜头时间分配。
- 所用模式及参考图槽位与 `<Picture N>` 的对应关系。
- 首状态、完整动作路径、末状态和下一 Clip 的承接状态。
- 台词、语气、停顿、环境音与动作音；无 BGM 时明确禁止 BGM。
- 是否需要上一段尾帧、上一段视频或 Motion Context；不默认隐式继承。

### 5.1 参考图接线的静默失败陷阱（提交前必读）

以下四个问题都不报错，只是「什么都没发生」——任务不创建、节点停在 `idle` 或参考不生效：

1. **config 节点必须在 `metadata` 顶层写 `model`**：不能只写在 `params.model` 里。`canvas_run_generation` 读的是 `metadata.model`，读不到就 `if (!selectedModel) continue` 静默跳过——不建任务、不报错、节点停在 `idle`。
2. **画布上存在多个同名 config**：按标题挑会改错节点（实测同时存在两个「12宫格 v2｜gpt设计」），**必须按 `id` 精确操作**。改完立刻读回确认 `prompt` 长度/特征串，而不是按标题。
3. **`referenceNodeIds` 经常不生效**：节点建了但没有参考连线。创建后必须读回确认连线数，不够就用 `canvas_connect_nodes` 补。
4. **提交 `canvas_run_generation` 前读回校验三件事**：`metadata.model` 有值、`prompt` 已更新、参考连线数正确。三者齐了再提交，否则任务要么不创建，要么生成用的是错误输入。

有承接依赖的连续 Clip 逐段生成。前一段完成并检查人物、动作、声音和承接关系后，再生成下一段；是否需要人工验收遵循本轮约定。避免重复描述同一动作起点和终点，防止人物把同一动作做两遍。

## 6. 画布归档与人工验收

画布应清楚保留项目需要的场景、人物、站位、色卡、提示词、关键帧、Clip 和参考连线。

生成前检查：

1. 当前目标段、镜头和版本正确。
2. 参考图已连接到正确槽位，顺序与提示词编号一致。
3. 时长、模式、画幅、台词和声音要求正确。
4. 用户是否要求先检查、只跑一张或暂停。

生成后检查：

1. 只产生了本次要求的结果，且画布可见、归属清楚。
2. 图片尺寸或视频时长符合要求，可正常预览。
3. 人物身份、服装、站位、轴线、家具和色卡连续。
4. 动作从上一镜自然开始，并为下一镜留下明确状态。
5. 情绪和对白强度符合本段剧情位置。
6. 在已授权范围内自检后继续后续镜头或 Clip；遇到约定的人工验收点再等待用户。

更新已有镜头时优先替换或明确标记版本，不堆积难以辨认的重复结果。

## 7. 常见制作问题

| 现象 | 常见原因 | 调整方向 |
|---|---|---|
| 人脸或服装漂移 | 身份参考过多或职责冲突 | 精简为单一人物身份锚点并重写职责 |
| 家具变小、变矮或移位 | 只写物件名称，没有锁尺度和人物关系 | 引用站位/场景基准并明确同一家具、同一尺度 |
| 正反打越轴或视线反转 | 没写固定屏幕方位与视线 | 重申 180° 轴线、左右位置和目光方向 |
| 人物在镜头间跳位 | 只描述本镜静态画面 | 补齐上一镜末状态到本镜首状态 |
| 末镜突然空无一人 | 没设计人物离场动作 | 在前序镜头安排出门、追出和关门过程 |
| 台词情绪平淡 | 只写台词内容 | 增加语气、音量、呼吸、停顿和身体反应 |
| 视频把动作做两遍 | 动作路径和结束状态重复 | 每个动作只保留一个起点、一条路径和一个终点 |
| 参考图未生效 | 连线顺序与 Image 编号不一致 | 生成前逐槽核对并重新编号职责 |

处理顺序：检查结果 → 定位一个主要制作问题 → 调整参考图或提示词 → 在已授权范围和预算内只重跑对应镜头 → 自检或约定的人工验收 → 继续。无法收敛或需要扩大范围时报告问题，不无限重跑。

## 8. 交付摘要

```text
项目与本轮范围：
最终采用的场景、人物、站位与色卡：
已验收关键帧：
已验收 Clip、时长与模式：
台词与声音方案：
镜头衔接检查：
待生成或待人工验收：
最终成片与素材位置：
```

区分“已准备”“已生成”“已验收”和“已交付”，不要把它们混成同一状态。
