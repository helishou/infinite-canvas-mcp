# 画布 MCP 效率总方案（P0–P7）

本文是唯一总纲。P0–P6 的实现细节与历次验收记录见 [`mcp-efficiency-design.md`](./mcp-efficiency-design.md)；P7 的独立设计见 [`orchestration-waste-p7.md`](./orchestration-waste-p7.md)。两份旧文档保留为过程记录，冲突时以本文为准。

## 0. 状态口径

每个阶段标注真实状态，分三档：

| 标记 | 含义 | 允许的说法 |
| --- | --- | --- |
| 已上线 | 现场 `tools/list` 已确认，且行为经实际调用验证 | 可以说「现在可用」 |

## 2. 为什么规则没拦住

仓库已有 `native-mcp-operation-budget.md`（174 行：合批读、一次收口、不重复查状态、不重提生成）。当晚仍发生 67 次读取与 5 轮误判重跑。

**规则是劝告，不是约束。** 执行时只看到当前一步，规则被上下文稀释；遇到 `failed` 时按训练惯性去改内容，不回头查规则。

因此本方案的取舍标准：**不能改变工具行为或返回结构的措施，不进方案。**

## 3. 总体架构：四层

```
第 4 层 决策层   canvas_next 阶段裁决 + 唯一 nextAction + settled 账本        ← P7d
第 3 层 执行层   错误分级 doNotRetry · 等待折叠 wait:'all' · 幂等与回执        ← P7a/P7b
第 2 层 目录层   profile 工具集 · production_edit 精简 schema · 描述分层       ← P2/P3
第 1 层 读取层   节点投影 · 字段选择 · 分页分块 · 内容指纹 · ifChanged 短路    ← P1a/P1b/P1c/P4/P7c
```

调用方只需关心：**读一次（第 1 层）→ 看目录（第 2 层）→ 提交或收口（第 3 层）→ 问下一步（第 4 层）**。

## 5. 各阶段要点

### P0 统一路径

按用户意图映射到单一入口，删除跨域「一律四步检查」。`production_start_run` 自带权威校验；H3 用其现有 planHash 预览；图片清单走图片契约。已取得且仍适用的检查结果直接复用。

### P1a 节点投影

| 投影 | 含 | 不含 |
| --- | --- | --- |
| summary | 身份、标题、类型、简短状态 | prompt、模型目录、参考正文、任务历史 |
| media | summary + 权威活动媒体 storageKey 与元数据 | base64、历史结果、输入快照 |
| generation | summary + 已保存模型/模式 | Prompt 正文、参考集合、预览 |
| full | 完整节点 | 不隐式扩展整个项目 |

兼容：无 `nodeIds` 无新参数 → 旧 index/graph；有 `nodeIds` 无新参数 → 旧完整节点；显式投影 → 新路径。

实测：同一角色节点完整 126,704 字节 → media 投影 657 字节，均为一次调用。

### P1b H3 读取收口

- 保存正文用 `fields`，保存参数用 `include:runtime`，编译引用用 `include:references`
- `segmentIds` 批量读，一次快照投影全部目标，不在 MCP 内循环 N 次项目读取
- 实测：10 个已知 Clip 读 → 一次批量写 → 批量核验 = **3 次业务调用**，13,405 字节

### P1c 可观测

沿用现有 `inputSummary/outputSummary`，不新增业务表。字段见 P1c 清单。分类规则：同目标同范围同内容指纹的再次全文返回记为「重复返回候选」，**不自动认定为无效调用**（缺用户意图标记）。

### P2 / P3 目录与声明

- profile 在会话初始化固定，不随页面切换；未分类第三方插件只在 full 暴露
- compact 从 canonical operation schema 派生，禁止第二份手写 validator；提交仍严格校验
- 实测：`production_edit` 48,395 → 17,873；目录 212,601 → 187,726（当前）

### P4 源稿字段

`fields` 只选顶层键；`partialSource / sourceFields / missingFields` 明确部分结果；部分结果不能作为整稿替换输入；cursor 绑定 fields 与分页范围。

实测：同一 Shot 完整 160,634 → 字段 645 字节；额外画布运行读取 0 次。

### P7 编排浪费治理（P7a 已实现，其余设计稿）

四项机制，全部 opt-in：

| 机制 | 契约 | 解决 |
| --- | --- | --- |
| 错误分级（已实现） | `error.scope: environment\|input\|conflict\|transient\|content` + `fix` + `doNotRetry` | 假失败重跑（当晚 5 轮 → 0） |
| 阶段裁决 | `canvas_next` 一次返回 `stage / settled / blockers / 唯一 nextAction / humanReview / budget` | 自我确认式读取（67 → ≤10） |
| 读取短路 | 读时传 `ifChanged`，命中回 `{unchanged:true, bytes:0}` | 重复全文返回 |
| 等待折叠 | 提交时 `wait:'all'`，内部轮询至终态，一次返回产物与规格 | 每批 N 轮 → 1 轮 |

`ifChanged` 即 P1c/§9.1 推迟的「内容哈希条件读取」，其触发条件（证明大量重复全文）已由本次实测满足。

## 6. 通用性：三层归属

| 层 | 内容 | 落点 | 推广 |
| --- | --- | --- | --- |
| ① 通用机制 | 错误分级、阶段裁决、读取短路、等待折叠、媒体工具链 | MCP 工具（P7） | 任意生成任务：短剧、广告、商品图、TTS |
| ② 可复用模板 | 角色资产链（立绘→漫转→头图→全身→资产图）、场景降级链、参考顺序门禁 | 独立 skill，多 skill 引用 | 任意人物 / 场景 |
| ③ 专属内容 | 势能周期、擦边手法、六段式提示词、剪映踩点、发布坑 | `character-flash-pv` 等 | 不推广 |

判据：与角色剧情画风无关 → ①；与人有关 → ②；与作品有关 → ③。

## 7. 验收

### 7.1 夹具（受控，不在真实制作稿压测，不提交收费生成）

A 节点投影 / B Clip 参数 / C 多 Clip 批量 / D 源稿局部编辑 / E 参考与预览 / F 等待 / G 恢复 / H 目录 profile / I 大正文分页（P0–P6 使用）；新增：

| 场景 | 操作 | 必须证明 |
| --- | --- | --- |
| J 假失败 | 注入 ffprobe 缺失后提交一次 H3 | 首错带 `doNotRetry=true`，同 run 无第二次提交 |
| K 重复读取 | 同目标同投影连读两次，第二次带 `ifChanged` | 返回 `unchanged`，字节近 0，不夹带正文 |
| L 阶段裁决 | 一次 `canvas_next` 覆盖 A+B+E 的信息 | 调用数 1，`nextAction` 唯一且 schema 合法 |
| M 等待折叠 | 两段 H3 以 `wait:'all'` 提交 | 一次调用返回两段产物与规格，无追加查询 |

### 7.2 指标

| 指标 | 基线（2026-10-28 实测） | 目标 |
| --- | --- | --- |
| 一次 PV 的 MCP 调用 | 177 | ≤ 40 |
| 其中纯读取校验 | 67 | ≤ 10 |
| 单任务等待耗时 | 240 s（空转） | ≈ 生成时长 |
| 假失败触发的重跑 | 5 轮 | 0 |
| 主线程无工具空档 | 113 分钟 | ≤ 5 分钟（需 skill 侧配合） |
| 节点读取字节（场景 A） | 126,704 | ≤ 25,000（投影路径） |
| `production_edit` 定义 | 48,395 | 17,873（已达） |

### 7.3 口径纪律

- 每个任务都记录：逻辑调用数、网络往返、目录字节、输入输出 UTF-8 字节、服务耗时、端到端耗时
- 并行调用计 N 次；批量接口计 1 次；不混淆轮次与次数
- 百分比只用于受控夹具验收；**不得用「简单夹具 vs 历史峰值」充当降幅证明**
- 夹具结果与真实任务结果分开报告；没有内容哈希时只能报「同范围同版本重复候选」
- 模型 token 与 MCP 字节是两种成本，不能互相换算成计费

## 8. 不做的事

- 不新增通用自然语言路由器、隐式自动生成、读取缓存服务、锁、审批状态机、DB 迁移
- 不调整产品超时、重试次数、输出上限、生成并发上限
- 不为省调用删除权威提交校验（如 H3 planHash、源稿 revision）
- 不把「重复返回候选」直接判定为无效调用
- `canvas_next` 只给建议，不代替授权与提交边界
- 读取短路不适用于任务状态与生成结果（旧状态比多读一次危险）

## 9. 兼容与回退

- P1/P7 参数全部显式 opt-in，不传即现状
- 新增字段（`contentFingerprint`、`error.scope`）是附加信息，旧消费方忽略即可
- profile 默认 full；schema 默认 compact（P3 用户决定），可显式 `schema=full`
- 回退只改注册与投影选择，不迁移或清理画布数据、媒体、任务与回执
- 回退不删除新增埋点与旧基线

## 10. 实施顺序

| 批次 | 内容 | 理由 |
| --- | --- | --- |
| 已完成 | P0–P6 + 媒体工具链 + 批量任务查询 | 体积维度收敛 |
| 第一批 | P7a 错误分级 | 改动最小，单独即可消灭假失败重跑 |
| 第二批 | P7b 等待折叠 | 每批 N 轮 → 1 轮，多段收益线性增长 |
| 第三批 | P7c 读取短路 | 已有指纹基础，主要是把统计变短路 |
| 第四批 | P7d `canvas_next` | 工作量最大，是压到个位数的关键 |

每阶段独立可交付，不以前一阶段全量完成为前提。P7a 与 P7b 不改变现有默认行为，风险最低。
