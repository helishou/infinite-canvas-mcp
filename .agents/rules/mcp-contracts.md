# MCP 工具契约

触发：新增或修改 MCP 工具、共享 schema、插件声明、读写返回或兼容入口。继承[根约定](../../AGENTS.md)；业务事务与数据保护见[画布数据契约](canvas-contracts.md)。工具开发路径见[工程指引](../skills/canvas-h3-implementation/references/mcp-tool-development.md)。

## 返回与完整读取

- 新增相似工具前，必须说明现有入口为何不能通过参数表达需求。相同业务仅所属对象、模式或目标数量不同，优先复用明确的身份和范围参数；不以重复命名扩充工具目录。

- 默认读取返回身份、版本、状态、数量和可执行的详情读取入口。正文、参考集合、历史结果、完整模型目录或整张画布必须显式读取；不得把完整对象藏在摘要的其他字段中。只读诊断以当前权威基线比对：有发布编译正文时用发布稿，未发布时用当前制作稿，不以「无法比较」代替真实漂移；诊断的「不同」保持信息级，不作为画布 H3 Clip 手动生成的门槛。
- 写工具按操作投影短回执，保留操作身份、revision、重放状态、结果数量、警告代码及读回入口。禁止展开业务完整返回后仅删除某个大字段；提交、幂等和原回执由 Backend 保持，返回体治理不得重新执行操作。响应丢失后恢复原回执须明确标记重放；重复同步同一发布输入，且绑定和顺序已一致时，不新增画布或制作稿版本。
- 失败回执的「谁的问题」由 `error-taxonomy` 单点判定，附加 `error.scope / doNotRetry / fix`，保留原有 `code`、`message` 与 `retryPolicy`；任务 `failed` 快照同样带 `failure` 分级。不得在 dispatcher 里手写「这是环境问题」一类判断，也不得用自由文本替代可执行字段。
- 大集合提供筛选与分页，长正文提供定向／分块读取，导出提供鉴权文件引用。必须能读取完整内容，不静默截断，不把当前页当全集。分块保留内容摘要，游标绑定读取对象、版本和查询条件；历史游标不能依赖当前草稿版本。
- 静态读取回执带 `contentFingerprint`，重复读同一范围时传 `ifChanged` 命中就只回 `{unchanged:true, bytes:0}`，不重复返回正文。短路在 MCP 出口统一实现，由静态读取白名单判定；任务状态、等待结果、`include:runtime/result` 等动态查询一律不参与——旧结果比多读一次更危险。指纹必须由实际返回内容算出，不能用整稿哈希代替（换 `fields`/`projection` 会误判未变）。
- 提交类工具沿用 `waitForCompletion` 折叠等待（不另开同义参数）：内部等本批终态后一次返回 `status/outputs/pending/blocked`，`partial` 不自动重试；不改变提交、并发、队列与超时语义。产物规格取任务自身的 `specification`，不额外 probe。
- 阶段裁决由 `canvas_next` 一次快照派生（`stage / settled / blockers / 唯一 nextAction / humanReview / budget`），只给建议不执行。`nextAction` 只能有一个且参数必须能被目标工具校验通过：拿不到必需 ID 时就退回到能执行的读工具，不得发出空参数动作；`deliver` 阶段不再给读取动作。
- 超限响应必须给出该工具实际支持的参数或替代工具。沿用当前输出保护，不能通过放大上限或关闭保护掩盖接口缺陷；产品边界调整按根约定取得对应授权。
- 下载引用不含 token 或本机路径；文件按固定内容身份读取并走 Backend 鉴权，不能复用免鉴权媒体路由暴露项目快照。

## 共享与验收

- 工具 schema、描述、插件声明、Backend 注册和 Agent 兼容入口同步；显式参数与默认返回必须一致。复用共享投影与服务，不在每个入口维护独立裁剪逻辑。
- 会话工具集由共享目录定义，新增或调整工具时检查任务与恢复依赖；未知工具默认仅在完整目录提供。工具集在会话内固定，插件重载不得重新开放被排除的工具；目录选择不代替授权。成本统计区分分页、条件命中、动态任务和同范围重复候选，不把同名调用次数直接认定为浪费。
- 默认精简 schema 只改变参数声明，必须从 canonical 合同派生并保留嵌套输入，提交仍经过原完整校验和事务。显式 schema=full 保留完整声明；验收分别记录首次合同发现与复用成本，不以目录变小代替调用次数、正确性或模型计费证据。
- MCP 节点创建只暴露智能生成节点和智能插件节点。不得注册普通 text/image/video/audio 节点创建工具；`canvas_apply_ops` 的 `add_node` 也必须执行相同限制，避免通用操作绕过工具边界。生成提示词保存在智能节点，不为 MCP 生成流程附建普通文本节点。
- 修改默认契约前检查直接消费方并同步调用参数；文档说明外部调用迁移。Backend 网页接口需要保留完整行为时，由 MCP 显式传递视图，不顺带改变网页默认契约。
- 新工具或返回契约变更必须使用大正文、多条目和历史结果夹具验证：默认返回不夹带完整集合；分页无重复遗漏；分块重组内容与哈希一致；版本变化拒绝旧游标；写回执能重放且不重复执行。
- 验证实际 tools/list 与 tools/call 的默认及显式行为，覆盖本次受影响的共享 HTTP MCP、插件和 Agent 兼容入口。记录同一任务的总 UTF-8 返回字节数、调用次数和耗时，不能只用单次变小证明收益。
- 收口区分源码已写、共享产物已构建、进程已加载和行为已验收；保留历史埋点，不删除旧峰值制造改善。
