# 画布数据与任务契约

触发：修改或操作画布持久数据、同步、生成、任务回写、媒体与参考。浏览器、Backend、MCP、Agent、插件均遵守；不按代码所在目录例外。

## 权威与写入

| 数据 | 权威 | 调用方可以做什么 |
|---|---|---|
| 项目、资产、生成记录、结构化业务配置 | Backend SQLite | 经现有 API/service 读取与变更 |
| 原始图片、视频、音频和文件 | Backend 媒体目录 | 按 storageKey 解析、引用、下载 |
| 待确认编辑、冲突草稿、恢复标记 | 浏览器持久 outbox | 按命令生命周期保留，不能作缓存丢弃 |
| 视口等纯视图状态、渲染副本 | 客户端 | 按现有策略缓存 |
| 光标、选区、拖动预览 presence | `/canvas/realtime` WS 内存通道 | 不写项目 JSON/SQLite，不增加 revision |

已有画布持久编辑统一走 ops。外部入口 `/canvas/projects/:id/ops` 携带稳定 operationId、expectedRevision 与 source.clientId/kind/label；Backend 内部复用 `stores.projects.applyOperations`，不必回环 HTTP。SQLite 事务完成幂等与 revision 后，广播同一份 delta。不得直接写库、整图覆盖或独立补造记录来绕过该链。

内置节点默认尺寸由 `@basketikun/canvas-agent` 的共享节点规格给出：浏览器、Backend 与 MCP 创建同类型节点得到同一大小，不各自写死兜底值。插件节点类型只在浏览器注册尺寸，其他入口按共享兜底尺寸处理；发给 Backend 的 `add_node` 带显式尺寸与坐标，不依赖 Backend 猜测。

节点数组顺序就是渲染层级。`add_node` 在数组中段插入（撤销删除、粘贴到中间、插入时垫在成员下面）时必须带 `index`；同一批 op 中的删除晚于新增执行，位置按回放数组中已存在的锚点计算，不能直接拿目标数组下标，否则节点会落到最上层。

打开中的画布收到 Backend revision 后采用 Zustand 已合并的内存快照；不能另绕异步 Promise 使有效更新被 UI version 防护丢弃。

## 制作稿、草稿与派生版本

- 同一制作 owner／目标只有一份当前权威源稿。浏览器草稿只记录未保存的编辑意图，不新增可独立维护的业务真值；多个视图复用同一编辑记录，不能各自保存一份需要用户同步的当前版本。
- Shot、Subject 和连续性在结构化源中维护；Clip 分组引用 Shots，正式 Prompt 由编译器组装。画布与工作台展示投影，局部修改沿既有正式编辑入口保存，不以修改投影副本绕过源稿。显式人工 Prompt 编辑作为可追溯例外，未解析内容保留为人工稿，不冒充已反向同步。
- Shot 关键帧可按 Subject 保存服装图片绑定；保存关键帧改动时，在同一制作事务中将关键帧出现的 Subject 与服装参考同步到 Shot 主体引用。只在保存时执行，不随未保存草稿或远端更新持续同步。
- 历史、发布与任务冻结快照保持可追溯且不参与日常双向编辑。内部 source revision、canvas revision、编译身份和 taskId 由程序核验；正常界面显示未保存、保存中、已保存、编译中及生成状态，技术标识放在详情，不要求用户手工管理版本。
- 制作可用性依据当前有效画布输入和逐目标检查；导演模块的历史 `unresolved` 说明保留为创作记录，不成为手工编辑或生成门槛。已确认画布输入提交后，按 canvas revision 刷新就绪状态；即使制作源稿 revision 未变也必须接入，不以重拉整份源稿和历史代替状态更新，迟到回执不覆盖更新的检查结果。
- 保存成功且原编辑意图未发生新变化时，结束对应未保存草稿；失败保留输入和原回执信息。修订号变化本身不构成编辑冲突，按实际修改字段与依赖判断；无冲突的更新自动接入，真实冲突才提供就地选择。

持久参数的控件、导入导出与执行共用共享解析，并明确默认继承与逐字段覆盖的来源；展示副本不能作为保存整段参数的来源。显式编辑只提交目标字段及必要联动字段，保留未编辑值与来源策略；`false`、`0`、显式 `null` 不得被界面兜底替换。保存成功提示和默认缓存只采用 Backend 确认值，读取失败不等于空配置；默认配置事件与重连刷新必须更新已打开控件，并拒绝迟到读取覆盖新确认值。验证控件编辑 → 细粒度 diff → Backend 事务 → 回执/delta → 刷新回读的完整链路，以及保存拒绝、失联、默认变化和相邻对象不受影响。

## 本地命令、并发与恢复

1. 在编辑动作入口捕获本次 before/after 的细粒度 ops，作为不可变命令独立落盘；网络发送时不能对整图快照重新求差分来猜意图。
2. 远端到达时，对队列逐条检测冲突并重放到新基线，不能覆盖未确认编辑。
3. 已发送但未确认时，先用原 operationId、原基线、原 ops 取回执；不能换 ID 重提来赌成功。
4. 确定性拒绝保留草稿并停止自动重试。同一不可变快照的确定性 400 只提交一次，记录脱敏的操作类型、目标 ID、拒绝原因，SSE/store 更新不得复活重试。
   明确未保存的内容校验拒绝只结束本次命令，不作为后续人工提交的全局锁；用户修正后可直接新提交。400 失败记录与编辑草稿保留，但不要求先核对服务器版本。409 版本冲突、超时或结果未知分别沿冲突处理和原回执恢复流程，不能与内容错误合并。
5. 冲突记录包含 conflictTargets 和 remoteProject。只有用户明确选择后，才在远端新基线上以新 ID 重提或丢弃意图；先持久化替代/丢弃标记，再清理旧记录，刷新不能复活旧命令。
   更新与本地编辑涉及独立字段或不同台账条目时，不判为冲突；自动保留本地改动并接入未编辑的远端内容。仅同一字段出现不同修改或编辑与删除相交时要求选择。读取最新版本并保留编辑只需一次明确操作，不叠加确认弹窗。
6. `delete_node`、`delete_connections`、`delete_h3_segment` 的目标已不存在时返回 skipped；正常竞态 no-op 不报 400。

生成前文本同步与重连只恢复当前画布中仍存在的节点、Clip 和文本项会话。已删除目标的 outbox 草稿保留供恢复，不因刷新重新发起读取或阻断其他目标；画布尚未加载不视为目标删除，当前目标的真实保存失败仍须上报。

复制标签页会继承 sessionStorage。不能将其中的 owner 直接视为独占身份；应用及测试入口须先完成草稿会话认领，再导入读取 outbox 的 Store/编辑器。恢复其他会话前再次检查排他权限；未取得权限时保留记录、禁止自动重放，不靠经过多久推断旧窗口关闭。

## 生成任务

- Motion Context 与尾帧参考是相邻 Clip 的互斥边界决定，只允许都关闭、仅尾帧或仅 Motion Context；两项同时开启须明确报错，不能静默选一种。从保存的全局默认参数、新节点或复制 Clip 不自动开启。A 段开关登记 A→B 的出边，实际由 B 段消费 A 的 AV latent 或末帧；不影响 A 自身输入。Motion Context 的导演选择按 Acheng shots 中的不可切镜规则执行，已有显式设置和历史媒体不自动改写。

- 所有画布生成经 Backend 统一任务服务，来源可以是网页、MCP、Agent 或浏览器模型；调用方提交源节点和输入，Backend 在任务绑定事务中创建结果占位、槽位与连线。
- 已有结果槽重试或明确 writeBackToTarget 可以原位回写；调用方不得为了看见产物另造结果 ID、位置或状态。
- 自定义模型脚本、Backend 尚不能无头执行的浏览器渠道，先创建 `canvas-browser-script` 权威任务并绑定节点，再由窗口唯一 workerId 原子认领。
- 浏览器只返回已归档媒体 key 或文本，由 Backend 校验归属并写终态。用户脚本不得转移到 Node new Function/vm；Backend 重启后不自动重跑已认领任务，避免重复请求和扣费。
- 面板连接状态不是业务能力可用性的门槛；使用当前 Backend/Comfy 端点解析器。相似路径可能属于不同实现，先确认前缀和处理进程。
- 提交、等待和恢复以精确 taskId 为准；生成输入改变后，旧结果仍对应旧输入。请求成功、文件存在或页面显示 success 均不能代替本轮结果证据。

## 剧目资产库与共享节点

- 剧目资产的内容权威为其专属共享资产画布中的唯一节点；共享画布中的每个角色、场景、道具节点自动进入共享素材库，资产库记录稳定来源与目录信息，正文、媒体、角色形象和声音、场景信息从源节点派生。入库不要求审核批准；无剧目归属的普通资产保持原有契约。普通分集画布引用可跨剧目；Backend 仍按稳定来源身份、节点类型和媒体身份校验。正式制作采用引用仍须符合其制作来源校验；批准证据只作可选历史信息。
- 图片实体只维护一个当前选择：角色以 `characterImages[characterPrimaryIndex]` 为权威图，场景以 `sceneImage`、道具以 `propImage` 为权威图。节点顶层 `content/storageKey/naturalWidth/naturalHeight/bytes/mimeType` 只是旧读路径与列表封面投影，必须从权威图派生；前端对顶层媒体字段的旧式更新由 Backend 在同一画布事务写回权威图，不能让 H3、节点卡片和共享素材分别选中不同图片。
- 普通素材加入剧目资产库时，共享源、目录绑定与原节点原位转引用在同一 Backend 事务中完成；智能生成只加入当前选定产物，保留原生成节点与任务历史。引用持久数据只保存身份、本地字段修改及编辑基线、布局与消费者上下文，源内容只作读取投影。
- 通用引用未编辑时跟随源；局部修改及本地生成结果保留在当前引用，明确更新资产库才提交共享源。由本集使用资产面板纳入制作的 `writeThrough` 引用是明确例外：可编辑内容直接写入共享源，精确成功且未过期的生成结果也写入共享源；传播到引用及登记过该稳定来源的分集。独立字段自动合并，同字段冲突保留输入并就地决定；响应未知先恢复原 operationId 的回执，不另造资产。源传播沿 ops 事务更新实际消费者和角色选图，历史及在途输入不改写。
- 删除引用只移除当前引用；资产库和共享画布删除源时统一检查所有引用，有引用则返回使用画布。迁移先备份，按稳定资产 ID 或唯一明确来源接入，保留旧节点差异与未确认草稿，不按名称合并，不移动既有共享节点。

## 制作画布与共享素材版本

- 制作编译沿正式源稿预检；生成默认只读校验当前画布的有效输入，显式 published 模式才校验发布稿。预检返回逐目标就绪、阻塞与非阻塞提示，不创建编译包或媒体任务。预检通过不能替代提交时的 revision、归属和幂等核验；原幂等请求允许恢复回执，不能被新状态误拦后诱导换 ID 重提。新发起的编译和校验使用本机当前激活引擎，源稿原文与历史实际版本保留，合法缺图草案不冒充生成就绪。
- 制作台角色、场景、道具以稳定实体 ID 和正式 owner 绑定对应类型的画布节点；风格不随此接入。名称与描述通过制作事务／画布 ops 双向编辑当前源稿，不按名称匹配；图片绑定引用真实画布来源，生成器与历史结果保留。实体名称以 `${kind}Name`／节点 `characterName`、`sceneName`、`propName` 为权威，节点标题只是卡片展示名（如「角色名 · 动画身份图」）；资产库投影、共享同步和编译 Subject 身份名都取名称字段，同名时以名称字段为准，标题仅作兜底。缺失节点沿准备命令补齐，读取不写入；普通 metadata 操作不得伪造实体绑定。本集使用共享节点时，分集源稿登记、主体、共享引用身份及本集节点在同一 Backend 事务中创建或移除；共享节点编辑传播至所有相关分集，移除本集引用不删除共享源。
- 主体绑定切换只允许本集已登记的同类型实体节点，包括已纳入共享画布的本集引用；Backend 按稳定实体 ID 校验，主体登记 ID 保持不变，关联图片引用、Shot 图片绑定及连续性实体引用随同一事务切换。不可按节点名称匹配，也不允许切到未登记或类型不一致的节点。
- 剧本文本节点投影正式 `script_scenes`，保留场次、正文分块与节拍身份。节点正文编辑与制作源稿 revision/hash 更新在同一画布 ops 事务内完成，沿原回执幂等重放并广播；源稿编辑在制作事务内更新对应节点和协作文档。只读入口不建节点，存量补齐沿准备命令执行，保留布局、未确认草稿与已发布历史，不提交媒体生成。
- 制作按分集固定绑定画布；场次只组织目录和节点分组。剧目共享资产使用专属画布及其独立制作记录，不给同一对象另建制作真值。已有非空绑定不改绑或清空，普通画布删除入口拒绝删除绑定画布；解除整个对象沿既有明确删除流程。
- 正式制作节点的位置由 Backend 按 canonical canvas 持久化的完整布局计划编译；布局计划、准备回执与节点创建沿准备事务提交。网页、Agent、MCP 和执行器消费同一计划，调用方不自行估算坐标、不在创建后批量补排。既有节点的几何为固定锚点，新增目标增量避让；文案、审核、依赖就绪和生成进度不能重分配坐标。布局标记由 Backend 生成并受普通用户 ops 保护；正式图片在预留显示框内 contain，加载结果不能回写位置。布局身份不替代正式 owner/目标绑定核验。
- 准备画布、资产节点和 Clip 是幂等编辑，不授权生成。正式 Clip 在准备与应用编译的事务内投影完整引用；缺少有效编译、批准参考、存在编辑冲突或运行占用时返回逐目标 referenceSync 阻塞回执，不能将草案节点当作生成就绪。正式展示目标使用 Backend 的 owner/workId、节点/Clip 及精确任务映射；缺少节点时展示对象编辑器，不按名称猜节点。
- 正式图片参考由导演源稿的编号参考卡、依赖和镜头资产表编译，绑定解析为有顺序、用途、资产版本和 SHA256 的清单。准备与编译应用经同一 ops 事务投影参考卡及连线；画布与自动/手动生成消费这份清单，不展开资产节点的其他图片或混入旧结果。人工参考连线与绑定在画布事务内保存，不改写导演参考卡或使原编译回执失真；有效归档媒体不因未审核而拒绝使用。正式编译清单保留为基线，提交核验本轮有序参考与实际字节并保存不可变快照。共享角色、场景、道具的唯一当前内容源是剧目共享画布节点；分集 `asset_plan[].sharedSource` 只保存来源身份，前端选中本集实体图片即完成引用，Backend 即时按该节点解析。不得另存采用状态或在 `director.assets` 再写共享来源；该映射只保存编译所需的节点和媒体清单。旧采用状态只作迁移归档，不参与校验、同步或就绪判断。
- 共享实体投影及引用只按稳定 sourceProjectId/sourceNodeId 对齐，不按名称猜测。共享节点更新在 Backend 传播事务中刷新分集实体、Subject 图片解析与未发布 H3 Clip 的共享派生引用；不自动编译或发布。Prompt、分镜、时长与历史/已发布快照保持原状；已有输出保留并标记 inputOutdated，在途任务的冻结输入不改写。普通节点写入不能伪造共享身份；分集的 writeThrough 编辑沿 Backend 事务写回共享源。
- 跨版本恢复保留原 runId 和已提交 taskId，跳过已完成目标；旧任务结果只绑定原发布版本，不能回写新的制作输入。自动范围沿既有授权扩展，逐项范围不扩张。
  显式启用场次并行的制作，可在 Backend 核验当前草稿和发布目标的输入作用域均与原任务版本一致、实际活动结果仍属于本轮任务后，将结果投影到当前等价目标；保留原 taskId、源版本及历史快照，不将它宣称为新输入生成的媒体。目标输入变化或用户已选择其他结果时，只保存原版本历史。

## H3 字段与引用

- H3 Clip `taskMode` 是制作模式唯一权威值；Acheng Segment `mode`/`mode_lock` 是同一值的源稿投影。编辑 H3 模式时，Backend 在同一 Canvas ops 事务同步 Segment 并使旧编译产物失效；编译与制作台读取按已绑定 H3 Clip 的 `taskMode` 投影模式，不得再按关键帧/参考数量覆盖为 I2VA/FL2VA/Ref2VA。没有绑定 H3 Clip 的新目标才可使用源稿模式推断；正式制作投影更新 H3 节点时必须保留该节点当前 `taskMode`。

- 自选视频模型关闭时，原生 H3 固定走本地 ComfyUI，保存稿、请求或默认参数残留的 RH／自动分流选择不参与原生路由，也不读取 RH 配置。自选模型开启后才使用其模型渠道、工作流及本地／RH／混合选择；界面、参数预检和后台执行共享这一语义。

- 互斥开关在显式编辑事务中同时保存本项与另一项的关闭值，回执和广播包含完整字段变化；刷新后的显示与 Backend 保存值及执行参数一致。不得仅在前端或参数解析中把保存的开启值伪装为关闭，也不得因正式 Clip 带有 productionClipProjection 而从 diff 中过滤允许人工编辑的续接开关。旧冲突配置经显式编辑修正，打开面板不自动改写；验证必须覆盖普通与正式 Clip 的当前／全局编辑、双向切换、保存回读、刷新、跨窗口回放及幂等回执。

- Clip 的 `start` 由 Backend 按段数组顺序和时长派生，不作为可编辑配置提交；浏览器预览和 delta 回放使用同一计算规则。调整顺序提交 `move_h3_segment`，不能只写起点。旧起点草稿仅在明确拒绝且用户选择恢复后转换；完整基线与连续起点无法还原顺序时保留原草稿，已发送未确认请求仍先取原回执。

- 普通生成节点引用角色时，主图引用随角色主图或图片变更自动更新；失效选图恢复当前主图，仍有效的独立服装选择和显式关闭图片保持原意。更新与角色编辑在同一 ops 事务中持久化和广播，参考卡、计数及实际输入使用共享解析；历史生成快照不改写、不自动重跑。验证换主图、等数量替换、删除、跨窗口回放及重复提交。

- H3 runtimeTaskId、status、进度、结果、结果历史由 Backend 独占。当前 Clip 在路由和输入准备、创建子任务之前绑定本轮父任务；此阶段失败也必须写回该 Clip 的明确错误，保留旧输出和后续未执行 Clip，不能继续显示旧成功状态。`diffCanvasProject` 只提交提示词、参考、布局等允许的用户编辑字段；旧页面快照不能覆盖 Backend 运行数据。
- 普通 Clip 编辑真值为 referenceBindings；正式制作 Clip 由 Backend 从正式源稿投影，允许人工修改正文、非共享参考、分镜和续接配置。共享来源的 referenceBindings 与角色组由稳定 pictureBindingId/sourceNodeId 回链，源更新时覆盖这些 H3 派生媒体字段，即使用户改过本地媒体选择也跟随 Subject 当前绑定；保留 Prompt、分镜、时长和非共享字段。其他编译字段继续按旧基线、当前内容与新导演稿三方合并。打开面板、刷新和远端事件不得擅自重写 Prompt。Backend 在 ops 中通过 canonicalizeH3References/registerH3ReferenceAssets 规范化并登记目录，前端不另启 reference-sync/write-coordinator。
- 画布图片与 Clip 的人工输入不要求最新编译或发布，生成中可保存下一版；任务状态、媒体与编译身份仍由 Backend 保护。同一物理目标的活动任务拒绝重复提交，图片槽位按实际重叠核验。人工参数通过 h3ParameterOverrides 保持逐字段优先级；明确切回默认策略清除覆盖，显式 null 风格保留。人工 H3 Clip 使用当前现场正文、参考与参数直接生成，不要求当前编译产物或先应用/翻译；artifactId/promptHash 仅作来源诊断与历史追溯。
- 新批次冻结当前画布的提示词、参数、参考与目标映射；待生成参考只能绑定本批次精确前置任务的归档结果一次。恢复沿原快照、scope 和任务 ID，不读取新画布替换未提交输入；无快照的旧批次保留发布稿语义。媒体完成后核对当前有效输入，旧输入结果保留历史并标记变化，不覆盖新输入已选结果；绑定任务不自动批准素材。
- 正式 Segment 的视觉风格保存为 `styleTemplateId`，显式模板或 null 在默认参数策略下保留原意；未声明的旧稿沿原默认解析。人工风格与源稿冲突时，经目标归属与画布版本核验后明确采用，再编译同步；不得将模板正文搬进源稿或自动覆盖其他人工字段。局部编译保留来源覆盖与状态重放的真实依赖，校验上下文不扩大发布或生成目标。
- 绑定使用 nodeId + segmentId + bindingId 定位；label、role、tags、subjectId 属于绑定上下文。同 assetId 可被不同 Clip 赋予不同语义，复制 Clip 后相同 bindingId 也须区分。
- Clip 重分组仅比较实际执行配置；模式选择理由等说明文字不同不构成配置冲突。相同配置的可执行分组直接保存，真实模式或风格选择不同才要求决定来源。不得把显式无风格与未声明默认风格合并为同一选择。
- 旧 refs/refItems 只在受保护迁移边界处理；先备份，无法完整迁移或冲突时拒绝丢弃。媒体源与 assetId 冲突不能静默覆盖。
- 参考连线与标签不证明实际生效；生成验收核对编译顺序、输入快照/日志与真实 provider/workflow 输入。
- 恢复历史输出须核对项目、节点、片段、日志和媒体，再经 Backend 支持的恢复操作。删除活动 Clip 不等于删除历史任务或归档媒体。
- 正式制作的历史选用通过 `select_director_result` 同时提交制作与画布 revision；核对原成功任务、正式绑定和媒体后，画布 ops 与活动制作映射在同一事务中更新，提交后才广播。原生节点任务绑定与正式批次提交回执都是正式归属证据；批次须按 owner、精确 taskId、目标、节点及 Clip 核验，不因缺少原生绑定拒绝合法批次历史，也不补造绑定记录。显式手动选用统一按当前草稿目标核验，不以是否发布或历史任务快照格式为前提，也不改写旧发布稿。图片选回后重新审核；旧输入标记、原任务输入和历史保留，不能恢复参数时改写 Segment 或连续性边界。
- SQLite created_at 的时间查询使用同格式 ISO 参数；无效时间表达式导致的空结果不能作为“没有写入”证据。

## 媒体与执行结果

- Subject 图片及 Shot 关键帧的 `node_selection` 绑定消费智能节点独立的 `smartImageReferenceSelection`：缺省跟随最新成功归档结果，显式历史选择只改变引用。绑定声明的 `latest_success` 或 `selected_result` 保持自身覆盖。浏览历史不恢复生成输入；恢复生成设置必须显式执行，且不改引用策略。选择、归档及实际消费者刷新沿现有 ops／事件与持久刷新链处理；不改在途快照或旧 Clip 的兼容引用语义。
- 普通画布生成与预览对智能图片节点的引用必须与正式绑定同类语义：前端 `canvasNodeImage` 与 Backend `addSmartImageReferences` 都经 `selectSmartImageResult(...,{mode:"node_selection"})` 解析，禁止直接按 `primaryImageId` 取快照——批量结果归档保持 `primaryImageId` 折叠时，引用方仍须自动跟随最新成功归档结果。钉选结果失效或策略非法时回落到最新成功归档结果，不得静默引用运行中／失败／占位图片，双方回落规则必须一致。引用输入 ID 保持 `${nodeId}:image:${imageId}` 稳定格式，供 `referenceNodeIds` 显式调用方定位。
- Subject 绑定去重必须连同 Shot 的字符串绑定 ID 在同一编辑事务内处理。只有除稳定 ID 外语义完全相同的绑定可合并；用途、保留／排除、状态或结果选择不同必须保留。未知引用在提交前定位拒绝，不按唯一剩余绑定猜选图；读取不得归一化源内容或改变其哈希身份。一个 Clip 多镜复用绑定只登记一个消费者索引条目。

- MEDIA_DIR 独立于 ComfyUI 安装目录；ComfyUI 只用执行缓存，输出归档回 Backend。迁出旧耦合目录先备份、复制并校验，再切换索引，保留原文件。
- WebP 缩略图仅为浏览器本地可丢弃渲染缓存，不进入节点、媒体记录、导出或模型参考；下载、编辑、生成、导出始终解析原 storageKey。
- ComfyUI 结果必须对应本轮精确 promptId，且最终媒体非空。禁止扫描 history 取最近成功记录补结果，时间接近不是任务身份证据。
- 取消、重启恢复与失败归档都保留父子任务关联。history/WS 无法确认输出时保留证据，不由前端猜测回填。
- 大段 prompt、参考和工作流快照放已有日志/任务数据中按需读取，不在每个节点和结果里反复复制。

## 受影响契约的验收

按改动选择重复提交、重复删除、并发窗口、远端重放、拒绝熔断、刷新恢复、任务取消/重启等场景；验证原用户意图与原数据仍可恢复。业务成功要有任务、日志、归档媒体和活动结果绑定的完整对应，不能只看单层状态。
